## Five steps

Your people already use AI tools. Gantry sits between those tools and the model providers, and takes you from seeing what is in use to governing it, one change at a time. Step 1 blocks nothing.

| Step | What you do | What you get |
|---|---|---|
| [1. See](/start/step-1-see/) | Run Gantry and point your tools at it | Which tools and models are in use and what they cost |
| [2. Know](/start/step-2-know/) | Give each person their own key | A name and a team on every request |
| [3. Limit](/start/step-3-limit/) | Set a budget per team | A cap on spend, and a stop button |
| [4. Protect](/start/step-4-protect/) | Add a check for secrets, on trial first | Keys and passwords stay out of prompts |
| [5. Prove](/start/step-5-prove/) | Keep and verify the audit log | Evidence of every request |

## How it works

Claude Code, Codex, Cursor and any OpenAI or Anthropic SDK point at Gantry instead of the provider. Gantry identifies the caller, decides by policy, writes a hash-chained audit record, and only then forwards the request with the provider key in place of the caller's.

It ships as one static binary with no database. Policy, keys and the audit log are plain files you can review, version and verify.

## Governance

<CardGrid>
	<Card title="Identity on every request" icon="seti:lock">
		Each person and workload gets a Gantry key tied to a name and a team. Only its SHA-256 is stored. Developers can issue their own expiring key through SSO with `gantry login`.
	</Card>
	<Card title="Policy as code" icon="document">
		First-match rules by team, person or anyone decide which models a caller may use. `gantry check` rejects unknown fields and names the file, line and fix.
	</Card>
	<Card title="Tamper-evident audit log" icon="list-format">
		One hash-chained record per request, written before forwarding. Refusals are recorded too. `gantry audit verify` proves nothing was changed or reordered.
	</Card>
	<Card title="Budgets and rate limits" icon="seti:pipeline">
		Dollar budgets per team, person or key, reserved at admission so they cannot be overrun. Requests and tokens per minute, with `Retry-After`.
	</Card>
	<Card title="Guardrails" icon="warning">
		Built-in secret and personal data detectors, seven guardrail vendors, and your own services by webhook. Block, mask or record, on requests and answers.
	</Card>
	<Card title="Kill switches" icon="error">
		Stop a person, a team, a key or a model at once with `gantry kill`. The person stopped sees who set it and why.
	</Card>
</CardGrid>

## Routing

<CardGrid>
	<Card title="Every major provider" icon="puzzle">
		OpenAI, Anthropic, Azure OpenAI, Claude on Amazon Bedrock and Vertex AI, Gemini, and any OpenAI-compatible server: Groq, Mistral, Together, Fireworks, DeepSeek, OpenRouter, Ollama, vLLM, LM Studio.
	</Card>

		Retries and a fallback per provider. Model aliases spread one name over several deployments with weights, cooldown and named fallbacks.
	</Card>
	<Card title="Cross-API translation" icon="translate">
		Opt in to send chat completions to Claude, or Claude Code's messages requests to GPT, Gemini or a local model.
	</Card>
	<Card title="Cost on every answer" icon="seti:db">
		Tokens and cost recorded for each answer, with prices built in for most models. `gantry prices <model>` shows the price and its source.
	</Card>
</CardGrid>
