A provider in the policy file may say `preset: <id>` instead of writing its `url` and `kind`. Enterplace takes both from this table; a `url` or `kind` written next to the preset wins. The provider still needs `key_env` (or `key_file`) and `models`.

```yaml
providers:
- name: groq
preset: groq
key_env: GROQ_API_KEY
models: [llama-3.3-70b-versatile]
```

The key goes in the header the kind sends: `Authorization: Bearer` for openai, `x-api-key` for anthropic, `x-goog-api-key` for gemini. A chat request goes to the URL followed by `/chat/completions` (anthropic: `/messages`; gemini: `/models/<model>:generateContent`).

Local entries are model servers you run yourself. Their URL is the server's default on this machine, so the provider also needs `allow_private: true`, and `key_env` only if the server was started with a key. Run `enterplace providers` to print this table.
