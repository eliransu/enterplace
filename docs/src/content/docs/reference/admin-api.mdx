The admin API does over HTTP what the console does, with the same permissions and the same audit records: keys, kill switches, provider credentials, usage, the policy and its parts, and (Gantry Enterprise) alert rules. It is on the gateway's own address. The keys file stays the one source of truth for keys, and a change to the policy is a new [policy version](/governance/policy/), checked as `gantry check` checks a file.

## OpenAPI document

`GET /admin/openapi.json` answers an OpenAPI 3.1 document of every admin route this gateway serves, with the permission each needs (`x-gantry-permission`) and the `action` of its record (`operationId`). It needs no key and is not recorded. The document and the routes come from one table, so a route that is not in it is refused with `unknown_route`, and CI calls every route in it to check that it is served with that action, and fails when the router serves an `/admin` path of its own outside the table.

```bash
curl -s http://127.0.0.1:8080/admin/openapi.json | jq '.paths | keys'
```

## Authentication

Send an admin key, one whose entry in the keys file says `admin: true`, as `Authorization: Bearer gantry_...` or `x-api-key: gantry_...`. Make the first one on the command line:

```bash
gantry key new noa.bar --team platform --admin
```

| Caller | Result |
|---|---|
| No key | 401 `no_key` |
| Unknown key | 401 `unknown_key` |
| Valid key, neither an admin's nor given a role | 403 `not_admin` |
| Key whose [role](/governance/policy/#console-roles) lacks the route's permission | 403 `not_permitted` |
| Admin key, or a key whose role has the permission | Allowed |

Each route needs one permission, named in the table below and in the OpenAPI document: `see_keys` to list keys, `issue_keys`, `revoke_keys`, `kill` for kill switches, `credentials` for provider credentials, `edit_policy` to change the policy or back test a guardrail, `see_spend` for usage and the explanation, `see_records` to read alert rules. Routes that only read the policy (providers, models, rules, teams) need any role. A role kept to an organization lists, issues, revokes and explains only that organization's keys, sees only that organization's usage and teams, and has no kill switches, credentials or policy changes. A role kept to teams or end customers (its `teams:` and `customers:`) sees the usage and the people of those only, and changes no policy either.

`DELETE /admin/keys/self` is the one exception: any valid key may revoke itself.

Every call, allowed or refused, is an `admin` record in the audit log, written before anything is done. A call that cannot be recorded is refused with 503 `audit_unavailable`. Every response carries `X-Gantry-Decision`. Errors use the OpenAI shape in [Refusal codes](/reference/refusal-codes/#response-shape).

The admin API exists only when Gantry serves from a keys file. Under `gantry serve --unchecked` every `/admin` route is refused with `unknown_route`.

## GET /admin/keys

Lists the keys of the version in use, sorted by name. Never a key.

```bash
curl http://127.0.0.1:8080/admin/keys -H "Authorization: Bearer $GANTRY_ADMIN_KEY"
```

```json title="200"
{"keys":[{"name":"maya.cohen","team":"payments","sha256_prefix":"5d1e4a07","admin":false,"expires":"2026-12-31","budget":{"usd":20.0,"per":"month"},"models":null,"tpm":null}]}
```

| Field | Type | Description |
|---|---|---|
| `name`, `team` | string | As in the keys file |
| `sha256_prefix` | string | The first 8 hex characters of the key's SHA-256 |
| `admin` | boolean | Whether it is an admin key |
| `expires` | string or null | UTC date or time |
| `budget` | object or null | `{"usd": number, "per": "day", "month", "6h", "month@America/New_York", ...}` |
| `org`, `customer`, `role` | string or null | The key's organization, end customer and console role |
| `tags` | array | The key's tags |
| `parallel` | number or null | Requests in flight at once for the key |
| `models` | array or null | The key's own model list |
| `tpm` | integer or null | The key's own tokens-per-minute limit |

## POST /admin/keys

Issues a key and appends its hash to the end of the keys file, exactly as `gantry key new` does. The key works as soon as the answer arrives. The admin API issues non-admin keys only; make admin keys with `gantry key new --admin` or in the console.

```bash
curl -X POST http://127.0.0.1:8080/admin/keys \
  -H "Authorization: Bearer $GANTRY_ADMIN_KEY" -H "Content-Type: application/json" \
  -d '{"name":"maya.cohen","team":"payments","expires":"2026-12-31","budget":{"usd":20,"per":"month"}}'
```

| Field | Type | Required | Description |
|---|---|---|---|
| `name` | string | yes | Letters, digits, dots, dashes, underscores and `@`, at most 100 characters |
| `team` | string | yes | Same characters |
| `expires` | string | no | `2026-12-31` or `2026-12-31T18:00:00Z`, UTC |
| `budget` | object | no | `{"usd": 20, "per": "month"}`. `usd` above 0, `per` is `day` or `month` |
| `models` | array of strings | no | At least one. Each must be a model or alias the policy serves, or `"*"` |
| `tpm` | integer | no | 1 to 1000000000 |

Unknown fields are refused with `invalid_request`.

```json title="201"
{"key":"gantry_3f9a...","name":"maya.cohen","team":"payments","sha256_prefix":"5d1e4a07","rotated":false,"status":{"in_effect":true},"message":"This key is shown once and is not stored anywhere. Only its hash is in the keys file."}
```

| Field | Type | Description |
|---|---|---|
| `key` | string | The key. Shown once |
| `sha256_prefix` | string | The first 8 hex characters of its hash |
| `rotated` | boolean | `true` when the name already had a key. Both work until the old entry is removed |
| `status` | object | Whether the change is in effect (below) |

### status

| Field | Type | Description |
|---|---|---|
| `in_effect` | boolean | `true` when the new keys file is in use |
| `problems` | array of strings | Only when `false`: the files on disk fail the check for another reason, so Gantry keeps the version it has |
| `message` | string | Only when `false`: what to do. The change applies within 2 seconds of the files passing |

## GET /admin/keys/&lt;prefix&gt;

A key's settings and what it spent, never the key.

```json
{"key": {"name": "maya.cohen", "team": "payments", "sha256_prefix": "5d1e4a07", "admin": false, "expires": null,
  "budget": {"usd": 20.0, "per": "month"}, "models": null, "tpm": null, "rpm": 60, "parallel": null,
  "tags": ["eval"], "metadata": {"owner": "maya"}, "routes": [], "from": [], "replaced_by": null},
 "spend": [{"per": "day", "period": "2026-11-14", "spent_usd": 0.412, "reserved_usd": 0.03},
           {"per": "month", "period": "2026-11", "spent_usd": 7.905, "reserved_usd": 0.03}],
 "spend_counted_by": "store"}
```

`spend_counted_by` is `store` when the policy has `store:` (every gateway on it), else `this gateway`. `reserved_usd` is held by requests in flight.

## PATCH /admin/keys/&lt;prefix&gt;

Changes the fields sent and leaves the rest. `null` removes a field.

| Field | Value |
|---|---|
| `expires` | `"2026-12-31"` or `"2026-12-31T18:00:00Z"`, not in the past |
| `budget` | `{"usd": 20, "per": "month"}`, with `"tz"` for a period aligned to a time zone |
| `models` | Models or aliases the policy serves, at least one |
| `tpm` | 1 to 1000000000 |
| `rpm` | 1 to 1000000 |
| `parallel` | 1 to 100000, shared across gateways on a store |
| `customer` | The end customer every request with the key is for |
| `tags` | Names, at most 16 |
| `metadata` | Object of names to text, at most 32 entries, values at most 256 characters |
| `routes` | Path prefixes starting with `/`, at most 32 |
| `from` | Address ranges such as `"10.0.0.0/8"`, at most 32 |

Name, team, `org`, `role` and `admin` cannot be changed: a new name or organization is a new key, and rights are given only when a key is issued. A role kept to one organization sees and changes only that organization's keys, and a key whose role grants more than the caller's may not be rotated by them. Any other field, or a wrong value, is refused with 400 `invalid_request` and nothing is changed. The `admin` record's `target.changes` holds `{"<field>": {"from": ..., "to": ...}}` for each field sent. The answer is the key as changed, with [`status`](#status).

## POST /admin/keys/&lt;prefix&gt;/rotate

Body `{"grace": "48h"}` (optional, default `24h`; `90s`, `30m`, `48h`, `7d`, at most `90d`, or `0`).

```json
{"key": "gantry_8a41...", "name": "maya.cohen", "team": "payments", "sha256_prefix": "8a41c2d0",
 "replaces": "5d1e4a07", "old_key_until": "2026-11-16T09:14:02Z", "status": {"in_effect": true}, "message": "..."}
```

The new key has the old one's settings and is shown once. The old key gets `expires` at `old_key_until` (or keeps an earlier one) and `replaced_by`, and every request with it until then is recorded with `key_rotated`. A key already rotated: 409 `already_rotated`. If the old key cannot be changed, the new one is removed again and the call fails with nothing changed.

## DELETE /admin/keys/&lt;prefix&gt;

Removes the entry whose hash starts with `<prefix>` from the keys file, only if nobody changed the file meanwhile, and stops the key at once. The prefix is 8 to 64 hex characters, as `GET /admin/keys` lists it.

```bash
curl -X DELETE http://127.0.0.1:8080/admin/keys/5d1e4a07 -H "Authorization: Bearer $GANTRY_ADMIN_KEY"
```

```json title="200"
{"revoked":{"name":"maya.cohen","team":"payments","sha256_prefix":"5d1e4a07"},"status":{"in_effect":true}}
```

| Status | Code | When |
|---|---|---|
| 400 | `invalid_request` | The prefix is not 8 to 64 hex characters |
| 400 | `ambiguous_key` | More than one hash starts with the prefix |
| 404 | `no_such_key` | No hash starts with it, or someone else removed it meanwhile |
| 409 | `keys_file` | The keys file cannot be read or written |

## DELETE /admin/keys/self

Revokes the key the request is sent with. Any valid key may call it. `gantry logout` uses it.

```bash
curl -X DELETE http://127.0.0.1:8080/admin/keys/self -H "Authorization: Bearer $GANTRY_KEY"
```

The response is that of `DELETE /admin/keys/<prefix>`.

```bash
curl http://127.0.0.1:8080/admin/kills -H "Authorization: Bearer $GANTRY_ADMIN_KEY"
```

```json title="200"
{"kills":[{"scope":"team","value":"payments","reason":"runaway agent, investigating","by":"noa.bar","at":"2026-11-13T10:02:11.482Z"}]}
```

| Field | Type | Description |
|---|---|---|

| `value` | string | The name, team, hash prefix or model. Empty for `all` |
| `reason` | string | Shown to the people stopped |
| `by` | string | The admin who set it |
| `at` | string | When, UTC |

## POST /admin/kills

Turns a kill switch on. Gantry refuses matching requests with `killed` at once, and within 1 second on every node serving the same files. `gantry kill` calls this route.

```bash
curl -X POST http://127.0.0.1:8080/admin/kills \
  -H "Authorization: Bearer $GANTRY_ADMIN_KEY" -H "Content-Type: application/json" \
  -d '{"scope":"team","value":"payments","reason":"runaway agent, investigating"}'
```

| Field | Type | Required | Description |
|---|---|---|---|
| `scope` | string | yes | `person`, `team`, `key_prefix`, `model` or `all` |
| `value` | string | yes, except for `all` | A name or team as the keys file names it, at least the first 8 hex characters of a key hash, or a model as clients send it (at most 200 characters). `all` takes no value |
| `reason` | string | yes | 1 to 500 characters |
| `force` | boolean | no | Set the switch even when it matches no key, team or served model |

```json title="201"
{"kill":{"scope":"team","value":"payments","reason":"runaway agent, investigating","by":"noa.bar","at":"2026-11-13T10:02:11.482Z"},"replaced":null,"in_effect":true}
```

`replaced` is the switch this one replaced, when one on the same scope and value was already on, or `null`. A switch that would stop nothing is refused with 400 `kill_matches_nothing`, naming close matches.

## DELETE /admin/kills

Turns a kill switch off. `gantry unkill` calls this route.

```bash
curl -X DELETE http://127.0.0.1:8080/admin/kills \
  -H "Authorization: Bearer $GANTRY_ADMIN_KEY" -H "Content-Type: application/json" \
  -d '{"scope":"team","value":"payments"}'
```

| Field | Type | Required | Description |
|---|---|---|---|
| `scope` | string | yes | As for `POST` |
| `value` | string | yes, except for `all` | As for `POST` |

```json title="200"
{"cleared":{"scope":"team","value":"payments","reason":"runaway agent, investigating","by":"noa.bar","at":"2026-11-13T10:02:11.482Z"},"in_effect":true}
```

No switch on for that scope and value is 404 `no_such_switch`. A kill switch file that cannot be read or written is 409 `kills_file`.

## Provider credentials

Need `store:` in the policy and `GANTRY_MASTER_KEY` on the gateway: without the store each call is 404 `credentials_need_store`, without the master key 409 `no_master_key`. See [Provider credentials](/governance/provider-credentials/).

```bash
curl -X POST http://127.0.0.1:8080/admin/credentials \
  -H "Authorization: Bearer $GANTRY_ADMIN_KEY" -H "Content-Type: application/json" \
  -d '{"name":"openai-prod","provider":"openai","value":"sk-..."}'
```

| Field | Type | Required | Description |
|---|---|---|---|
| `name` | string | yes, for `POST` | Letters, digits, `.`, `-`, `_` and `@`. A provider names it with `credential:` |
| `provider` | string | yes, for `POST` | The vendor the key is for, such as `openai`. Shown in lists |
| `value` | string | yes | The provider key. 8 to 4096 bytes, no spaces or line breaks. Never shown again |

```json title="201"
{"credential":{"name":"openai-prod","provider":"openai","fingerprint":"...9f3b","created_by":"noa.bar","created_at":"2026-11-13T10:02:11.482Z","rotated_by":null,"rotated_at":null},"message":"The value is sealed in the store and never shown again. A provider names it with credential: in the policy."}
```

`PUT /admin/credentials/<name>` takes `{"value": "..."}` and answers 200 with the credential: every gateway on the store sends the new value within 2 seconds. `DELETE /admin/credentials/<name>` answers 200 with `removed`; a credential the policy in use names is 409 `credential_in_use`. `GET /admin/credentials` answers `{"credentials": [...]}`. The record of each call names the credential, its vendor and fingerprint, never the value.

## Teams

Reading needs `see_keys`; a role [kept to teams](/governance/teams/#roles-kept-to-teams) sees its teams. A change needs `edit_policy` in a role kept to no part of the install, and the policy kept in the store (`store.policy_from: store`); otherwise 409 `policy_in_file`. See [Teams](/governance/teams/#the-teams-api).

| Field | Type | Required | Description |
|---|---|---|---|
| `name` | string | yes, for `POST` | The team's name. A `PUT` body that names another team is 400 |
| `owner` | string | no | An email |
| `members` | list | no | Emails. A person in another team's members is 400 `invalid_policy` |
| `sso_values` | list | no | Group values that put a person in the team |
| `metadata` | map | no | Your own notes |

A change answers 201 (`POST`) or 200 with the policy version it saved, `in_effect` and a message, as a policy change does. A team already listed is 409 `team_exists`; a team the policy does not list is 404 `no_such_team`.

## GET /admin/usage

Spend, tokens and requests of the requests that match, summed by one dimension, by day or by hour. With a store the request index sums them in SQL across every gateway (`counted_by: store`); without one, this gateway folds its own audit log (`this gateway`, at most 200,000 requests).

| Parameter | Description |
|---|---|
| `group_by` | `day` (default), `hour`, or a dimension: `org`, `team`, `person`, `key`, `customer`, `tag`, `model`, `provider`, `agent`. A request with several tags counts under each |
| `from`, `to` | A date (`2026-11-01`, `to` takes the whole day) or a time (`2026-11-14T09:30:00Z`), UTC |
| `team`, `model`, ... | Any dimension as a filter, as the request log takes it, and `outcome`, `code`, `min_cost`, `max_cost`, `min_ms`, `max_ms` |
| `format` | `csv` for CSV; or send `Accept: text/csv`. JSON otherwise |

```bash
curl "http://127.0.0.1:8080/admin/usage?group_by=team&from=2026-11-01&to=2026-11-30" -H "Authorization: Bearer $GANTRY_ADMIN_KEY"
```

```json title="200"
{"group_by":"team","from":"2026-11-01","to":"2026-11-30","filters":{},"counted_by":"store",
 "totals":{"requests":1840,"refused":12,"errors":3,"input_tokens":5120400,"output_tokens":822100,"total_tokens":5942500,"spend_usd":41.27,"latency_p50_ms":820,"latency_p95_ms":4100},
 "groups":[{"team":"payments","requests":1203,"refused":4,"errors":1,"input_tokens":3900100,"output_tokens":610300,"total_tokens":4510400,"spend_usd":30.11,"latency_p50_ms":790,"latency_p95_ms":3900}]}
```

`spend_usd` is what the provider's answers cost at the policy's prices. Groups are ordered by spend, then requests; `day` and `hour` groups oldest first. The CSV has a header row, `<group>,requests,refused,errors,input_tokens,output_tokens,total_tokens,spend_usd,latency_p50_ms,latency_p95_ms`, and every group value quoted. A role kept to an organization, teams or customers sees usage within them only (within each, when it is kept to more than one kind): `org=`, `team=` or `customer=` outside them is 403 `not_permitted`, never an empty answer.

## The policy by part

Each part of the policy file has its routes: `providers`, `rules`, `guardrails`, `mcp` (MCP servers) and `aliases` are lists of entries named by `name`; `budgets` is the `limits:` list whole. An entry is the JSON of what the policy file holds for it, with the same fields.

```bash
curl -X PUT http://127.0.0.1:8080/admin/rules/payments -H "Authorization: Bearer $GANTRY_ADMIN_KEY" \
  -d '{"principals": {"team": "payments"}, "models": ["gpt-4o-mini"], "budget": {"usd": 200, "per": "month"}}'
curl -X PUT http://127.0.0.1:8080/admin/budgets -H "Authorization: Bearer $GANTRY_ADMIN_KEY" \
  -d '[{"team": "payments", "budget": {"usd": 500, "per": "month"}}]'
curl -X POST http://127.0.0.1:8080/admin/models -H "Authorization: Bearer $GANTRY_ADMIN_KEY" \
  -d '{"provider": "openai", "model": "gpt-4o-mini", "input": 0.15, "output": 0.60, "aliases": ["fast"]}'
curl -X PUT http://127.0.0.1:8080/admin/models/gpt-4o-mini/price -H "Authorization: Bearer $GANTRY_ADMIN_KEY" -d '{"input": 0.15, "output": 0.60}'
```

- A change is a new policy version on the live one, exactly as `PUT /admin/policy` saves it: 201 with the version, its state (`live`, or `pending` when the live version asks for approval) and `in_effect`. Every gateway on the store uses it within 2 seconds.
- `If-Match: "<version>"` is optional: send it to be refused with 409 `version_conflict` when someone saved meanwhile. Without it the change is made on the version live now.
- A version `gantry check` refuses is 400 `invalid_policy` with each problem; a missing entry is 404 `no_such_entry`.
- Changes need `edit_policy` in a role not kept to an organization, teams or customers, and the policy kept in the store (`store.policy_from: store`). A policy kept in its file is read through these routes, and a change is 409 `policy_in_file`.
- The record's `target` names the part, the entry and what was sent. The policy holds no secrets: provider keys are named by `key_env` or `credential:`, and credentials are added write-only with `POST /admin/credentials`.
- Comments of the policy file are not kept by a change through these routes, as in the console's forms; `PUT /admin/policy` keeps them.

`GET /admin/models` answers each model with its provider and price, and the aliases.

## Alert rules

Gantry Enterprise with the `alerts` feature adds these routes; without it each answers 403 `license_required`. Reading needs `see_records`; changing `edit_policy`. See [Alerting](/operations/alerting/) for the kinds and their parameters.

```bash
curl -X POST http://127.0.0.1:8080/admin/alerts/rules -H "Authorization: Bearer $GANTRY_ADMIN_KEY" \
  -d '{"name": "Payments spend", "kind": "budget", "params": {"scope": "team", "name": "payments", "period": "month", "usd": "500"}, "channels": [1], "cooldown_minutes": 60, "max_per_hour": 10, "enabled": true}'
```

| Field | Description |
|---|---|
| `name`, `kind` | Required. `kind` as the Alerting page lists it |
| `params` | The kind's parameters as text, as the page's form takes them |
| `channels` | Channel numbers, as `GET /admin/alerts/channels` lists them. Channels are added on the page, where a signing secret is shown once |
| `cooldown_minutes`, `max_per_hour`, `enabled` | 0 to 10080 (60), 1 to 1000 (10), `true` |

`PUT /admin/alerts/rules/<id>` takes the same body and replaces the rule; `DELETE` removes it (its past alerts stay). A wrong body is 400 `invalid_rule`, an unknown rule 404 `no_such_rule`.

<Aside type="caution">
An admin key can issue keys and stop all traffic. Keep admin keys in your secret manager, and revoke one the moment it may have leaked.
</Aside>
