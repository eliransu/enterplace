Every refusal has a stable code, an HTTP status, a message that names the cause and the fix, and the decision ID. It never contains an address, an internal error or another caller's data.

## Response shape

On `/v1/messages` and `/v1/messages/count_tokens` a refusal uses Anthropic's error shape, so Claude Code and Anthropic's SDKs show the message. On Google's Gemini API routes (`/v1beta/models...`) it uses Google's shape, so Gemini CLI shows it. Everywhere else, the admin API included, it uses OpenAI's shape.

```json title="Anthropic shape"
{"type":"error","error":{"type":"permission_error","message":"Refused (model_not_allowed): ... Decision 01M79..."},"enterplace_code":"model_not_allowed","decision":"01M79..."}
```

```json title="Google shape"
{"error":{"code":403,"message":"Refused (model_not_allowed): ... Decision 01M79...","status":"PERMISSION_DENIED","details":[{"@type":"type.googleapis.com/google.rpc.ErrorInfo","reason":"model_not_allowed","domain":"enterplace","metadata":{"decision":"01M79..."}}]}}
```

```json title="OpenAI shape"
{"error":{"message":"Refused (no_key): ... Decision 01M79...","type":"enterplace_error","code":"no_key","decision":"01M79..."}}
```

| Header | On | Value |
|---|---|---|
| `X-Enterplace-Decision` | Every response | The decision ID |
| `x-should-retry` | Every refusal | `true` for `busy`, `rate_limited` and `upstream_*`, `false` otherwise |
| `Retry-After` | `busy`, `rate_limited` | `1` for `busy`; the seconds to wait for `rate_limited` |

Every refusal except `audit_unavailable` is written to the audit log with its code. The `upstream_*` codes, `bad_path` and the 502 `untranslatable` come after the request was recorded as allowed, so its record says `allow`.

## Identity

### no_key

**401.** No credential, an empty one, an `Authorization` header that is not `Bearer`, or a header that is not text. The key is checked before the route, so an unknown route without a key gets `no_key`.

**Fix:** send the Enterplace key as `Authorization: Bearer enterplace_...` or `x-api-key: enterplace_...`. On Google's Gemini API routes, `x-goog-api-key: enterplace_...` or `?key=enterplace_...` (Gemini CLI: `GEMINI_API_KEY`) work too.

### ambiguous_key

**400.** `Authorization` and `x-api-key` hold different values, one of them is empty beside the other (the message names the empty one), or one of them appears twice. On the admin API, also a key prefix that more than one key hash starts with.

On Google's Gemini API routes, also a key in `x-goog-api-key` or `?key=` beside another one, there or in `Authorization` or `x-api-key`.

**Fix:** send exactly one credential, the Enterplace key. On the admin API, send more of the hash.

### ambiguous_model

**400.** On Google's Gemini API routes, the body names a model (`model`, or `generateContentRequest.model` for `countTokens`) other than the one in the path. The policy decides on the path's model, so the provider must not be told another.

**Fix:** remove the model from the body, or make it the same as the path's (`models/<model>` or `<model>`).

### unknown_key

**401.** The key's hash is not in the keys file: never issued, or removed. A key starting with `sk-` gets the hint that it looks like a provider key.

**Fix:** ask an admin for a key. A key just issued works within 2 seconds. Never send a provider key.

### key_expired

**401.** The key's entry has `expires:` and that UTC date or time has come. The record names whose key it was.

**Fix:** ask an admin for a new key, or run `enterplace login` again.

A subscription request is never answered 401: Claude Code reads a 401 as its own login having expired.

### person_needed

**403.** A request carries a login that is not an Enterplace key (a Claude subscription's), names no person in `x-enterplace-user`, and the [passthrough provider](/governance/subscriptions/) has `identity: required`.

**Fix:** set `ANTHROPIC_CUSTOM_HEADERS="x-enterplace-user: <person token>"` in Claude Code. Get a token from the console, `enterplace login` or `enterplace key new --identity-only`.

### person_token_only

**403.** A person token (`enterplace_u_...`) was sent as the request's only credential. It names a person and reaches no model on its own.

**Fix:** send it in `x-enterplace-user` beside your own Claude login, or use an Enterplace key.

### login_needed

**403.** The model is served only by a provider with `auth: passthrough`, which holds no key, and the request carries an Enterplace key in place of a login.

**Fix:** in Claude Code, unset `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN`, keep your Claude login and send your person token in `x-enterplace-user`. An app with a service key has no login to send: an admin serves the model from a provider with its own key, with **Add a provider** on the console's **New and pending** page.

### login_not_accepted

**403.** The request carries your own Claude login, and the model is served by a provider that uses Enterplace's key, or the route is `/passthrough`. A login is never swapped for Enterplace's key.

**Fix:** ask an admin to serve the model from a provider with `auth: passthrough`, or send an Enterplace key instead.

### no_login

**403.** `x-enterplace-user` names a person and the request carries no login to send on, or an empty one.

**Fix:** sign in to Claude Code with your Claude subscription (`/login`).

### passthrough_off

**400.** `x-enterplace-user` arrived with a login, and no provider of this gateway has `auth: passthrough`.

**Fix:** ask an admin to turn on Claude subscriptions (console, **Coding agents**, **Getting started**), or send your Enterplace key as your only credential.

### killed

**403.** A kill switch stops this person, team, key, model or everyone. The message names the switch, the reason, the admin who set it and when.

**Fix:** ask that admin. The switch stays until `enterplace unkill`. See [Kill switches](/governance/kill-switches/).

### awaiting_approval

**403.** The caller (a key, a person token or a single sign-on name) is new: no admin has reviewed it, and the policy's `new_callers: { mode: hold }` holds new callers until an admin allows them. The message names the caller and the console page. Nothing was sent to a provider.

**Fix:** an admin presses **Allow** on the console's **New and pending** page (`/console/app/#/apps/new`), or adds the name under `new_callers.allowed` in the policy. It works within 2 seconds. See [New callers](/governance/new-callers/).

### caller_blocked

**403.** The caller is on the policy's `new_callers.blocked` list, or it is new and `new_callers: { mode: block }` refuses new callers. Refused in every mode, observe included. Nothing was sent to a provider.

**Fix:** if it should get through, an admin presses **Allow** on the console's **New and pending** page, and it works within 2 seconds. See [New callers](/governance/new-callers/).

### kills_unreadable

**503.** `enterplace.kills.json` beside the keys file cannot be read, so Enterplace cannot tell whether a switch stops the request. Every request is refused.

**Fix:** the admin fixes the file, or deletes it, which turns every switch off.

### ip_not_allowed

The request came from an address outside the key's or the rule's `from` list; the record's `ip_not_allowed` says which. Send it from an allowed network, or ask an admin to change the list. See [Source address ranges](/governance/access-control/#source-address-ranges).

### route_not_allowed

The key's `routes` do not include this path. Ask an admin to change the key's routes.

### cert_required

The key is bound to a client certificate (`cert:` on the key), and this connection did not present a certificate with that name that Enterplace verified. Connect with the certificate, or ask an admin to change the key's `cert`. See [Mutual TLS](/governance/mutual-tls/).

### identity_invalid

Enterplace Enterprise: the request came through a trusted proxy with `identity_headers` set, and what the headers say cannot be taken: a header arrived twice, the user header holds no valid name, or the person is in no team. The message says which. Fix the proxy's header settings, or ask an admin to add the person's group to a team. See [Identity from an authenticating proxy](/governance/auth-proxy/).

### jwt_untrusted

The bearer token is a JWT from an issuer the policy's `jwt:` does not list. Use a token from a trusted issuer, or an Enterplace key.

### jwt_invalid

The JWT is malformed, signed with an algorithm other than RS256 or ES256, signed with a key not in its issuer's key set, has a wrong signature or audience, or is not valid yet. The message names which.

### jwt_expired

The JWT's `exp` has passed. Get a new token from the identity provider.

### jwt_claims

The JWT's person or team claim is missing, holds more than one value, or is not a name. Check `person_claim` and `team_claim` under `jwt:` against the tokens.

### jwt_keys_unavailable

The issuer's key set could not be read and no copy was cached. Retry; check `jwks_url` if it repeats.

## Route and body

### unknown_route

**404.** The method and path are not one Enterplace serves. See [HTTP routes](/reference/http-routes/). On the admin API, also a method and path it does not serve, or an Enterplace that serves no keys file.

**Fix:** check the method and the path.

### body_too_large

**413.** The body is over 32 MiB, or over the memory one caller may hold at once (64 MiB).

**Fix:** send a smaller request.

### body_timeout

**408.** The body did not arrive within 30 seconds.

**Fix:** send it again, from a faster link.

### busy

**429** when this caller's requests in flight already hold 64 MiB of request bodies. **503** when Enterplace holds as many request bodies as its 256 MiB budget allows, across all callers. Both send `Retry-After: 1`.

**Fix:** wait a moment and send again.

### unreadable_request

**400.** One of:

- The body is not a JSON object with exactly one `model` string. A second spelling such as `Model` counts as a second one. Or it stopped before it was complete.
- On `/v1/audio/transcriptions`: the body is not `multipart/form-data` with one boundary and exactly one `model` field, or a part is not plain (an extended `name*=`, spaces around `=`, an escape, a folded header).
- The body is sent with a `Content-Encoding` other than `identity`.
- On a rule with guardrails: an object in the body names the same key twice, or a text field has a shape the guardrails do not read (a moderation input item other than a string or `text` item, a non-string image prompt or speech input).

**Fix:** send an uncompressed JSON object, or form, with one `model` field and each key once.

### bad_limits

**400.** A budget or a cache applies, and the body names `model`, `messages`, `system`, `input`, `stream`, `max_tokens`, `max_completion_tokens`, `max_output_tokens` or `n` twice, gives a token limit that is not a whole number, `n` that is not a whole number from 1 to 16, or `stream` that is not `true`, `false` or `null`. On a rule that also has guardrails, a key named twice is caught first as `unreadable_request`.

**Fix:** send each field once, token limits as whole numbers.

### stored_context

**400.** A budget applies to a `/v1/responses` request that names `previous_response_id`, `conversation` or `prompt`. The provider adds stored context Enterplace cannot see, so the most the request could cost is unknown. The message names the fields.

**Fix:** send the whole conversation in `input` with `store: false`, as Codex does, or ask an admin to set `max_context` for the model under `prices:`.

### max_tokens_needed

**400.** A budget or a tokens-per-minute limit applies, the request states no `max_tokens` (or `max_completion_tokens`, `max_output_tokens`), and the model's price has no `max_output`, so the most it could cost or use is unknown. The message names the budget that applies and the field of the route. An image or speech request to a token-priced model has no such field: its model needs `max_output`, or `per_image` for images.

**Fix:** send `max_tokens` (`max_output_tokens` on `/v1/responses`), or ask an admin to set `max_output` for the model under `prices:`.

## Policy

### no_rule

**403.** No rule names the caller's name or team.

**Fix:** an admin adds a rule. See [Policy file](/governance/policy/).

### tool_not_allowed

**JSON-RPC error on `/mcp`.** The first rule that names the caller does not list the MCP tool. The message names the rule and the tools it allows.

**Fix:** call an allowed tool, or ask an admin to add it to the rule's `tools:`. See [MCP gateway](/governance/mcp-gateway/).

### browser_not_allowed

**403.** The caller's rule (or the policy) sets `coding_agents: { browser: block }` and the request offers the model a browser tool, such as Claude in Chrome's `mcp__claude-in-chrome__navigate`. The message names the tools and the rule. With the rule's `tool_action: strip` the tools are taken out instead.

**Fix:** in Claude Code turn Chrome off (`/chrome`, or start without `--chrome`) or remove the browser MCP server, or ask an admin to allow the browser. See [Coding agent controls](/governance/coding-agent-controls/).

### unknown_tool

**JSON-RPC error on `/mcp`.** The rule allows the name, and it is not `<server>.<tool>` of a server the policy lists.

**Fix:** run `tools/list` for the names.

### mcp_client_not_allowed

**JSON-RPC error on `/mcp`.** The caller's rule has `mcp_clients`, and the MCP client is not one of them. The message names the clients the rule lets connect and what this client called itself.

**Fix:** use a client the rule names, or ask an admin to add this one. See [Client allowlist](/governance/mcp-gateway/#client-allowlist).

### session_revoked

**JSON-RPC error on `/mcp`.** An admin ended this MCP session.

**Fix:** connect the MCP client again. See [Sessions](/governance/mcp-gateway/#sessions).

### model_not_allowed

**403.** The first rule that names the caller does not list the model. The message names the rule and what it allows. Also when the rule allows the model and the caller's key has its own `models:` list without it: the message then names the key and its list, and the record has `key_models: true`.

**Fix:** use an allowed model, or ask an admin to change the policy.

### caller_provider_key_not_allowed

**403.** The request carries `x-enterplace-provider-key`, and the caller's rule does not set `caller_provider_key: allowed`. The request is not forwarded, with that key or with Enterplace's.

**Fix:** send it without the header, or ask an admin to set `caller_provider_key: allowed` on the rule. See [A caller's own provider key](/governance/provider-credentials/#a-callers-own-provider-key).

### caller_provider_key_unsupported

**400.** The model is served on Amazon Bedrock, whose requests Enterplace signs with AWS keys, so a caller's provider key cannot be used.

**Fix:** send it without `x-enterplace-provider-key`.

### caller_provider_key_invalid

**400.** `x-enterplace-provider-key` is empty or holds a character that cannot go in an HTTP header. Sent twice, it is `ambiguous_key` instead.

**Fix:** send the provider key alone, once.

### unknown_model

**403.** The rule allows the model, but no provider lists it, or an alias has no deployment Enterplace can reach. It is 403, not 404, because Claude Code replaces the message of a 404 with its own and retries a 400.

**Fix:** check the model name, or an admin adds it to a provider. The console's **New and pending** page lists the model with **Add a provider**, and the message names that page. See [Providers](/providers/overview/).

### wrong_route

**400.** The model is served by a provider that speaks the other API. The message names the route to use and, where it applies, the provider setting that would allow it:

- A chat request for an `anthropic`, `bedrock` or `vertex_anthropic` model. An admin can set `accept_chat: true`.
- A messages request for a chat provider without `accept_messages`. An admin can set it.
- `count_tokens` for a `bedrock` or `vertex_anthropic` model, or a model on a provider with `accept_messages`.
- A Responses, embeddings, images, audio, moderations or rerank request for a model on a provider not of kind `openai`.

**Fix:** send chat requests for `openai`, `azure`, `gemini` and `vertex` models to `/v1/chat/completions`, messages requests for `anthropic`, `bedrock` and `vertex_anthropic` models to `/v1/messages`, and the other `/v1` routes to `openai` models only. To serve the model on this route too, an admin adds a provider that takes it, with **Add a provider** on the console's **New and pending** page, which the message names.

### untranslatable

**400** before the record: a chat request for a provider with `accept_chat: true` holds a field the messages API has no equivalent for, or a messages request for a provider with `accept_messages: true` holds one chat completions has none for (thinking of type `enabled`, a server tool, a `context_management` edit other than clearing thinking). A chat request to a `gemini` or `vertex` model that cannot be translated is refused the same way. The message names the field.

**502** after the record: the provider's whole answer to a translated request could not be translated back.

**Fix:** remove the field, or use a model whose provider speaks the route's API. For a 502, tell the admin.

### unknown_query

**400.** A query parameter the route does not forward, a value it does not take, or a parameter given twice. Allowed: `beta` (`true` or `false`) on the messages routes, `limit` (1 to 1000) on `/v1/models`, none elsewhere. The value is never repeated in the message.

**Fix:** remove the parameter.

### guardrail_blocked

**403.** A guardrail the rule names refused the request. The message names the guardrail, the kinds it found (for example `aws_access_key (1)`) and where (`/messages/0/content`), never the text. A `fail_closed` webhook guardrail that could not check the request refuses with this code too, and says so.

Also 403 when a guardrail with `on: [answer]` withheld the model's whole answer. That one comes after the request was recorded as allowed, and has an `answer_guardrails` record with the same ID.

**500** when a guardrail masked the request and the masked body could not be written. The unmasked body is never sent.

An [events guardrail](/governance/plugin-events/) refuses with this code too: 403 when its plugin blocks a request, an answer, a tool call or a tool result, and 502 when the plugin masked something and the mask could not be written.

**Fix:** remove what was found and send again. For a guardrail service that is down, try later or tell the admin. See [Guardrails](/governance/guardrails/).

### session_ended

**403.** An [events guardrail](/governance/plugin-events/#the-verdict)'s plugin ended this session (`session_action: end`), so every request of the session is refused for the guardrail's `session_end_seconds`. The message names the guardrail. The provider is not called.

**Fix:** start a new conversation. If the session was ended in error, ask the admin about the guardrail.

### application_not_allowed

**403.** The request names an application in `x-enterplace-application` that its rule's `applications` does not list. See [Applications](/governance/plugin-events/#applications).

**Fix:** leave the header out, or ask the admin to add the application (or `"*"`) to the rule.

## Limits

### rate_limited

**429.** The caller sent as many requests in the last minute as `rate: { rpm: N }` allows, or the tokens used in the last minute, plus those held by requests in flight, plus the most this request could use would pass a `tpm` limit (the rule's, or the key's). `Retry-After` says how many seconds to wait. A request that could use more tokens than a whole minute allows is refused without `Retry-After`. The record's `limit` field names the limit.

**Fix:** wait the seconds in `Retry-After`, or send a smaller `max_tokens`. See [Budgets and rate limits](/governance/budgets-and-rate-limits/).

### batch_too_many_lines

**400.** A batch file or message batch holds more lines than the rule's `batch: { max_lines }` allows. Checked at upload and again when the batch is created.

**Fix:** split it into batches of at most that many lines, or ask an admin to raise the limit.

### batch_too_many_open

**429.** You have as many batches not yet ended as the rule's `batch: { max_open }` allows, counting OpenAI batches and Anthropic message batches. A batch counts until Enterplace sees it end.

**Fix:** wait for one to end, or cancel one, and send it again.

### budget_exceeded

**429.** Spent, plus what requests in flight reserved, plus the most this request could cost would pass a `budget` of the rule or of a `limits:` scope (global, organization, team, person, customer, tag, model). The message names the scope, how much is spent of how much, what requests in flight hold, where the budget is written, and when it starts again in its time zone. The record's `applied` field names the scope's counter and the entry.

**Fix:** wait for the period to end, send a smaller `max_tokens`, or ask an admin to raise the budget.

### key_budget_exceeded

**429.** The key has a `budget:` of its own, and its spend plus what its requests in flight reserved plus the most this request could cost would pass it. The message names the key by the first 8 hex characters of its hash.

**Fix:** wait for the period to end, or ask an admin to raise the key's budget.

### session_budget_exceeded

**429.** The rule has `budget: { usd, per: session }`, and what the request's session spent plus the most this request could cost would pass it. The message names the session.

**Fix:** start a new session (a new conversation in the tool), or ask an admin to raise the session budget. See [Session budgets](/governance/budgets-and-rate-limits/#session-budgets).

### session_requests_exceeded

**429.** The request's session has sent the rule's `rate.session_requests` requests.

**Fix:** start a new session, or ask an admin to raise `session_requests`.

### required_missing

**400.** The rule's `require:` lists a header or a body field the request does not carry, or carries empty. The message names each one missing.

**Fix:** send the header or the field with a value. See [Required headers and fields](/governance/policy/#required-headers-and-fields).

### key_bounds_exceeded

**403.** A key was asked for with a longer life, a faster budget or a model beyond what `key_bounds:` lets the issuer's role grant. On the admin API and `enterplace login`.

**Fix:** ask for less, or leave the field out to get the most allowed. See [Bounds on issued keys](/governance/keys/#bounds-on-issued-keys).

### parallel_limited

**429.** A `parallel:` limit of the rule, the key or a `limits:` scope already has that many requests in flight. `Retry-After: 1`.

**Fix:** send it again when one of them has finished, or ask an admin to raise the limit.

### customer_not_allowed

**403.** `x-enterplace-customer` names a customer the rule's `customers:` does not list, or another customer than the one the key is for.

**Fix:** leave the header out, use that customer's key, or ask an admin to list the customer (or `"*"`) on the rule.

### tag_not_allowed

**403.** `x-enterplace-tags` holds a tag the rule's `tags:` does not list. Tags are refused by name so they cannot be forged.

**Fix:** remove the tag, or ask an admin to add it to the rule.

### bad_header

**400.** `x-enterplace-customer` or `x-enterplace-tags` is sent more than once, holds a name with characters Enterplace does not accept, or brings the request to more than 16 tags.

**Fix:** send each header once, with names in letters, digits, `.`, `-`, `_` and `@`.

### no_price

**403.** A budgeted rule reached a model with no price. Only possible in a configuration built in code: `enterplace check` refuses it in a policy file.

**Fix:** add the model's price under `prices:`.

### tag_not_allowed

`x-enterplace-tags` holds a tag the rule's `tags:` does not list. The message names the tag and the list.

### region_not_allowed

The rule has `regions:` and the request has no deployment in one of them: an alias with no deployment labelled so, a model that is not an alias, or a passthrough call. Nothing was sent. See [Residency](/routing/strategies/#residency-regions).

### no_deployment

Every deployment of the alias that the request may use is kept (`for:`) for another team or tag.

### deployment_limit

**429.** Every deployment of the alias is at its `max_parallel`, `rpm` or `tpm`, counted across every replica on the store. Nothing was sent.

**Fix:** try again in a moment, or ask an admin to raise the limits or add a deployment. See [Deployment limits](/routing/strategies/#balance).

### batch_not_configured

**400.** The batch file's model runs on a Bedrock or Vertex AI provider that has no `batch:` section, so there is no bucket for its batch job.

**Fix:** ask an admin to add `batch: { bucket: ... }` to the provider.

### wrong_endpoint

**400.** The batch file's model runs on Bedrock or Vertex AI, and its lines name another `url` than `/v1/chat/completions`, the one Enterplace translates for those batch jobs.

**Fix:** write the lines as chat completions requests.

### provider_refused

**4xx, the provider's own.** Bedrock, Vertex AI, S3 or Cloud Storage refused what Enterplace asked for a batch (keeping its file, starting or describing its job). The message carries the provider's words.

**Fix:** act on the provider's message, often a bucket permission or a model the account cannot run in batch.

## Audit and provider

### audit_unavailable

**503.** The record could not be written: the disk failed, or the log was deleted, moved, replaced or cut short. Every request, admin call and console action is refused until a restart, and `/healthz` answers 503. This refusal has no record, because that is the problem it reports.

**Fix:** the admin checks the log file and the server's stderr, then restarts. See [Running in production](/operations/operations/#disk-full-and-audit-repair).

### store_unavailable

**503.** A budget applies to the request, and Enterplace cannot reach the Postgres [store](/operations/store/) to reserve what it could cost. It is refused rather than let through unchecked. Requests without a budget are still served, and known keys keep working.

**Fix:** the admin checks the database and the connection string in the variable `store: postgres_url_env` names. Budgeted requests are served again within a second of the database answering.

### upstream_unreachable

**502.** Enterplace could not connect to the provider within the 5 second connect timeout.

**Fix:** try again. If it persists, the admin checks the provider URL and the network.

### upstream_failed

**502.** The provider broke the connection before answering, or Enterplace could not sign a Bedrock request with the configured credentials and region.

**Fix:** try again. If it persists, tell the admin.

### upstream_timeout

**504.** The provider sent nothing for 120 seconds.

**Fix:** try again, or with a smaller request.

### bad_path

**400.** The request path could not be joined to the provider URL.

**Fix:** check the path.

### no_upstream

**503.** Only with `enterplace serve --unchecked`: `ENTERPLACE_UPSTREAM` is not set.

**Fix:** set `ENTERPLACE_UPSTREAM` and restart.

<Aside type="note">
With `retries` or a `fallback` on the provider, an `upstream_*` failure, a 429 or a 5xx is tried again before any byte reaches the caller, and an `attempts` record lists every try. The caller sees only the last outcome.
</Aside>

## Admin API codes

These come from `/admin/keys`, `/admin/kills` and `/admin/credentials`, in OpenAI's shape. `no_key`, `ambiguous_key`, `unknown_key`, `unknown_route`, `busy`, `body_too_large`, `body_timeout` and `audit_unavailable` apply there too. See [Admin API](/reference/admin-api/).

### not_admin

**403.** The key is valid, but its entry does not say `admin: true` and gives no role. For a [JWT on the admin API](/governance/access-control/#the-admin-api): its issuer has no `role_claim`, or the claim holds none of the values in a role's `sso_values`.

**Fix:** use an admin key, or ask an admin to give you a role (for a JWT, to add your group to a role's `sso_values`).

### invalid_request

**400.** The body is not the JSON object the route takes, has an unknown field, or holds a value out of range: a name or team with characters other than letters, digits, dots, dashes, underscores and `@` or over 100 characters, a bad expiry, a budget that is not above 0 per `day` or `month`, an empty `models` list or a model not served, a `tpm` outside 1 to 1000000000, a key prefix that is not 8 to 64 hex characters, a kill scope other than `person`, `team`, `key_prefix`, `model` or `all`, or a kill reason that is not 1 to 500 characters.

**Fix:** correct the field the message names.

### kill_matches_nothing

**400.** The kill switch names a person, team, key or model that no key holds and no provider serves, so it would stop nothing. The message lists names close to it.

**Fix:** name one that exists, or send `"force": true` (`enterplace kill --force`).

### already_rotated

`POST /admin/keys/<prefix>/rotate` on a key that was already rotated. Rotate the key that replaced it.

### no_such_key

**404.** No key in the keys file has a hash starting with that prefix, or someone else removed it meanwhile.

**Fix:** list the keys with `GET /admin/keys`.

### no_such_switch

**404.** No kill switch is on for that scope and value.

**Fix:** list the switches with `GET /admin/kills`.

### keys_file

**409.** The keys file could not be read or written, or changed while Enterplace was writing it.

**Fix:** check the file and its permissions, then try again.

### kills_file

**409.** The kill switch file could not be read or written.

**Fix:** check `enterplace.kills.json` and its permissions, then try again.

### credentials_need_store

**404.** A `/admin/credentials` call on a gateway whose policy has no `store:`.

**Fix:** keep provider keys in `key_env` or `key_file`, or add `store:` and set `ENTERPLACE_MASTER_KEY`.

### no_master_key

**409.** A `/admin/credentials` call on a gateway started without `ENTERPLACE_MASTER_KEY`.

**Fix:** set `ENTERPLACE_MASTER_KEY` (the same on every gateway on the store) and restart.

### credential_exists

**409.** `POST /admin/credentials` with a name the store already holds.

**Fix:** rotate it with `PUT /admin/credentials/<name>`, or choose another name.

### no_such_credential

**404.** No credential has that name.

**Fix:** `GET /admin/credentials` lists them.

### credential_in_use

**409.** A provider of the policy in use names the credential, so it is not removed.

**Fix:** point the provider at another credential or `key_env` first, or rotate this one.

### no_randomness

**503.** The operating system gave no randomness for a new key.

**Fix:** try again.

### internal

**500.** The change stopped before it finished.

**Fix:** check the keys file and try again.

## Single sign-on codes

Console and `enterplace login` sign-ins that fail show a page with the cause and the fix, and write an `admin` record with `action: console_sign_in` and one of these codes. See [Single sign-on](/governance/single-sign-on/).

| Code | Cause |
|---|---|
| `sso_config` | `console.sso` is not set up, or does not pass the check |
| `sso_secret` | The variable `client_secret_env` names is not set |
| `sso_provider` | The identity provider's discovery document or key set could not be read, names an endpoint that is not https, or does not offer PKCE with S256 |
| `sso_issuer` | The discovery document names a different issuer than `console.sso.issuer` |
| `sso_state` | The sign-in came back with a state this browser did not start, already used, or older than 10 minutes |
| `sso_token` | The code could not be traded for an ID token |
| `sso_signature` | The ID token is signed with an algorithm other than RS256 or ES256, or the signature does not hold |
| `sso_unknown_key` | The ID token names a signing key that is not in the provider's key set |
| `sso_audience` | The ID token was issued for another client |
| `sso_expired` | The ID token has expired |
| `sso_nonce` | The ID token's nonce does not match the sign-in |
| `sso_email` | The ID token has no email, an email marked unverified, or one not in `allowed_emails` or `allowed_domains` |
| `sso_role` | The role claim holds no value from `admin_values` or `read_only_values` |
| `sso_self_issue` | `enterplace login` is used and the policy has no `console.sso.self_issue` section |
| `sso_team` | `enterplace login`: the policy's `teams:` place people, place this person in no team, and `self_issue.team` is not written |
| `saml_response` | The SAML response could not be read: not base64, not XML Enterplace takes, or not exactly one assertion |
| `saml_status` | The identity provider did not sign the person in |
| `saml_unsigned` | The SAML assertion is not signed |
| `saml_signature` | The SAML signature does not verify with `idp_certificate`, or uses an algorithm Enterplace does not take |
| `saml_issuer` | The assertion's issuer is not `console.saml.idp_entity_id` |
| `saml_audience` | The assertion names no audience, or not `console.saml.sp_entity_id` |
| `saml_recipient` | The response is addressed to another ACS URL |
| `saml_expired` | The assertion is expired or not valid yet |
| `saml_replay` | The response answers no request this browser started, or was used already |
| `saml_encrypted` | The assertion is encrypted |
| `cli_login` | A `enterplace login` link was cut short or changed |

Inside a signed-in console session, `not_admin` is recorded for a key that is not an admin's, and `read_only` for a read-only person who tries to issue or revoke a key.

## Not a refusal

A provider's own error passes through unchanged, with `X-Enterplace-Decision` added. Two exceptions keep the caller's error shape: a Bedrock error is put in Anthropic's shape, and an error answer to a translated chat request is put in OpenAI's shape, each with the provider's message.

A request the HTTP library rejects as malformed gets a bare 400 with no body, no code and no decision ID. A client that takes more than 10 seconds to send its headers is disconnected.
