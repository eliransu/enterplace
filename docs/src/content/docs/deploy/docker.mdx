One Compose file runs the gateway and Postgres 16 on one machine, each with a named volume: `gantry-data` for the audit log and `postgres-data` for the database. It fits a trial on a laptop and a team on one VM. You need Docker and the two files on this page. Nothing is cloned or built.

## Prerequisites

- Docker with Compose 2.23 or later (`docker compose version`).
- Your license key, and a key for at least one provider (OpenAI in this guide).

## From nothing to a governed call

<Steps>

1. Make a folder and save the Compose file in it. The policy is inside it, under `configs:`.

   ```bash
   mkdir gantry && cd gantry
   ```

   ```yaml title="docker-compose.yml"
   # Gantry Enterprise on one machine: the gateway and Postgres 16, each with its own named volume.
   # Settings come from .env beside this file. Admin commands run with the same image:
   #   docker compose run --rm gantry <command>
   name: gantry

   services:
     postgres:
       image: postgres:16-alpine
       environment:
         POSTGRES_USER: gantry
         POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?set POSTGRES_PASSWORD in .env}
         POSTGRES_DB: gantry
       volumes:
         - postgres-data:/var/lib/postgresql/data
       # Gantry shares this container's network (network_mode below), so its port is published here.
       ports:
         - "${GANTRY_BIND:-127.0.0.1}:${GANTRY_PORT:-8080}:8080"
       healthcheck:
         test: ["CMD", "pg_isready", "-U", "gantry", "-d", "gantry"]
         interval: 2s
         timeout: 3s
         retries: 30
       restart: unless-stopped

     gantry:
       image: ${GANTRY_IMAGE:-ghcr.io/eliransu/gantry:latest}
       command: ["serve", "/etc/gantry/gantry.policy.yaml", "--keys", "/var/lib/gantry/gantry.keys.yaml", "--listen", "0.0.0.0:8080"]
       # Sharing Postgres's network keeps the database off every other network, so the connection is plain.
       network_mode: service:postgres
       environment:
         DATABASE_URL: postgres://gantry:${POSTGRES_PASSWORD}@localhost:5432/gantry?sslmode=disable
         OPENAI_PROVIDER_KEY: ${OPENAI_PROVIDER_KEY:-}
         GANTRY_LICENSE: ${GANTRY_LICENSE:-}
         # Optional, both: empty leaves the feature off. See .env.
         GANTRY_MASTER_KEY: ${GANTRY_MASTER_KEY:-}
         GANTRY_EXPORT_KEY: ${GANTRY_EXPORT_KEY:-}
       configs:
         - source: policy
           target: /etc/gantry/gantry.policy.yaml
       volumes:
         # The audit log. One volume per gateway: each writes its own hash chain.
         - gantry-data:/var/lib/gantry
       depends_on:
         postgres:
           condition: service_healthy
       # No read_only: Compose cannot place the policy in a read-only container. The image runs as user 65532 and
       # holds one binary, so the only folder Gantry can write is its volume.
       cap_drop: [ALL]
       security_opt: ["no-new-privileges:true"]
       # 30 s for requests in flight after SIGTERM, plus margin, so the audit log is synced before the stop.
       stop_grace_period: 40s
       restart: unless-stopped

   configs:
     # The policy. Reference: https://gantry-docs.eliran.me/governance/policy/
     policy:
       content: |
         version: 1
         providers:
           - name: openai
             kind: openai
             url: https://api.openai.com/v1
             key_env: OPENAI_PROVIDER_KEY
             models: [gpt-4o-mini]
         rules:
           - name: everyone
             principals: { any: true }
             models: [gpt-4o-mini]
         # On the volume: everything else in the container is read-only.
         audit: { path: /var/lib/gantry/gantry-audit.jsonl }
         # Keys, kill switches and budgets live in Postgres.
         store: { postgres_url_env: DATABASE_URL }

   volumes:
     postgres-data:
     gantry-data:
   ```

2. Save the settings beside it as `.env`, and fill in the empty values. `GANTRY_MASTER_KEY` and `GANTRY_EXPORT_KEY` are optional: leave them empty until you keep [provider credentials](/governance/provider-credentials/) in the store or send the audit log to a [SIEM](/operations/siem-export/) destination with a secret.

   ```bash title=".env"
   # Letters and digits only: it goes into a connection string unescaped. `openssl rand -hex 16` makes one.
   POSTGRES_PASSWORD=
   # The provider key the policy names in key_env.
   OPENAI_PROVIDER_KEY=
   # Your license key, on one line. Empty runs the open source features only.
   GANTRY_LICENSE=
   # Optional. Seals provider credentials kept in Postgres (Provider credentials in the console). 64 hex characters,
   # made once with `openssl rand -hex 32` and kept in your secret manager: a lost one cannot be recovered.
   # Empty: credentials are off, and providers use key_env as above.
   GANTRY_MASTER_KEY=
   # Optional. Encrypts the secrets of SIEM export destinations (license feature siem). 64 hex characters,
   # `openssl rand -hex 32`. Empty: only destinations that need no secret can be saved.
   GANTRY_EXPORT_KEY=
   # The image. Pin a release version, or a commit SHA, in production.
   GANTRY_IMAGE=ghcr.io/eliransu/gantry:latest
   # Where Gantry listens on this machine.
   GANTRY_BIND=127.0.0.1
   GANTRY_PORT=8080
   ```

   ```bash
   chmod 600 .env
   ```

3. Start the stack.

   ```bash
   docker compose up -d
   curl -s http://127.0.0.1:8080/healthz
   ```

   ```json
   {"status":"ok","policy_sha256":"2e4896bb...","keys_sha256":"aebe9c54...","rejected":null}
   ```

   Compose pulls the image, waits for Postgres to be healthy, and starts Gantry, which creates its tables in the `gantry` database. `docker compose logs gantry` shows what it started with:

   ```text
   License lic_8f2 for Acme: scim, siem, 50 seats, until 2027-11-13.
   warning: DATABASE_URL says sslmode=disable, so the connection to the store is not encrypted: ...
   gantry enterprise 0.0.1 listening on http://0.0.0.0:8080
   First run: no admin key yet. Open http://127.0.0.1:8080/console/setup/efe8afe6... to make the first one. The link works once.
   Audit log: /var/lib/gantry/gantry-audit.jsonl is new. The chain starts at record 1.
   1 rule, 0 keys, 1 provider: openai (openai) at https://api.openai.com/v1.
   Keys, kill switches and budgets are shared through the store named by DATABASE_URL with every Gantry on that database.
   ```

   The `sslmode=disable` warning is expected here: Gantry shares the Postgres container's network, so database traffic never leaves the machine.

4. Make the first admin and sign in to the console. Print the one-time link and open it in a browser on this machine.

   ```bash
   docker compose logs gantry | grep 'First run'
   ```

   Give your name and team. The page shows your admin key once: keep it in your password manager. Sign in at `http://127.0.0.1:8080/console` with it.

5. Issue a key and make a governed call. Admin commands run with the same image: `docker compose run --rm gantry <command>` takes every `gantry` command.

   ```bash
   KEY=$(docker compose run --rm -T gantry key new maya.cohen --team payments --policy /etc/gantry/gantry.policy.yaml --quiet)
   sleep 2
   curl -s http://127.0.0.1:8080/v1/chat/completions \
     -H "Authorization: Bearer $KEY" -H 'Content-Type: application/json' \
     -d '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"Say hi"}]}'
   ```

   `key new` writes the key's hash to Postgres, because the policy has `store:`, and prints the key alone. The gateway accepts it within 2 seconds. The answer is OpenAI's, with an `X-Gantry-Decision` header added. A call without a key is refused with 401 `no_key`.

6. Verify the audit log.

   ```bash
   docker compose run --rm -T gantry audit verify /var/lib/gantry/gantry-audit.jsonl
   ```

   ```text
   /var/lib/gantry/gantry-audit.jsonl: 9 records in an unbroken chain from record 1 to record 9.
   1 request, 3 configuration records, 4 admin records, 1 usage record.
   Last hash: b92eb3a59f5e593cc7ad082fb6308e924b5f32f6f152163b935e574169e44ec3
   ```

   The console's **Audit log** page does the same with **Verify chain now**.

</Steps>

## Change the policy

The policy is the `content:` under `configs:` in `docker-compose.yml`. Edit it, then recreate the gateway; Compose sees the change.

```bash
docker compose up -d
docker compose run --rm -T gantry check /etc/gantry/gantry.policy.yaml
```

```text
/etc/gantry/gantry.policy.yaml is valid: 1 rule, keys in the store named by DATABASE_URL, 1 provider: openai (openai) at https://api.openai.com/v1.
```

To change the policy without a restart, keep it in a file: save the YAML as `gantry.policy.yaml` beside `docker-compose.yml`, replace `content: |` and the lines under it with `file: ./gantry.policy.yaml`, and run `docker compose up -d` once. From then on Gantry uses each saved change within 2 seconds, or keeps the version it has and records `config_rejected`. Changing the `store:` section always needs `docker compose up -d --force-recreate gantry`.

## Try it without a provider key

A stand-in for OpenAI answers every chat call with `pong`, so the steps above work before you have a provider key. Save this beside `docker-compose.yml`; Compose reads it on every command.

```yaml title="docker-compose.override.yml"
# A stand-in for OpenAI, for a trial: delete this file to use OpenAI.
services:
  mock:
    image: python:3.12-alpine
    command:
      - python
      - -c
      - |
        import json
        from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer
        class Handler(BaseHTTPRequestHandler):
            def do_POST(self):
                body = json.loads(self.rfile.read(int(self.headers.get("Content-Length", 0))) or b"{}")
                answer = json.dumps({
                    "id": "chatcmpl-mock", "object": "chat.completion", "created": 0,
                    "model": body.get("model", "gpt-4o-mini"),
                    "choices": [{"index": 0, "message": {"role": "assistant", "content": "pong"}, "finish_reason": "stop"}],
                    "usage": {"prompt_tokens": 5, "completion_tokens": 1, "total_tokens": 6},
                }).encode()
                self.send_response(200)
                self.send_header("Content-Type", "application/json")
                self.send_header("Content-Length", str(len(answer)))
                self.end_headers()
                self.wfile.write(answer)
        ThreadingHTTPServer(("0.0.0.0", 9000), Handler).serve_forever()

configs:
  policy:
    content: |
      version: 1
      providers:
        - name: openai
          kind: openai
          url: http://mock:9000/v1
          # The stand-in is on the Compose network, a private address Gantry refuses unless told.
          allow_private: true
          models: [gpt-4o-mini]
      rules:
        - name: everyone
          principals: { any: true }
          models: [gpt-4o-mini]
      audit: { path: /var/lib/gantry/gantry-audit.jsonl }
      store: { postgres_url_env: DATABASE_URL }
```

Then run steps 3 to 6. The governed call answers `pong`. To switch to OpenAI, delete the file, set `OPENAI_PROVIDER_KEY` and run `docker compose up -d --remove-orphans`.

## Production on one VM

<Steps>

1. **Pin the image.** Set `GANTRY_IMAGE` in `.env` to a release version, or a commit SHA, never `latest`, so an upgrade happens only when you choose it.

   ```bash title=".env"
   GANTRY_IMAGE=ghcr.io/eliransu/gantry:<version>
   ```

2. **TLS.** Keep `GANTRY_BIND=127.0.0.1`, so Gantry listens on this machine only, and put Caddy on the VM in front of it. Caddy gets and renews the certificate.

   ```text title="/etc/caddy/Caddyfile"
   gantry.example.com {
       reverse_proxy 127.0.0.1:8080 {
           flush_interval -1
       }
   }
   ```

   For nginx, see [Deployment](/operations/deployment/#a-proxy-in-front). Callers then use `https://gantry.example.com/v1`.

3. **Secrets.** `.env` holds the database password, the provider keys, the license and, when set, the master key and the export key. Keep a copy of the master key in your secret manager: without it, the provider credentials in the database cannot be opened. Keep `.env` readable by its owner only (`chmod 600 .env`), out of version control, or write it at boot from your secret manager.

4. **Start on boot.** Every service has `restart: unless-stopped`, so the stack comes back when Docker does.

   ```bash
   sudo systemctl enable docker
   ```

5. **Back up Postgres** on a schedule. It holds the keys, kill switches and spend.

   ```bash
   docker compose exec -T postgres pg_dump -U gantry gantry > gantry-db-$(date +%F).sql
   ```

   To restore, stop the gateway, load the dump into an empty database, and start it again:

   ```bash
   docker compose stop gantry
   docker compose exec -T postgres dropdb -U gantry gantry
   docker compose exec -T postgres createdb -U gantry gantry
   docker compose exec -T postgres psql -q -U gantry -d gantry < gantry-db-2026-11-13.sql
   docker compose start gantry
   ```

6. **Back up the audit volume** and keep its last hash where the VM cannot write. A chain cannot show records removed from its end; the kept hash can.

   ```bash
   docker run --rm -v gantry_gantry-data:/data:ro -v "$PWD":/backup busybox:1.36.1 \
     tar czf /backup/gantry-data-$(date +%F).tgz -C /data .
   docker compose run --rm -T gantry audit verify /var/lib/gantry/gantry-audit.jsonl | sed -n 's/^Last hash: //p'
   ```

   Later, `audit verify ... --expect-last <kept hash>` proves no record up to it was changed or removed. To ship the log as it is written, see [Observability](/operations/observability/#shipping-the-audit-log).

7. **Monitoring.** Add metrics and traces in `docker-compose.override.yml` beside `docker-compose.yml`. The port is published on the `postgres` service because Gantry shares its network.

   ```yaml title="docker-compose.override.yml"
   services:
     postgres:
       ports:
         - "127.0.0.1:9464:9464"
     gantry:
       command: ["serve", "/etc/gantry/gantry.policy.yaml", "--keys", "/var/lib/gantry/gantry.keys.yaml", "--listen", "0.0.0.0:8080", "--metrics", "0.0.0.0:9464"]
       environment:
         OTEL_EXPORTER_OTLP_ENDPOINT: http://otel-collector.internal:4318
   ```

   ```bash
   docker compose up -d
   curl -s http://127.0.0.1:9464/metrics | head -3
   ```

   Point your uptime check at `https://gantry.example.com/healthz`. Scrape configuration and alerts are in [Observability](/operations/observability/#scrape-and-alert).

8. **Upgrade.** Back up Postgres first: a newer Gantry may update the database schema, and an older one refuses a database a newer one has written. Then set the new version in `GANTRY_IMAGE` and recreate the gateway. Requests in flight get 30 seconds.

   ```bash
   docker compose exec -T postgres pg_dump -U gantry gantry > gantry-db-before-upgrade.sql
   docker compose pull gantry
   docker compose up -d
   docker compose logs gantry | grep 'Audit log'
   ```

   The start line says the chain continues at the next record.

9. **Roll back.** Set `GANTRY_IMAGE` back to the previous version and run `docker compose up -d`. If the previous version refuses the database because the new one changed its schema, restore the dump taken before the upgrade, as in step 5.

</Steps>

### What to watch

| Signal | Meaning | Do |
|---|---|---|
| `/healthz` answers 503, or `gantry_audit_broken` is `1` | The audit log cannot be written. Every request is refused | Free disk space on the volume, then `docker compose restart gantry` |
| Refusals with `store_unavailable` | Postgres is down. Requests under a budget are refused; others are served | `docker compose ps postgres`, `docker compose logs postgres` |
| Disk use of the `gantry-data` volume | About 1.35 GB per million requests | [Start a new chain](/operations/operations/#start-a-new-chain) before the disk fills |
| The license line at start | A warning means the license is in its 30-day grace period | Set the renewed license and recreate the gateway |
| Certificate expiry | Caddy renews on its own; a certificate you manage does not | Renew before it lapses |

<Aside type="caution">
One gateway per `gantry-data` volume. Two processes writing one audit log break its chain. `docker compose run --rm gantry` runs admin commands, never a second `serve`. To run more than one replica, use [Kubernetes](/deploy/kubernetes/) or [AWS](/deploy/aws/).
</Aside>
