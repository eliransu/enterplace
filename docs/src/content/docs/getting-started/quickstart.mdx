Three steps, about two minutes, no provider key needed.

**1. Install**

<Tabs syncKey="install">
<TabItem label="macOS and Linux">

```bash
curl -fsSL https://enterplace.dev/install.sh | sh
```

</TabItem>
<TabItem label="Docker">

```bash
docker run --pull always -d --name enterplace -p 8080:8080 -v enterplace-data:/var/lib/enterplace ghcr.io/eliransu/enterplace
```

The container runs step 2 itself. `docker logs enterplace` prints the dashboard link: open it in your browser and go to step 3.

</TabItem>
</Tabs>

**2. Start it**

```bash
enterplace start
```

**3. Your browser opens:** pick what you want to start with and follow the steps. The first step connects a model (paste a provider key) or tries the free demo model; the second sends your first request, and you see it arrive.

Or send the first request from the terminal, with the `export ENTERPLACE_KEY=...` line that `enterplace start` printed:

```bash
curl http://127.0.0.1:8080/v1/chat/completions \
  -H "Authorization: Bearer $ENTERPLACE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"enterplace-demo","messages":[{"role":"user","content":"hello"}]}'
```

The answer starts with `Hello from the Enterplace demo model.`, and the request is in the dashboard under **Requests**. Next, connect a coding agent ([Codex](/integrations/codex/), [Claude Code](/integrations/claude-code/), [Gemini CLI](/integrations/gemini-cli/) or [another tool](/integrations/coding-tools/)) or [your own app](/integrations/sdks/).

Everything below is detail.

## What enterplace start does

In the current folder it writes `enterplace.policy.yaml` in observe mode (nothing is blocked: every request is sent and recorded, and one a rule would stop is marked `would_refuse`), an admin key and a person token for you (their hashes in `enterplace.keys.yaml`) and `enterplace-master.key`, then serves on `http://127.0.0.1:8080`. The first lines it prints:

```text
Enterplace is running. Open the dashboard:

  http://127.0.0.1:8080/console/sign-in/4be1...

The link signs you in once, from this machine, within 10 minutes. Opening it in your browser now.

Admin key, shown once (Enterplace keeps only its hash). Use it for the command line and the API:

  export ENTERPLACE_KEY=enterplace_3f9c...

Claude Code on your Claude subscription, with sarah on every request: paste these two lines in your shell, then run claude. The person token is shown once.

  export ANTHROPIC_BASE_URL=http://127.0.0.1:8080
  export ANTHROPIC_CUSTOM_HEADERS="x-enterplace-user: enterplace_u_8a2d..."
```

The link is the sign-in: it works once, only from a browser on the same machine, for 10 minutes, and the sign-in is recorded in the audit log. On a terminal with a display, Enterplace opens it for you; `--no-open` skips that. Keep the admin key in your password manager: it signs in to the console too, and the command line and the admin API use it.

**Claude subscriptions.** The policy also has a provider named `claude-subscriptions` with `auth: passthrough`: Claude Code on a Claude Pro, Max, Team or Enterprise login goes through Enterplace with no Anthropic key at all. Every request carries a person's name (`identity: required`), and the person token in the last two lines is yours (your user name on this machine, or `admin`), so your first `claude` request arrives named. A company can allow unnamed requests while it rolls out tokens, on the console's **Getting started** page under Coding agents ("Every request needs a name"); they show as the person `unknown`. See [Subscriptions](/governance/subscriptions/).

**Provider keys.** None is needed to start. A key in the environment is picked up (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, or the `*_PROVIDER_KEY` form), so `OPENAI_API_KEY=sk-... enterplace start` works too. A key pasted in the dashboard's **Connect a model** is sealed with `enterplace-master.key` (AES-256-GCM) and kept in `enterplace-credentials.json`, which holds only sealed bytes: keep the master key with the policy, and out of version control. To send a provider's requests through a proxy, set `ENTERPLACE_OPENAI_BASE_URL` (or `ENTERPLACE_ANTHROPIC_BASE_URL`, `ENTERPLACE_GEMINI_BASE_URL`) before `enterplace start`.

**The demo model.** The policy always has a provider named `demo` with the model `enterplace-demo`. Enterplace answers it itself with a short sample text (chat completions, responses and messages, streaming too), sends nothing anywhere and prices it at zero, so the first request works before any key is set. Its requests are recorded under the provider `demo`.

**Restart and start over.** Stop it with Ctrl-C, or with `enterplace stop` in the same folder from another terminal. `enterplace start` in the same folder serves the same policy again and prints a new sign-in link (no new admin key or person token). To start over, delete `enterplace.policy.yaml`, `enterplace.keys.yaml`, `enterplace-credentials.json`, `enterplace-master.key` and `enterplace-audit.jsonl`, or run `enterplace start --force` (which keeps the master key).

## The install script

The script picks the binary for your machine (macOS or Linux, x86_64 or arm64) from the latest GitHub Release, checks its release signature and SHA256, and installs it to `~/.local/bin`. When that folder is not on your PATH it adds it in your shell's startup file (`~/.zshrc`, `~/.bashrc`, `~/.bash_profile` on macOS, fish's `conf.d`, or `~/.profile`), once, and prints the one line that does it in the current terminal; `ENTERPLACE_NO_MODIFY_PATH=1` leaves the file alone. `ENTERPLACE_VERSION=edge` installs the build of the latest commit on main, `ENTERPLACE_VERSION=v0.4.0` a given release, and `ENTERPLACE_INSTALL_DIR=/usr/local/bin` another folder (with sudo when needed).

## The Docker image

The image is public: no login. `--pull always` fetches the newest `latest`, so a copy cached from an earlier day is never used. The first start writes the policy, the admin key and the master key to the `enterplace-data` volume and serves on port 8080; its log starts with the same block as `enterplace start`, with the link on `http://127.0.0.1:8080`. Inside a container the browser's address is the container network's, so the link works from any address there (once, within 10 minutes), as the admin key in the same log does.

- Restart: `docker restart enterplace`. Each start prints a new sign-in link in `docker logs enterplace`, and no new admin key.
- Start over: `docker rm -f enterplace && docker volume rm enterplace-data`.
- A provider key in the environment works too (`-e OPENAI_API_KEY=sk-...`), but you can paste it in the dashboard instead.

<Aside type="caution">
The admin key stays in the container's log until the container is removed. Copy it to your password manager, then read it back with `docker logs enterplace 2>&1 | grep ENTERPLACE_KEY` only if you lost it.
</Aside>

## The dashboard

The console opens on **Overview**, its home, with one card per use case: **Coding agents**, **Apps and agents** and **MCP tools**. On an empty install each card's **Set up** button opens that use case's checklist, on its Getting started page (or on **MCP tools**). **Other ways to start** offers two more: a spend limit for the team, or Claude Team seats you can only watch (Enterplace Enterprise). Every checklist but the last starts the same way:

1. **Connect a model**: pick OpenAI, Anthropic or Google Gemini and paste its key, or choose **Try without a key** for the demo model.
2. **Send your first request**: a ready-to-copy curl (with Python and Node tabs) holding the gateway's address and a key: `$ENTERPLACE_KEY`, or a key the step makes for it, shown once. The step turns done by itself when the request arrives, even if the provider refuses it: the request shows in Requests with the provider's answer.

**Coding agents** first asks how your team pays for its coding agents. With **API keys, any coding agent**, the default, any coding agent works: the checklist makes a key per person and shows the lines for Claude Code, Codex, Cursor, Gemini CLI or any OpenAI-compatible tool. With **Claude subscriptions, for Claude Code**, Claude Code keeps its own login: there is no model to connect and no API key, since `enterplace start` already wrote the `claude-subscriptions` provider, and the checklist mints a free person token and shows the two lines for Claude Code (`ANTHROPIC_BASE_URL` and `ANTHROPIC_CUSTOM_HEADERS`). Every step has **Copy for your agent**, a ready prompt that has your coding agent do the step for you. See [Subscriptions](/governance/subscriptions/).

The steps that follow are the choice's own: a key per person, the lines for Codex, Claude Code, Cursor, Gemini CLI or an SDK, a budget, an MCP server. Each says what **turns it done** and what you **then see**, and Enterplace checks its own records for it: the checklist ticks each step as the gateway sees it happen. Once the checklist is done, Overview shows the five steps of a rollout (See, Know, Limit, Protect, Prove, the same as the [Start here](/start/why/) pages).

A key, person token or sign-in no admin has reviewed is let through and listed on **Access requests**, since `enterplace start` writes `new_callers: { mode: allow }`. See [New callers](/governance/new-callers/).

## Verify the audit log

The audit log is `enterplace-audit.jsonl` beside the policy (in the container, `/var/lib/enterplace/enterplace-audit.jsonl` on the volume). Each record holds the hash of the one before it, so a removed or changed record shows:

```bash
enterplace audit verify enterplace-audit.jsonl
docker exec enterplace /enterplace audit verify /var/lib/enterplace/enterplace-audit.jsonl
```

```text
enterplace-audit.jsonl: 3 records in an unbroken chain from record 1 to record 3.
1 request, 1 configuration record, 1 admin record, 0 usage records.
Last hash: 9be869bf...
```

See [Audit log](/governance/audit-log/).

## With Postgres: Docker Compose

For a team, keys, kill switches, budgets and credentials live in Postgres, so they are shared and survive the container. One command runs Enterplace and Postgres 16 on one machine, with no provider key and no file to write:

```bash
mkdir enterplace && cd enterplace && curl -fsSLO https://raw.githubusercontent.com/eliransu/enterplace/main/deploy/compose/compose.yaml && docker compose up -d
docker compose logs enterplace | grep ENTERPLACE_KEY
```

The second line prints the admin key, once. The console is at `http://127.0.0.1:8080/console`, with the same Overview, checklists and free demo model. To write your own policy file, follow the [Docker Compose guide](/deploy/docker/); to run it in your cloud, use a [one-click deploy](/deploy/one-click/).

## From source

You need Rust 1.88 or later. The repository pins it in `rust-toolchain.toml`, so `rustup` installs it on the first build.

```bash
git clone https://github.com/eliransu/enterplace.git
cd enterplace
cargo build --release
target/release/enterplace start
```

This binary is the open source edition (MIT). The image runs the enterprise build, which without a license key is the same open source gateway.
