Qwen Code reaches Enterplace through its `openai` auth type. Its requests go to `POST /v1/chat/completions` on Enterplace, or to `POST /v1/responses` with `wireApi: responses`, identified by a Enterplace key.

<Aside type="tip" title="Before you start">
You need a running Enterplace and a Enterplace key. `enterplace start` gives both in one command and prints the key as `export ENTERPLACE_KEY=...`: see the [Quickstart](/getting-started/quickstart/). No provider key yet? Put the model `enterplace-demo` in place of the model in the examples below: Enterplace answers it itself, free. After your first prompt, **Requests** in the console shows it with the key's name, the model and the cost.
</Aside>

## Setup

<Tabs>
<TabItem label="Environment">

```bash
export OPENAI_BASE_URL=http://127.0.0.1:8080/v1   # Enterplace's address, with /v1
export OPENAI_API_KEY=enterplace_...                  # the Enterplace key
export OPENAI_MODEL=gpt-4o-mini                   # the model as the policy names it
qwen
```

With `OPENAI_API_KEY` set, Qwen Code picks its OpenAI-compatible auth from the environment alone. `--openai-base-url` and `--openai-api-key` do the same for one run.

</TabItem>
<TabItem label="settings.json">

```json title="~/.qwen/settings.json"
{
  "modelProviders": {
    "openai": [
      {
        "id": "gpt-4o-mini",
        "envKey": "ENTERPLACE_KEY",
        "baseUrl": "http://127.0.0.1:8080/v1",
        "wireApi": "chat-completions"
      }
    ]
  },
  "security": { "auth": { "selectedType": "openai" } },
  "model": { "name": "gpt-4o-mini" }
}
```

`envKey` names the variable that holds the Enterplace key, never the key itself. `baseUrl` is the `/v1` root: Qwen Code adds the request path. `wireApi: responses` uses `POST /v1/responses`, which reaches every provider: sent as it is to `openai` and `azure`, translated for the rest.

</TabItem>
</Tabs>

## What Enterplace governs

- Every model request: identity, the rule's model list, budgets, guardrails and one audit record each.
- Its records carry the user agent `QwenCode/<version>`, which [Coverage](/governance/coverage/) counts as `qwen-code`.

## What Enterplace does not see

- Usage statistics, sent to Qwen Code's own collection endpoint unless `QWEN_USAGE_STATISTICS_ENABLED=false` or `privacy.usageStatisticsEnabled: false`.
- The model catalog download from `models.dev`. `QWEN_CODE_MODELS_DEV=off` stops it.
- The built-in `web_search` tool on Qwen's own plans. With a Enterplace key it is not set up.

<Aside type="note">
This setup follows Qwen Code's configuration, auth and model providers documentation. It was run headless (`qwen -p`) against a local Enterplace and a mock provider: each turn was one allowed request on `/v1/chat/completions`.
</Aside>
