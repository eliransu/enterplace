Gemini CLI speaks Google's Gemini API. Enterplace serves that API on `/v1beta/models/<model>:<method>`, so Gemini CLI goes through Enterplace with two environment variables. Each request is checked against your policy, guarded, metered and recorded like a chat completions request.

<Aside type="tip" title="Before you start">
You need a running Enterplace and a Enterplace key. `enterplace start` gives both in one command and prints the key as `export ENTERPLACE_KEY=...`: see the [Quickstart](/getting-started/quickstart/). This tool speaks Gemini's own API, so it needs a `gemini` or `vertex` provider with a key: the free demo model does not answer it. After your first prompt, **Requests** in the console shows it with the key's name, the model and the cost.
</Aside>

## Setup

Point Gemini CLI at Enterplace and give it your Enterplace key as its Gemini API key:

```bash
export GOOGLE_GEMINI_BASE_URL=https://enterplace.example.com   # or http://127.0.0.1:8080 on this machine
export GEMINI_API_KEY=enterplace_...
gemini
```

Gemini CLI takes `http://` only for `localhost`, `127.0.0.1` and `[::1]`; any other Enterplace must be on HTTPS. With `GOOGLE_GEMINI_BASE_URL` set, Gemini CLI uses its gateway sign-in and sends the key in `x-goog-api-key`. To set the sign-in in settings instead:

```json title="~/.gemini/settings.json"
{ "security": { "auth": { "selectedType": "gemini-api-key" } } }
```

On the Enterplace side, the models Gemini CLI asks for must be on a provider of `kind: gemini` or `kind: vertex`, or be an alias whose deployments are there, and the caller's rule must allow them:

```yaml title="enterplace.policy.yaml"
version: 1
providers:
  - name: gemini
    kind: gemini
    url: https://generativelanguage.googleapis.com
    key_env: GEMINI_PROVIDER_KEY
    models: [gemini-2.5-pro, gemini-2.5-flash, gemini-2.5-flash-lite]
rules:
  - name: engineering
    principals: { team: eng }
    models: [gemini-2.5-pro, gemini-2.5-flash, gemini-2.5-flash-lite]
```

Gemini CLI picks its model with `-m` or `/model`. A model the rule does not allow is refused with `model_not_allowed`, and Gemini CLI shows the refusal with the allowed models.

## What Enterplace serves

| Route | What it does |
|---|---|
| `POST /v1beta/models/<model>:generateContent` | One answer |
| `POST /v1beta/models/<model>:streamGenerateContent?alt=sse` | Server-sent events, as Gemini CLI asks |
| `POST /v1beta/models/<model>:streamGenerateContent` | The same stream as one JSON array, as Google sends it without `alt=sse` |
| `POST /v1beta/models/<model>:countTokens` | Free: never counted against a budget |
| `POST /v1beta/models/<model>:embedContent` and `:batchEmbedContents` | Embeddings |
| `GET /v1beta/models` and `GET /v1beta/models/<model>` | Only the models the caller's rule (and key) allow |

The `/v1/models/<model>:<method>` forms work too. The key is read from `x-goog-api-key`, from `?key=`, or from `Authorization: Bearer`, exactly one of them. A key in the query is taken out before anything else sees the request: it is never forwarded, traced or written to the audit log.

## What applies

Everything a chat completions request gets:

- The rule's decision on the model in the path, aliases, kill switches, observe mode and regions.
- Guardrails on the request's text: `contents`, `systemInstruction`, tool calls and tool results (`functionCall.args`, `functionResponse.response`), and the embedding methods' `content`. A mask is written back where the text was.
- Guardrails on the answer's text, whole or streamed (`buffer_stream` or `check_stream_every`). A stream a guardrail stops ends with an error event in Google's shape.
- Budgets, rate and parallel limits, with usage read from `usageMetadata`. The output limit is `generationConfig.maxOutputTokens`. A whole `generateContent` answer can be cached; a stream and `countTokens` never are.
- A decision record with the caller's user agent (`GeminiCLI/<version>/<model> ...`), and a usage record.

The body goes to the provider as sent: a field Enterplace does not know passes through untouched. A body that names a model other than the path's is refused with `ambiguous_model`. Refusals come back in Google's error shape (`{"error": {"code": 403, "status": "PERMISSION_DENIED", ...}}`) with Enterplace's code as the reason and the decision ID in the message.

## Run it locally

This is how the setup was checked, with Gemini CLI 0.68.0 and a mock of the Gemini API on port 9701 (any server that answers `streamGenerateContent` with an event will do). With `allow_private: true` on the provider so Enterplace may reach the mock:

```bash
enterplace key new dana --team eng --keys enterplace.keys.yaml
MOCK_GEMINI_KEY=mock-key enterplace serve enterplace.policy.yaml --keys enterplace.keys.yaml --listen 127.0.0.1:9700

GOOGLE_GEMINI_BASE_URL=http://127.0.0.1:9700 GEMINI_API_KEY=enterplace_... GEMINI_CLI_TRUST_WORKSPACE=true \
  npx @google/gemini-cli -m gemini-2.5-flash -p "Say hello"
```

Gemini CLI printed the mock's answer. The audit log held one allowed decision and its usage:

```text
POST /v1beta/models/gemini-2.5-flash:streamGenerateContent  allow  rule everyone  provider gemini
  user_agent GeminiCLI-tui/0.68.0/gemini-2.5-flash (darwin; arm64; terminal)
usage  input_tokens 12  output_tokens 5  ended complete
```

With `-m gemini-1.5-pro`, which the rule does not allow, Gemini CLI showed `Refused (model_not_allowed): ...` with status 403, and nothing reached the mock.

## What Enterplace does not see

Google sign-in (not used with a key), usage statistics (`privacy.usageStatisticsEnabled`, on by default, sent to Google) and telemetry sent to an OTLP endpoint of your own do not go through the base URL. Gemini CLI's docs do not say whether its web search and URL fetch tools use it.

<Aside type="note">
Google has replaced Gemini CLI with Antigravity CLI for free-tier users. Gemini CLI with an API key, as here, still works.
</Aside>
