Kilo Code takes Enterplace as a custom provider, in the VS Code extension or in `kilo.json` for the Kilo CLI. Its requests then go to Enterplace, identified by an Enterplace key.

<Aside type="tip" title="Before you start">
You need a running Enterplace and an Enterplace key. `enterplace start` gives both in one command and prints the key as `export ENTERPLACE_KEY=...`: see the [Quickstart](/getting-started/quickstart/). No provider key yet? Put the model `enterplace-demo` in place of the model in the examples below: Enterplace answers it itself, free. After your first prompt, **Requests** in the console shows it with the key's name, the model and the cost.
</Aside>

## Setup

<Tabs>
<TabItem label="VS Code">

Open Settings (the gear), then the **Providers** tab, then **Custom provider**:

| Field | Value |
|---|---|
| Provider ID | `enterplace` |
| Display name | Enterplace |
| Provider API | OpenAI Compatible (`POST /v1/chat/completions`), OpenAI Responses (`POST /v1/responses`) or Anthropic Messages (`POST /v1/messages`) |
| Base URL | Enterplace's address with `/v1`, for example `http://127.0.0.1:8080/v1` |
| API key | The Enterplace key |
| Models | **Fetch models** lists the models the key may use from `GET /v1/models` |

</TabItem>
<TabItem label="Kilo CLI">

```json title="~/.config/kilo/kilo.json"
{
  "provider": {
    "enterplace": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Enterplace",
      "options": { "baseURL": "http://127.0.0.1:8080/v1", "apiKey": "{env:ENTERPLACE_KEY}" },
      "models": {
        "gpt-4o-mini": { "name": "gpt-4o-mini", "limit": { "context": 128000, "output": 16000 } }
      }
    }
  }
}
```

```bash
export ENTERPLACE_KEY=enterplace_...
kilo run -m enterplace/gpt-4o-mini "explain this repository"
```

Set `limit` on each model: without it Kilo assumes a context of 0 and turns off compaction. `{env:ENTERPLACE_KEY}` is read only in a trusted file (the global `~/.config/kilo`, `KILO_CONFIG` or an MDM-managed file), never from a `kilo.json` committed to a project.

</TabItem>
</Tabs>

## What Enterplace governs

- Every request to the custom provider. Its records carry the user agent `Kilo-Code/<version>`, which [Coverage](/governance/coverage/) counts as `kilo-code`.

## What Enterplace does not see

- Autocomplete, which always goes through Kilo's own gateway to Codestral, or to Mistral with a Mistral key. It is on by default.
- Requests to the built-in Kilo Code provider, if someone picks it.
- Kilo CLI telemetry, on by default. `experimental.openTelemetry = false` turns it off.

<Aside type="note">
This follows Kilo Code's documentation (custom models, OpenAI-compatible provider, CLI). The CLI setup above was run (`kilo run`, Kilo CLI 7.8.27) against a local Enterplace and a mock provider: one allowed request on `/v1/chat/completions`. The VS Code setup was not run.
</Aside>
