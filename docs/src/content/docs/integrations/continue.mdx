Continue reads its models from `config.yaml` in `~/.continue`. Use the `openai` provider with `apiBase` set to Enterplace, and its requests go to `POST /v1/chat/completions` on Enterplace.

<Aside type="tip" title="Before you start">
You need a running Enterplace and an Enterplace key. `enterplace start` gives both in one command and prints the key as `export ENTERPLACE_KEY=...`: see the [Quickstart](/getting-started/quickstart/). No provider key yet? Put the model `enterplace-demo` in place of the model in the examples below: Enterplace answers it itself, free. After your first prompt, **Requests** in the console shows it with the key's name, the model and the cost.
</Aside>

## Setup

<Steps>

1. Add a model to Continue's `config.yaml`:

    ```yaml title="~/.continue/config.yaml"
    name: Enterplace
    version: 0.0.1
    schema: v1
    models:
      - name: gpt-4o-mini via Enterplace
        provider: openai
        model: gpt-4o-mini
        apiBase: http://127.0.0.1:8080/v1
        apiKey: ${{ secrets.ENTERPLACE_KEY }}
        roles: [chat, edit, apply]
    ```

2. Put the key in `~/.continue/.env`, or in `.env` or `.continue/.env` in the workspace:

    ```bash title="~/.continue/.env"
    ENTERPLACE_KEY=enterplace_...
    ```

3. Restart the IDE.

</Steps>

| Setting | Value |
|---|---|
| `provider` | `openai` |
| `apiBase` | Enterplace's address with `/v1` |
| `apiKey` | The Enterplace key, best as `${{ secrets.ENTERPLACE_KEY }}` |
| `model` | The model as the policy names it |

## Behavior

- Continue's VS Code and JetBrains extensions do not read shell environment variables, so `export ENTERPLACE_KEY=...` is not enough there. Use a `.env` file. Only the Continue CLI reads the process environment.
- Without `apiBase`, the `openai` provider sends the key to OpenAI.
- Continue documents no `apiBase` for its `anthropic` provider, so use the `openai` provider. For Claude models, set `accept_chat: true` on the Enterplace provider. See [Translation](/routing/translation/).
- The example leaves out the `autocomplete` role. Enterplace serves chat completions; autocomplete through Enterplace is untried.

<Aside type="note">
This setup follows Continue's documentation. How Continue displays an Enterplace refusal is not documented.
</Aside>
