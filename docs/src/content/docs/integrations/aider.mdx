Aider reaches an OpenAI-compatible server through two environment variables. Point them at Gantry and its requests go to `POST /v1/chat/completions`.

## Setup

```bash
export OPENAI_API_BASE=http://127.0.0.1:8080/v1
export OPENAI_API_KEY=gantry_...
aider --model openai/gpt-4o-mini
```

| Variable | Value |
|---|---|
| `OPENAI_API_BASE` | Gantry's address with `/v1` |
| `OPENAI_API_KEY` | The Gantry key |

The `openai/` prefix tells Aider which API to use. Gantry receives the name after it, `gpt-4o-mini`, which the person's rule must allow.

## Behavior

- Aider warns about models it has no information on. The warning is Aider's own.
- Aider documents only `ANTHROPIC_API_KEY` for Anthropic, with no base URL, so use the OpenAI route. For Claude models, set `accept_chat: true` on the Gantry provider. See [Translation](/routing/translation/).

<Aside type="note">
This setup follows Aider's documentation. How Aider displays a Gantry refusal is not documented.
</Aside>
