Most teams pay for Claude Code with Claude subscriptions (Pro, Max, Team or Enterprise seats), not with Anthropic API keys. Enterplace routes those sessions as they are: Claude Code keeps its own Claude login, Enterplace sends that login to Anthropic unchanged, and a free Enterplace person token says who sent each request. Nobody creates an API key.

## The shortest path

On a Claude subscription, with a new install, start Enterplace, with no key:

```bash
enterplace start    # once, on the machine that runs Enterplace
```

Every request carries a name, and `enterplace start` hands you yours: it makes a person token for you (your user name on that machine) and prints it once, in the two lines to paste:

```bash
export ANTHROPIC_BASE_URL=http://127.0.0.1:8080
export ANTHROPIC_CUSTOM_HEADERS="x-enterplace-user: enterplace_u_..."
```

Then run `claude`. The same two keys can go in the `env` block of `~/.claude/settings.json` instead ([step 3 below](#claude-subscriptions)).

Claude Code keeps your Claude login. Leave `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN` unset. Send a prompt, and **Requests** in the console shows it under your name. No Enterplace yet? See the [Quickstart](/getting-started/quickstart/).

<Aside type="caution" title="Not in the Claude desktop app">
This works in Claude Code in a terminal and in the VS Code extension (`claudeCode.environmentVariables`). The Code tab of the Claude desktop app sets `ANTHROPIC_BASE_URL` to `https://api.anthropic.com` itself, over your shell profile and `settings.json`, so its sessions never reach Enterplace. Run `echo $ANTHROPIC_BASE_URL` inside a session to check. For the desktop app, use its [third-party inference setup](/integrations/claude-desktop/) with an Enterplace key.
</Aside>

## Three ways

Three ways to bring Claude Code under Enterplace, in order of preference:

| | Claude subscriptions through Enterplace | Watch mode | Anthropic API keys through Enterplace |
|---|---|---|---|
| Who pays Anthropic | Each person's Claude seat | Each person's Claude seat | Per request, on an API key |
| Requests go through Enterplace | Yes | No, telemetry only | Yes |
| Rules, guardrails, kill switches | Yes | No | Yes |
| Limits | Tokens and requests per person, team and day | No | Dollars, tokens and requests |
| Cost shown | API-equivalent estimate | Claude Code's estimate | What was billed |
| Setup per developer | Two `env` settings | Managed settings | Two `env` settings and a key |

## Claude subscriptions

<Steps>

1. **Turn on subscription passthrough.** `enterplace start` writes this provider, so a new install has it already. Otherwise press **Turn on Claude subscriptions** on the console's **Coding agents**, **Getting started** page (one click), or add it to the policy:

    ```yaml title="enterplace.policy.yaml"
    version: 1
    providers:
      - name: claude-subscriptions
        kind: anthropic
        url: https://api.anthropic.com
        auth: passthrough
        identity: required
        models: ["claude-*"]
    rules:
      - name: everyone
        principals: { any: true }
        models: ["*"]
    ```

    The provider holds no key. Each request carries the person's own Claude login, which Enterplace sends on unchanged and never keeps. See [Subscriptions](/governance/subscriptions/) for what Enterplace can and cannot do with that traffic.

2. **Get a person token.** It names the person to Enterplace and reaches no model on its own, so it costs nothing. `enterplace start` already made one for the person who ran it.

    <Tabs syncKey="keysource">
    <TabItem label="From the console">

    **Coding agents**, **Getting started**: the step **Point Claude Code at Enterplace** has **Make my person token** for your own. For someone else, press **Hand out a person token**, enter a name and a team and press **Make person token**. The token is shown once, in the lines below, with **Copy for your agent**: a prompt that gives the person's Claude Code these exact settings.

    </TabItem>
    <TabItem label="Single sign-on">

    ```bash
    enterplace login https://enterplace.example.com
    ```

    It writes `ANTHROPIC_BASE_URL` and `ANTHROPIC_CUSTOM_HEADERS` (with the person's own key) into the `env` block of `~/.claude/settings.json` and keeps every other key in that file, so step 3 is already done. A settings file that is not valid JSON is left as it is, with an error. It also writes `~/.config/enterplace/env` for the OpenAI SDKs and Codex, which is the shell fallback for Claude Code. See [Single sign-on](/governance/single-sign-on/).

    </TabItem>
    <TabItem label="Issued by an admin">

    ```bash
    enterplace key new maya.cohen --team payments --identity-only --url https://enterplace.example.com
    ```

    Prints a `enterplace_u_...` token once, with the settings below.

    </TabItem>
    </Tabs>

3. **Point Claude Code at Enterplace, and keep your normal Claude login.**

    Add the `env` block to `~/.claude/settings.json` (keep the file's other keys). `enterplace login` does this for you.

    ```json title="~/.claude/settings.json"
    {
      "env": {
        "ANTHROPIC_BASE_URL": "https://enterplace.example.com",
        "ANTHROPIC_CUSTOM_HEADERS": "x-enterplace-user: enterplace_u_..."
      }
    }
    ```

    Fallback: if you cannot edit that file, export the same two variables in the shell that runs Claude Code.

    ```bash
    export ANTHROPIC_BASE_URL=https://enterplace.example.com
    export ANTHROPIC_CUSTOM_HEADERS="x-enterplace-user: enterplace_u_..."
    claude
    ```

    Leave `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN` unset: with either set, Claude Code stops using the subscription. Sign in as usual with `/login` if Claude Code asks.

4. **See it arrive.** The step on **Getting started** turns done when the person's first request arrives. **Requests** shows it with the person, the model, tokens and the cost marked as an estimate.

</Steps>

### Roll it out with managed settings

Claude Code reads `env` from its [managed settings file](https://code.claude.com/docs/en/settings), which your MDM (Jamf, Intune) can place on each machine, one token per person:

```json title="managed-settings.json"
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://enterplace.example.com",
    "ANTHROPIC_CUSTOM_HEADERS": "x-enterplace-user: enterplace_u_..."
  }
}
```

- macOS: `/Library/Application Support/ClaudeCode/managed-settings.json`
- Linux and WSL: `/etc/claude-code/managed-settings.json`
- Windows: `C:\Program Files\ClaudeCode\managed-settings.json`

The Enterplace [device agent](/operations/devices/) sets the same two keys in each person's `~/.claude/settings.json`, from the key their `enterplace login` saved.

### Allow unnamed requests while you roll out

Every request is named by default (`identity: required`): a request without `x-enterplace-user` is refused with `person_needed` (403). A company that wants to point Claude Code at Enterplace first and hand out person tokens later can allow unnamed requests for a while:

| Where | How |
|---|---|
| Console | **Coding agents**, **Getting started**: turn off **Every request needs a name** under **Names**. It sets every passthrough provider at once, saved and audited like any policy edit |
| Policy | `identity: optional` on the passthrough provider |

An unnamed request is recorded as the person `unknown` (team `unknown`), told apart by Claude Code's session ID, and the console warns while unnamed requests are allowed. A kill switch on the person `unknown` stops every unnamed request. Turn the requirement back on once everyone has a token.

### What Claude Code sends

| Header | What Enterplace does |
|---|---|
| `Authorization: Bearer sk-ant-oat...` (the subscription login) | Taken off the request before any check, sent to the passthrough provider unchanged, and to nothing else: no guardrail webhook, plugin, trace, log or record sees it. Never stored, hashed into a record or cached |
| `x-enterplace-user` | Names the person and team. Removed before the request is forwarded |
| `anthropic-beta`, `anthropic-version`, `x-app`, `X-Claude-Code-Session-Id`, user agent | Passed unchanged. The session ID groups the requests into sessions |

A login is never swapped for a key of Enterplace's, and an Enterplace key never goes to a passthrough provider:

| Request | Answer |
|---|---|
| A login for a model only a keyed provider serves | 403 `login_not_accepted` |
| An Enterplace key (or `ANTHROPIC_API_KEY`) for a model only a passthrough provider serves | 403 `login_needed` |
| A person token as the only credential | 403 `person_token_only` |
| A login and a different Enterplace key at once | 400 `ambiguous_key` |
| No `x-enterplace-user` on a provider with `identity: required` | 403 `person_needed` |

When a passthrough provider and a keyed provider list the same model, a request with a login goes to the passthrough one and a request with an Enterplace key to the keyed one.

<Aside type="caution">
Check that routing your plan's traffic through your own gateway fits Anthropic's terms for your plan (consumer terms for Pro and Max, your commercial agreement for Team and Enterprise). Enterplace does not change what Claude Code sends Anthropic; it reads it on the way.
</Aside>

## Watch mode

To see usage without routing anything, send Claude Code's own telemetry to Enterplace instead. It records who used Claude Code, the models, tokens and estimated cost, and enforces nothing. See [Claude Team and Enterprise](/integrations/claude-team/).

## Anthropic API keys

When Claude Code runs on API keys, Enterplace holds the provider key and each developer gets an Enterplace key in its place.

<Steps>

1. **Allow both of Claude Code's models.** Claude Code uses a main model and a smaller one for background work. A provider must serve both, and the person's rule must allow both.

    ```yaml title="enterplace.policy.yaml"
    version: 1
    providers:
      - name: anthropic
        kind: anthropic
        url: https://api.anthropic.com
        key_env: ANTHROPIC_PROVIDER_KEY
        models: [claude-sonnet-5-5, claude-haiku-5-5]
    rules:
      - name: payments-team
        principals: { team: payments }
        models: [claude-sonnet-5-5, claude-haiku-5-5]
    ```

    Keep the provider key in a variable of its own. Claude Code reads `ANTHROPIC_API_KEY` for its own key, which must be the Enterplace key.

2. **Get an Enterplace key**: **Issue a key** on the console's **Users** page (or **Coding agents**, **Getting started**, **API keys, any coding agent**), `enterplace login` on a gateway without subscription passthrough, or `enterplace key new maya.cohen --team payments --url https://enterplace.example.com`. See [Keys and identity](/governance/keys/).

3. **Point Claude Code at Enterplace.**

    ```json title="~/.claude/settings.json"
    {
      "env": {
        "ANTHROPIC_BASE_URL": "http://127.0.0.1:8080",
        "ANTHROPIC_API_KEY": "enterplace_...",
        "ANTHROPIC_MODEL": "claude-sonnet-5-5",
        "ANTHROPIC_SMALL_FAST_MODEL": "claude-haiku-5-5"
      }
    }
    ```

    Fallback, in the shell that runs Claude Code:

    ```bash
    export ANTHROPIC_BASE_URL=http://127.0.0.1:8080
    export ANTHROPIC_API_KEY=enterplace_...
    export ANTHROPIC_MODEL=claude-sonnet-5-5
    export ANTHROPIC_SMALL_FAST_MODEL=claude-haiku-5-5
    claude
    ```

</Steps>

Each request now has a record in the audit log, background calls included.

## Model picker

Set `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` and Claude Code asks Enterplace for its model list at startup (`GET /v1/models`). The `/model` picker then shows the models the person's rule allows on providers that take messages requests, each described as `Allowed by Enterplace rule "<rule>"`. Each list request is recorded.

Models on chat providers without `accept_messages` are left out: Claude Code would offer them, and every request would be refused with `wrong_route`.

## Other providers

The same four variables reach Claude on other clouds, and non-Claude models through translation. Only the provider entry changes.

<Tabs>
<TabItem label="Amazon Bedrock">

```yaml
providers:
  - name: bedrock
    kind: bedrock
    region: us-east-1
    models: [claude-sonnet-5-5, claude-haiku-5-5]
    model_ids:
      claude-sonnet-5-5: us.anthropic.claude-sonnet-5-5-v1:0
      claude-haiku-5-5: us.anthropic.claude-haiku-5-5-v1:0
```

Enterplace signs with AWS credentials from its own environment. See [Amazon Bedrock](/providers/bedrock/).

</TabItem>
<TabItem label="Vertex AI">

```yaml
providers:
  - name: claude-vertex
    kind: vertex_anthropic
    url: https://us-east5-aiplatform.googleapis.com/v1/projects/my-project/locations/us-east5/publishers/anthropic
    key_env: VERTEX_ACCESS_TOKEN
    models: [claude-sonnet-4-6, claude-haiku-4-5]
```

Vertex AI names models without Anthropic's date suffix. When Claude Code sends another name, map it with an [alias](/routing/aliases/). See [Vertex AI](/providers/vertex/).

</TabItem>
<TabItem label="GPT, Gemini or a local model">

```yaml
providers:
  - name: openai
    kind: openai
    url: https://api.openai.com
    key_env: OPENAI_PROVIDER_KEY
    models: [gpt-5, gpt-5-mini]
    accept_messages: true
```

```bash
export ANTHROPIC_MODEL=gpt-5
export ANTHROPIC_SMALL_FAST_MODEL=gpt-5-mini
```

`accept_messages: true` works on `openai`, `azure`, `gemini` and `vertex` providers. Requests and answers, streamed or whole and tool calls included, are translated to chat completions and back. A field with no chat equivalent is refused with `untranslatable`, naming the field. Claude Code warns that it does not know the model and assumes a context window; set one in its model configuration. See [Translation](/routing/translation/).

</TabItem>
</Tabs>

The full runbook for both clouds, with Claude Code's own Bedrock and Vertex AI modes, is [Claude Code on Bedrock and Vertex AI](/integrations/claude-code-on-bedrock-and-vertex/).

## What Enterplace does with its requests

| Request | Behavior |
|---|---|
| `POST /v1/messages`, `POST /v1/messages/count_tokens` | Checked, recorded and forwarded as the original bytes to `anthropic` providers, streams, tool use and background calls included. Rewritten for `bedrock` and `vertex_anthropic`, translated for a provider with `accept_messages`. |
| `anthropic-*` and `x-claude-code-*` headers | Passed unchanged, including `anthropic-version` and `anthropic-beta`. A provider with `accept_messages` gets no `anthropic-*` header. |
| `?beta=true` or `?beta=false` | Forwarded, once. Any other query parameter or value, or `beta` twice, is refused by name with `unknown_query`. The refusal never repeats the value. |
| `HEAD /api/hello` | Claude Code's startup probe. Answered with 200 and not recorded, because it reaches no provider. Any other method on `/api/hello` is refused with `unknown_route` and recorded. |

## Refusals

On the messages routes a refusal uses Anthropic's error shape, so Claude Code shows Enterplace's message:

```text
API Error: 403 Refused (model_not_allowed): team "interns" may not use model "claude-sonnet-5-5" under rule "everyone-else". This rule allows no models. Ask an Enterplace admin to change the policy if you need this one. Decision 01M7969SCWCX2P3AR3KSXZJ7VS.
```

Claude Code labels any 403 "Failed to authenticate". The message after that label is Enterplace's.

- A model no provider serves is refused with 403 `unknown_model`, not 404. Claude Code replaces the text of a 404 with its own and resends a 400 several times; it shows a 403 as it is and sends it once. The message names the console's **New and pending** page, where an admin serves the model with **Add a provider**. See [New callers](/governance/new-callers/).
- Every refusal sets `x-should-retry: false`, except `busy`, `rate_limited` and the `upstream_*` codes, which set `x-should-retry: true`. Claude Code resends those on its own. `rate_limited` also sets `Retry-After`.
- A guardrail refusal says where the finding is, in words and as a JSON pointer: `in message 3 (/messages/2/content/1/text)`. That is the third message of the conversation Claude Code sent, which may be an earlier turn, a file it read or a tool result. Remove the secret from that turn or file and send again. A new session starts without the earlier turns.

See [Refusal codes](/reference/refusal-codes/) for every code.

## Permission modes and the browser

An admin can block `--dangerously-skip-permissions`, auto mode and Claude in Chrome for the organization, a team or a person with the policy's `coding_agents:`. The device agent writes them into Claude Code's managed settings; with the browser blocked, a request sent while Chrome is on is refused with `browser_not_allowed`. See [Coding agent controls](/governance/coding-agent-controls/).

## Budgets

On Claude subscriptions, dollar budgets do not count by default: see [Subscriptions](/governance/subscriptions/), and limit tokens and requests instead. On API keys, a budget reserves the most a request could cost before it is sent: its body at the input price plus its `max_tokens` at the output price. Claude Code asks for a large `max_tokens` on every request (32,000 or more, depending on the model), so each request reserves far more than it usually spends. One measurement put the reserve at $1.34 per Claude Code request.

The difference is given back when the answer ends. While it is held, a small budget refuses requests that would have fitted, with `budget_exceeded` and "could cost up to ...". When budget is left, the refusal says a request with a smaller output token limit could fit.

- **Lower what each request asks for.** Run `export CLAUDE_CODE_MAX_OUTPUT_TOKENS=8000` before `claude`. Claude Code sends that `max_tokens`, and each request reserves less.
- **Size the budget for the reserve, not the average.** A team running several sessions at once holds one reserve per request in flight.

See [Budgets and rate limits](/governance/budgets-and-rate-limits/).

### Budget in the status line

Claude Code's [status line](https://code.claude.com/docs/en/statusline) runs a command and shows what it prints. `enterplace budget status --short` prints what your own key has left, so a small script puts it under the prompt:

```sh title="~/.claude/enterplace-statusline.sh"
#!/bin/sh
input=$(cat)
model=$(printf '%s' "$input" | jq -r '.model.display_name // "Claude"' 2>/dev/null)
budget=$(enterplace budget status --short 2>/dev/null) || budget="budget unknown"
printf '[%s] Enterplace: %s\n' "${model:-Claude}" "$budget"
```

```json title="~/.claude/settings.json"
{
  "statusLine": {
    "type": "command",
    "command": "~/.claude/enterplace-statusline.sh",
    "refreshInterval": 60
  }
}
```

```text
[Sonnet] Enterplace: $412.37 left (resets 2026-12-01 00:00 UTC)
```

Make the script executable (`chmod +x`). It needs `jq` and the `enterplace` binary on your PATH, and your key in `ENTERPLACE_KEY` (or a `enterplace login`) with the gateway in `ENTERPLACE_URL`. `statusLine`, `type`, `command` and `refreshInterval` are Claude Code's own settings; `refreshInterval` re-runs the command every that many seconds, so the figure stays current while a session is idle. The script is in the repository at `examples/claude-code/enterplace-statusline.sh`. The call it makes (`GET /v1/enterplace/me`) costs nothing and writes no audit record.
