Open WebUI connects to Enterplace as an OpenAI-compatible API. An admin connection is called from the Open WebUI server with one key; a direct connection is called from each person's browser with their own key.

<Aside type="tip" title="Before you start">
You need a running Enterplace and a Enterplace key. `enterplace start` gives both in one command and prints the key as `export ENTERPLACE_KEY=...`: see the [Quickstart](/getting-started/quickstart/). No provider key yet? Put the model `enterplace-demo` in place of the model in the examples below: Enterplace answers it itself, free. After your first prompt, **Requests** in the console shows it with the key's name, the model and the cost.
</Aside>

## Setup

<Tabs>
<TabItem label="Admin connection">

Open **Settings**, **Admin**, **Connections**, and under **Manage OpenAI API Connections** choose **Add Connection**:

| Field | Value |
|---|---|
| URL | Enterplace's address with `/v1`, for example `http://enterplace:8080/v1` |
| API Key | A Enterplace key for Open WebUI |
| Provider (Advanced) | Default |

**Verify Connection** calls `GET /v1/models`. The same can be set with `OPENAI_API_BASE_URL` and `OPENAI_API_KEY` on first start; after that, the values saved in Open WebUI's database win.

</TabItem>
<TabItem label="Direct connections">

An admin turns on **Direct Connections** under **Settings**, **Admin**, **Connections** (or `ENABLE_DIRECT_CONNECTIONS=true`). Each person then adds Enterplace under **User Settings**, **Connections**, with Enterplace's `/v1` address and their own Enterplace key. The key stays in their browser.

</TabItem>
</Tabs>

Requests go to `POST /v1/chat/completions`.

## What Enterplace governs

- Every chat request. With an admin connection, everyone shares one key, so Enterplace records and budgets Open WebUI as one identity.
- With direct connections, each request carries the person's own key.

## What Enterplace does not see

- Background steps such as titles and tags, which the Open WebUI server runs with its own connections even when the chat itself is a direct connection.
- Features configured with other providers: embeddings for documents, web search, image generation.

<Aside type="caution">
Direct connections are called from the browser, so they need CORS. Allow Open WebUI's origin in the policy, and Enterplace answers the preflight itself:

```yaml
cors:
  allowed_origins: [https://chat.example.com]
```

Use the address people open Open WebUI at. Without `cors:` (off by default) direct connections fail in the browser; the admin connection needs none. See [Browser pages (CORS)](/governance/access-control/#browser-pages-cors).
</Aside>
