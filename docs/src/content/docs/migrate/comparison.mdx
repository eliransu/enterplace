This page compares Enterplace 0.1.0 with the open source editions of LiteLLM (v1.109.1, which its release notes call the current stable release) and Bifrost (v2.5.1, released 2026-11-10). The LiteLLM and Bifrost cells were re-read from their public documentation on 2026-11-15; a claim those pages did not confirm was removed. Figures marked "review" come from a hands-on review run in Docker against a mock provider on 2026-11-12, on one machine, and are not benchmarks.

Enterplace is younger than both and serves fewer providers. Where it leads is governance: a verified record of every request in the open source edition, a policy that fails on any unknown key, and nothing dropped from a request silently.

## Side by side

| Identity per request | Enterplace key per person or workload, or one `enterplace login` issues after SSO | Virtual key, scoped to key, user, team, team member, customer, organization | Virtual key owned by a team or a customer |

## What LiteLLM does better

- **Providers.** About 141 providers against Enterplace's 15 native kinds and its 120 presets, and `/v1/messages` accepted for every one of them.
- **A shared cache.** One cache for every instance through Redis, semantic matching included. Enterplace's cache is per replica, since it never writes answers to its database.
- **Routing breadth.** Usage-based, priority and custom strategies on top of the ones Enterplace has, and a retry policy per kind of error.
- **Time to a first request (review).** 8 seconds from `docker run` with a five-line config and no database. Enterplace's image needs nothing first either: `docker run` with no config and no provider key writes its policy, serves the demo model and answers a first governed request within a second.

## What Bifrost does better

- **Speed of forwarding with features on (review).** About 1 ms added at p50 in the review's Docker setup, with routing, budgets and logging.
- **More providers behind the Responses API.** `/v1/responses` on 31 of its 35 providers.
- **Cache and logs on external stores.** Semantic caching on Weaviate, Qdrant or Pinecone, and a ClickHouse log store.
- **MCP agent and code modes**, beyond relaying tools.

## What Enterplace does better

- **A record before every request, in the open source edition.** Every request, allowed or refused, gets a hash-chained audit record before it is forwarded, and `enterplace audit verify` checks the chain. Both others keep an audit log only in their enterprise editions, and it covers admin changes, not requests.
- **Fail closed on the record (review).** If the record cannot be written, the request is refused. In the review, LiteLLM kept forwarding while its per-request spend rows went missing for 6,498 load-test requests.
- **Unknown config is an error.** `enterplace check` names the file, line and nearest known word for every mistake. Both others accepted misspelled keys silently in the review.
- **Nothing dropped silently.** The body is forwarded byte for byte, and an unknown query parameter is refused by name. Translated to another API, a field that has no equivalent is refused with the fix; the few that cannot change the answer (Codex's `client_metadata`, `store`, cache hints) are dropped and listed in the request's record. LiteLLM's docs say Claude Code and Codex traffic drops unsupported parameters by default; Bifrost's say many providers drop them.
- **Governance features in open source.** Guardrails, SSO without a seat limit, budgets for any period, and a kill switch, where Bifrost keeps guardrails, SSO and clustering in its enterprise edition and LiteLLM caps free SSO at 5 users.
- **Small footprint (review).** About 3.4 MiB of memory idle in an image built `FROM scratch`, running as a non-root user.
- **Refusals a person can act on.** Each names the cause, the fix and a decision ID, in the error shape the client already shows.
