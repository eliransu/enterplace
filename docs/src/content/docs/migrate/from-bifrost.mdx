This page maps each Bifrost concept to its Enterplace equivalent and walks through moving a gateway over. You end with a `enterplace.policy.yaml` that passes `enterplace check`, one Enterplace key per virtual key, and clients pointed at Enterplace.

Enterplace has no importer for Bifrost. You write the policy by hand from your `config.json`, which for most setups is one provider block and one rule per team.

## Concepts

| Bifrost | Enterplace | Notes |
|---|---|---|
| `config.json`, or configuration kept through the web UI | The [policy file](/governance/policy/), one YAML file checked by `enterplace check`. With `store: { policy_from: store }` it is kept in Postgres as versions and [edited in the console](/operations/console-editing/) | An unknown key is an error with its line |
| Provider with one or more keys | A provider with `key_env`, or a [key pool](/routing/key-pools/) under `keys:` | |
| Virtual key (`sk-bf-*`) | A [Enterplace key](/governance/keys/) (`enterplace_...`), stored as a hash, shown once | Each key has a name and a team |
| Customer, above teams | An [organization](/governance/policy/#organizations) | Enterplace's "end customer" is something else: a customer of your own product, named per request |
| Team | The key's team, and [teams](/governance/teams/) in the policy | Rules match on `principals: { team: ... }` |
| Budgets and rate limits | `budget`, `rate` (`rpm`, `tpm`) and `parallel` on a rule, on a key, and per scope in the [`limits:` list](/governance/budgets-and-rate-limits/#scopes-and-the-limits-list) | A budget reserves a request's worst case before it is sent |
| Routing between providers, weights | An [alias](/routing/aliases/) with weighted `deployments` and a [`balance`](/routing/strategies/) | Rules decide on the alias |
| Fallbacks | A provider's `fallback`, or an alias's deployments | Set in the policy, not in the request |
| Governance plugin | Built in. Every request is decided by the policy | |
| Logging plugin, request log | The hash-chained [audit log](/governance/audit-log/) and the [request log](/operations/request-log/) | No prompt or answer text unless a rule captures it |
| Telemetry, OpenTelemetry and other observability plugins | Prometheus [metrics](/operations/observability/), traces, and [observability integrations](/operations/observability-integrations/) | |
| Semantic cache plugin | [`cache:` on a rule](/routing/caching/), exact or semantic | Kept per replica |
| Custom plugins | No in-process plugins. Outside services over HTTP: a [guardrail webhook](/governance/guardrail-webhooks/), an [events plugin](/governance/plugin-events/) or a [transform](/governance/transforms/) | |
| MCP gateway | The [MCP gateway](/governance/mcp-gateway/) | Tools, prompts and resources by rule |
| Drop-in SDK paths (`/openai`, `/anthropic`) | OpenAI format at `/v1`, Anthropic format at the root | See [OpenAI and Anthropic SDKs](/integrations/sdks/) |
| Web UI | The [console](/operations/console/) | |

## Field by field

| Bifrost | Enterplace |
|---|---|
| Virtual key (`sk-bf-*`), sent as `x-bf-vk` or `Authorization: Bearer` | An Enterplace key, sent as `Authorization: Bearer` or `x-api-key` |
| `client.enforce_auth_on_inference` | Always on. A request without a known Enterplace key is refused before its body is read |
| Virtual key `is_active: false` | Revoke the key in the console, with the [admin API](/reference/admin-api/), or by removing its line from `enterplace.keys.yaml` |
| Virtual key `expires_at` | `enterplace key new --expires <date>` |
| `provider_configs[].allowed_models` | The rule's `models:` list, narrowed per key with `--models` |
| `allow_all_providers: true` | `models: ["*"]` on the rule |
| Budget on a virtual key | `enterplace key new --budget <usd>/<period>`, for example `100/month`, `20/week` or `5/6h` |
| Budget on a team or a customer | `budget:` on a `{ team: ... }` rule, or a `{ team: ... }` or `{ org: ... }` entry in `limits:`. It counts the whole team or organization |
| Budget `reset_duration` (`1h`, `1d`, `1w`, `1M`, `1Y`) | The budget's `per`: `hour`, `day`, `week`, `month`, `year`, or a count such as `6h` or `3mo`. See [Periods](/governance/budgets-and-rate-limits/#periods) |
| Several budgets on one key or team | `budget:` takes a list, one per period |
| `request_max_limit` with `request_reset_duration: 1m` | `rate: { rpm: ... }` on a rule (each person), or `rpm` on a key |
| `token_max_limit` with `token_reset_duration: 1m` | `rate: { tpm: ... }` on a rule (each person), or `--tpm` on a key |
| `providers.<name>.keys[].value: env.NAME` | `key_env: NAME` on the provider |
| Several `keys[]` for one provider, with `weight` | A [key pool](/routing/key-pools/): `keys: [{ key_env: A }, { key_env: B, weight: 2 }]` |
| `keys[].models` | The provider's `models:` list. A model name belongs to one provider; a second provider lists it under an alias |
| `provider_configs[].weight` across providers | An alias with `deployments` and `weight` |
| `network_config` retries | The provider's `retries` (0 to 5) |
| `fallbacks` in the request body | The provider's `fallback`, or an alias's deployments. A fallback may speak the other API, translated. See [Retries and fallbacks](/routing/retries-and-fallbacks/) |
| `provider/model` names such as `openai/gpt-4o-mini` | Bare model names. To keep clients that send the prefixed name, add an alias with that name |
| `vault.<path>` key references | A [secret manager reference](/operations/secret-managers/) as the variable's value, such as `vault://secret/data/enterplace#openai` |
| `semantic_cache` plugin | `cache: { ttl_seconds: N, semantic: { model: ..., threshold: ... } }` on a rule |
| `/metrics` | `enterplace serve --metrics <address>` serves Prometheus metrics on an address of its own |
| `/api/governance/virtual-keys` | The admin API at `/admin/keys`, or `enterplace key new` |
| Default port `8080`, `POST /v1/chat/completions` | The same: Enterplace listens on `127.0.0.1:8080` by default and serves `/v1/chat/completions` |

## Example

This Bifrost `config.json` serves two models through one virtual key with a monthly budget and a rate limit:

```json title="config.json"
{
  "providers": {
    "openai": {
      "keys": [
        { "name": "openai-primary", "value": "env.OPENAI_API_KEY", "models": ["gpt-4o-mini"], "weight": 1.0 }
      ]
    },
    "anthropic": {
      "keys": [
        { "name": "anthropic-primary", "value": "env.ANTHROPIC_API_KEY", "models": ["claude-sonnet-4-5"], "weight": 1.0 }
      ]
    }
  },
  "governance": {
    "virtual_keys": [
      {
        "id": "vk-eng",
        "name": "Engineering",
        "value": "sk-bf-*",
        "is_active": true,
        "provider_configs": [
          { "provider": "openai", "weight": 1.0, "allowed_models": ["gpt-4o-mini"], "key_ids": ["openai-primary"] },
          { "provider": "anthropic", "weight": 1.0, "allowed_models": ["claude-sonnet-4-5"], "key_ids": ["anthropic-primary"] }
        ],
        "rate_limit_id": "rl-eng"
      }
    ],
    "budgets": [
      { "id": "budget-eng", "virtual_key_id": "vk-eng", "max_limit": 100.00, "reset_duration": "1M" }
    ],
    "rate_limits": [
      { "id": "rl-eng", "token_max_limit": 50000, "token_reset_duration": "1m", "request_max_limit": 100, "request_reset_duration": "1m" }
    ]
  }
}
```

The Enterplace policy that does the same:

```yaml title="enterplace.policy.yaml"
version: 1
providers:
  - name: openai
    kind: openai
    url: https://api.openai.com
    key_env: OPENAI_PROVIDER_KEY
    models: [gpt-4o-mini]
    retries: 2
  - name: anthropic
    kind: anthropic
    url: https://api.anthropic.com
    key_env: ANTHROPIC_PROVIDER_KEY
    models: [claude-sonnet-4-5]
    retries: 2
aliases:
  # Clients that still send Bifrost's provider/model names keep working.
  - name: openai/gpt-4o-mini
    deployments:
      - { provider: openai, model: gpt-4o-mini }
  - name: anthropic/claude-sonnet-4-5
    deployments:
      - { provider: anthropic, model: claude-sonnet-4-5 }
rules:
  - name: team-eng
    principals: { team: eng }
    models: [gpt-4o-mini, claude-sonnet-4-5, openai/gpt-4o-mini, anthropic/claude-sonnet-4-5]
    rate: { rpm: 100, tpm: 50000 }
  - name: everyone-else
    principals: { any: true }
    models: []
```

The virtual key's budget moves to the key itself:

```bash
enterplace key new engineering --team eng --budget 100/month
```

The rule's `rate` counts each person, so with one key per person it limits each key as Bifrost's virtual key limit did.

<Aside type="tip">
Give provider keys variable names of their own, such as `ANTHROPIC_PROVIDER_KEY`. Claude Code reads `ANTHROPIC_API_KEY` for its own key, which through Enterplace is an Enterplace key.
</Aside>

## Migrate step by step

<Steps>

1. List what your Bifrost gateway holds: the `providers` block of `config.json`, and every virtual key, team, budget and rate limit (from `config.json` or `GET /api/governance/virtual-keys`, `/teams` and `/customers`).

2. Write one Enterplace provider per Bifrost provider. Set `key_env` to the variable that holds its key, and list the models it serves under `models`.

3. Write one rule per team, with the models its virtual keys allow. Put a team budget on the rule, and a per-minute `rate` if the team has one. End with a `{ any: true }` rule that allows `[]`, so a caller no rule names gets a clear refusal.

4. Check the policy.

   ```bash
   enterplace check enterplace.policy.yaml
   ```

5. Issue one Enterplace key per virtual key, in the folder that holds the policy. Carry over the budget, expiry and models of each.

   ```bash
   enterplace key new engineering --team eng --budget 100/month --expires 2027-01-01 --models gpt-4o-mini
   ```

   Bifrost's key values cannot be reused. Send each printed key to its owner through your secret manager, or let developers get their own with `enterplace login`.

6. Start Enterplace with the provider keys in its environment.

   ```bash
   OPENAI_PROVIDER_KEY=sk-... ANTHROPIC_PROVIDER_KEY=sk-ant-... enterplace serve enterplace.policy.yaml
   ```

7. Point each client at Enterplace, with the Enterplace key in place of the virtual key. A client on `http://<host>:8080/v1` keeps that shape. An OpenAI SDK pointed at Bifrost's `/openai` path takes `http://<host>:8080/v1`, and an Anthropic SDK pointed at `/anthropic` takes `http://<host>:8080`. Replace an `x-bf-vk` header with `Authorization: Bearer enterplace_...`.

8. Send a test request per team, then read the records with `enterplace audit verify enterplace-audit.jsonl` and the console. Turn the Bifrost gateway off when traffic has moved.

</Steps>

## What differs

- **No importer.** `enterplace import` reads LiteLLM configs only. A Bifrost `config.json` is translated by hand, as above.
- **Rules, not keys, hold the policy.** A Bifrost virtual key carries its providers, models, budget and limits. An Enterplace key carries a name and a team, the first matching rule decides, and a key can only narrow its rule.
- **A record before every request.** Each request, allowed or refused, gets a hash-chained [audit record](/governance/audit-log/) before it is forwarded, and a request that cannot be recorded is refused.
- **No prompt text by default.** The audit log and the request log hold no prompt or answer text. A rule can [capture bodies](/operations/request-log/#bodies), redacted, for named viewers and a set number of days.
- **Budgets reserve.** A request under a budget reserves the most it could cost before it is sent and gives the rest back when the answer ends. See [how a budget is counted](/governance/budgets-and-rate-limits/#how-a-budget-is-counted).
- **Keys cannot be read back.** Enterplace stores a key's hash and shows the key once. Bifrost's key values cannot be reused either way: every key is issued again.

## What has no equivalent

| Bifrost | In Enterplace |
|---|---|
| `fallbacks` in the request body | Enterplace does not read it. On an `openai` provider it is forwarded with the rest of the body, so remove it from requests. Fallbacks are set in the policy |
| Rate limits over a period other than a minute | `rpm` and `tpm` count any 60 seconds. For a longer period, use a budget in dollars |
| Plugins that run inside the gateway | None. An outside service is called over HTTP: a guardrail webhook, an events plugin or a transform |
| Request and answer content in every log row | Off unless a rule captures bodies |
