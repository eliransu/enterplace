Gantry records the tokens and cost of every answer in a usage record. Prices for most models are built in; `prices:` in the policy sets or overrides any of them.

## How cost is recorded

When an answer ends, Gantry writes a usage record with the status, the tokens the provider reported, and the cost in US dollars. The record's `price_source` says where the price came from. Budgets, the console's Spend page and the dollars metric all read these records.

A model with no price still gets usage records, with the cost left unknown. A rule with a budget cannot reach it: `gantry check` refuses the file.

Answers without usage:

| Case | Charged | `usage` in the record |
|---|---|---|
| No usage reported (an OpenAI chat stream without `stream_options.include_usage`, an answer without `usage`, a stream that ended without its last event), under a budget | The whole reservation | `"not_reported"` |
| Same, without a budget, on a stream the provider finished | An estimate: one output token per byte of streamed text plus one per event, the prompt at one token per three bytes | `"estimated"` |
| Caller closed the stream before its final usage, or a whole answer cut off | The larger of what was reported and the reservation | `"partial"` |

Send `stream_options: {"include_usage": true}` on OpenAI streams to be charged exactly what the provider reports. Gantry never adds it, because it never rewrites a request.

## Where prices come from

A model's price comes from the first of these that has it:

1. The policy's `prices:`, by exact model name.
2. Gantry's own table: `gpt-4o-mini`, `gpt-4o`, `claude-sonnet-5-5`, `claude-haiku-5-5`, checked against each provider's price list.
3. A table of several thousand models generated by `scripts/prices.py` from LiteLLM's model price map (MIT licensed, attribution in `crates/gantry-core/data/LICENSE-litellm-prices`), at a pinned commit.

The LiteLLM table carries input, output, cache read and write, the 1 hour cache write, per image, `max_output`, `max_context`, one long context tier, audio token prices and batch prices where the map has them. A model listed there only under a provider prefix (`vertex_ai/...`) is also found by its bare name. Audio priced by the second is not in it.

## gantry prices

`gantry prices <model> [--policy <file>]` prints the price Gantry charges and where it came from.

```bash
gantry prices gemini-2.5-pro
```

```text
gemini-2.5-pro: from the LiteLLM price map (MIT), read 2026-11-13 from https://raw.githubusercontent.com/BerriAI/litellm/28540cecc0e65b9e7252689cc42d0e2d9fd187f5/model_prices_and_context_window.json.
US dollars per million tokens: input 1.25, output 10, cache read 0.125, cache write 1.25, cache write 1h 1.25.
Above 200000 prompt tokens: input 2.5, output 15.
Most output tokens in one answer: 65536. Context window: 1048576.
```

For a model with no price it exits with an error and prints the lines to add:

```text
error: no price is known for model "nope-model": its usage is recorded with cost unknown, and a budget cannot reach it. Add it under prices: in the policy, for example
prices:
  nope-model: { input: 3, output: 15 }
```

Pass `--policy` to include the policy's own `prices:`.

## Set your own prices

```yaml
prices:
  my-local-model: { input: 0, output: 0 }
  dall-e-3: { input: 0, output: 0, per_image: 0.04 }
  gpt-4o:
    input: 2.5
    output: 10
    cache_read: 1.25
    long_context: { above_prompt_tokens: 200000, price: { input: 5, output: 15 } }
```

Prices are US dollars per million tokens, 0 or more. Prices change without a restart.

| Field | Type | Default | Description |
|---|---|---|---|
| `input` | number | required | Per million prompt tokens. |
| `output` | number | required | Per million output tokens. |
| `cache_read` | number | `input` | Per million prompt tokens read from the provider's cache. |
| `cache_write` | number | `input` | Per million prompt tokens written to the cache. |
| `cache_write_1h` | number | `cache_write` | Per million tokens written to Anthropic's 1 hour cache. |
| `long_context` | map | none | `{ above_prompt_tokens: N, price: { ... } }`. A request whose whole prompt is longer than N tokens pays these prices for all of its tokens. |
| `max_output` | integer | from the tables | The most output tokens the model writes in one answer. A budget reserves this many for a request that sets no `max_tokens`. |
| `max_context` | integer | from the tables | The most tokens of context the model reads in one request. A budget reserves this many input tokens for a Responses request that names stored context. |
| `per_image` | number | none | US dollars per image, for an image model billed by the image. |
| `input_audio`, `output_audio`, `cache_read_audio` | number | `input`, `output`, `cache_read` | Per million audio tokens: prompt audio, generated audio, cached prompt audio. A realtime session's usage events split tokens by modality, and each part is charged its own price. Set them for a realtime model: audio usually costs several times text. |
| `batch_input`, `batch_output`, `batch_cache_read` | number | half the price | Per million tokens for a batch line. With `batch_input` and `batch_output` set, a batch line pays them (and other parts in the same proportion); without them, half the model's price, as OpenAI, Anthropic, Bedrock and Vertex AI bill batches. |

## How prices drive budgets

A budget reserves the most a request could cost before it is sent, then replaces the reservation with the real cost when the answer ends. See [Budgets and rate limits](/governance/budgets-and-rate-limits/).

- **No token limit.** A request that sets none of `max_tokens`, `max_completion_tokens` or `max_output_tokens` reserves the model's `max_output`. Without one, it is refused with `max_tokens_needed` (400). Built-in values: 16384 for `gpt-4o-mini` and `gpt-4o`, 64000 for `claude-sonnet-5-5` and `claude-haiku-5-5`.
- **Stored context.** A Responses request that names `previous_response_id`, `conversation` or `prompt` is refused under a budget with `stored_context` (400), unless the model has `max_context`.
- **Images.** An images request reserves `n` (default 1) times `per_image` and is charged for each image in the answer. An image or speech model priced by the token needs `max_output` instead, and reserves `n` times it. Without either, it is refused with `max_tokens_needed`.

<Aside type="caution">
Gantry trusts `max_context` as given. It must cover the model's whole context window, or a request can be charged more than it reserved and pass the budget by the difference. The usage record shows both, and Gantry logs a line naming the model.
</Aside>

## Errors from gantry check

```text
gantry.policy.yaml:9: The price of model "o3" has a negative or non-numeric value. Give every price as US dollars per million tokens, 0 or more.
gantry.policy.yaml:23: rule "everyone-else" has a budget in dollars, and model "my-model" has no price, so its spend could not be counted. Add its price in US dollars per million tokens under prices:, for example
```
