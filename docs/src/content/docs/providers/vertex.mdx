Gantry reaches two model families on Vertex AI. `kind: vertex_anthropic` serves Claude through the messages route. `kind: vertex` serves Gemini through the chat completions route, translated.

## Setup

<Tabs>
<TabItem label="Claude">

```yaml title="gantry.policy.yaml"
version: 1
providers:
  - name: claude-vertex
    kind: vertex_anthropic
    url: https://us-east5-aiplatform.googleapis.com/v1/projects/my-project/locations/us-east5/publishers/anthropic
    models: [claude-sonnet-4-6, claude-haiku-4-5]
rules:
  - name: everyone
    principals: { any: true }
    models: [claude-sonnet-4-6, claude-haiku-4-5]
```

The `url` must end in `/publishers/anthropic`.

</TabItem>
<TabItem label="Gemini">

```yaml title="gantry.policy.yaml"
version: 1
providers:
  - name: vertex
    kind: vertex
    url: https://us-central1-aiplatform.googleapis.com/v1/projects/my-project/locations/us-central1/publishers/google
    models: [gemini-2.5-pro]
rules:
  - name: everyone
    principals: { any: true }
    models: [gemini-2.5-pro]
```

The `url` must end in `/publishers/google`.

</TabItem>
</Tabs>

## Credentials

Without `key_env`, Gantry signs in to Google Cloud itself, in the order of Application Default Credentials, and the first source that answers is used:

| Order | Source | Set up by |
|---|---|---|
| 1 | The file `GOOGLE_APPLICATION_CREDENTIALS` names: a service account key, or a gcloud user sign-in | You |
| 2 | `~/.config/gcloud/application_default_credentials.json` (under `CLOUDSDK_CONFIG` when set) | `gcloud auth application-default login` |
| 3 | The metadata server | Compute Engine, GKE Workload Identity, Cloud Run |

A service account key is signed into a token with a JWT (RS256) at Google's token endpoint; the metadata server hands out the token of the service account the workload runs as. Either way the token lasts about an hour, and Gantry renews it in the background five minutes before it expires, so requests never wait and nothing restarts. The start line names the source, never the token:

```text
gantry: provider "claude-vertex" signs in to Google Cloud with the metadata server at 169.254.169.254 (the service account of the GCE VM, GKE pod with Workload Identity, or Cloud Run service).
```

When no source answers, Gantry does not start and names each source it tried. The service account needs the Vertex AI User role (`roles/aiplatform.user`) in the project of the `url`. Gantry asks for the `cloud-platform` scope.

### Cloud Run

Run the service as a service account with `roles/aiplatform.user`. Nothing else is needed: the metadata server answers inside every Cloud Run instance.

```bash
gcloud run deploy gantry --service-account gantry@my-project.iam.gserviceaccount.com ...
```

### GKE with Workload Identity

Let the Kubernetes service account Gantry runs as act for a Google service account with `roles/aiplatform.user`:

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: gantry
  annotations:
    iam.gke.io/gcp-service-account: gantry@my-project.iam.gserviceaccount.com
```

```bash
gcloud iam service-accounts add-iam-policy-binding gantry@my-project.iam.gserviceaccount.com \
  --role roles/iam.workloadIdentityUser \
  --member "serviceAccount:my-project.svc.id.goog[gantry/gantry]"
```

Granting `roles/aiplatform.user` to the Kubernetes service account's principal directly (`principal://iam.googleapis.com/projects/<number>/locations/global/workloadIdentityPools/my-project.svc.id.goog/subject/ns/gantry/sa/gantry`) works the same way.

### Compute Engine

Attach a service account with `roles/aiplatform.user` to the VM, with the `cloud-platform` access scope.

### A service account key file

Outside Google Cloud, point `GOOGLE_APPLICATION_CREDENTIALS` at a JSON key:

```bash
export GOOGLE_APPLICATION_CREDENTIALS=/run/secrets/gantry-vertex.json
gantry serve gantry.policy.yaml
```

A workload identity federation file (`external_account`) is not read yet: Gantry refuses it at start and says so.

### An access token, for local use

`key_env` still takes an OAuth access token, which Google issues for about an hour. Gantry reads it at start and does not renew it, so an expired token means a restart with a new one:

```yaml
    key_env: VERTEX_ACCESS_TOKEN     # export VERTEX_ACCESS_TOKEN=$(gcloud auth print-access-token)
```

## Claude on Vertex AI

Claude Code or any messages client reaches these models through `POST /v1/messages`. Gantry sends the body to `<url>/models/<model>:rawPredict`, or `:streamRawPredict` when the body says `"stream": true`, with `Authorization: Bearer <token>`.

- `model` is removed from the body, because the path carries it.
- `"anthropic_version": "vertex-2023-10-16"` is added.
- The answer is Anthropic's own format, streamed or whole, and goes back unchanged.
- `anthropic-beta` headers are passed on as sent. Whether Vertex AI honours a beta is up to Vertex AI.
- `POST /v1/messages/count_tokens` is refused with `wrong_route` for these models.
- `accept_chat: true` lets chat completions clients reach them too, translated. See [Translation](/routing/translation/).

### Model names

Vertex AI names Claude models without Anthropic's date suffix (`claude-sonnet-4-6`). When Claude Code sends another name, map it with an alias:

```yaml
aliases:
  - name: claude-sonnet-5-5
    deployments:
      - { provider: claude-vertex, model: claude-sonnet-4-6 }
```

See [Aliases](/routing/aliases/).

## Gemini on Vertex AI

Callers use `POST /v1/chat/completions`. Gantry applies the same translation as the [`gemini` kind](/providers/gemini/) and sends it to `<url>/models/<model>:generateContent`, or `:streamGenerateContent?alt=sse` for a stream, with `Authorization: Bearer <token>`.

A `vertex` provider can fall back to a `gemini` or another `vertex` provider. With `accept_messages: true`, Claude Code can use these Gemini models too.

## Batches

With a `batch:` section naming a bucket, `/v1/files` and `/v1/batches` run as Vertex AI batch prediction, for Gemini and Claude, on files Gantry keeps in Cloud Storage, owned, checked, reserved and metered per line like OpenAI batches. See [Bedrock and Vertex AI batches](/providers/batches-and-realtime/#bedrock-and-vertex-ai-batches).

## Errors from gantry check

```text
gantry.policy.yaml:5: a vertex provider's url ends in /publishers/google, for example https://us-central1-aiplatform.googleapis.com/v1/projects/my-project/locations/us-central1/publishers/google.
```
