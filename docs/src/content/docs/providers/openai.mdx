A provider of `kind: openai` serves OpenAI's API: chat completions, Responses, embeddings, images, audio, moderations, rerank and legacy completions, plus files, batches, fine-tuning jobs and Realtime sessions. The same kind reaches any vendor with an OpenAI-compatible endpoint; only the `url`, `key_env` and model names change.

## OpenAI

```yaml title="gantry.policy.yaml"
version: 1
providers:
  - name: openai
    kind: openai
    url: https://api.openai.com
    key_env: OPENAI_PROVIDER_KEY
    models: [gpt-4o-mini, gpt-4o]
rules:
  - name: everyone
    principals: { any: true }
    models: [gpt-4o-mini]
```

Gantry sends the key as `Authorization: Bearer <key>` and forwards the body byte for byte, so the model name the client sends is the one OpenAI receives.

## OpenAI-compatible vendors

Every vendor below is `kind: openai`. Write the vendor's documented base URL as `url`: Gantry adds the route after `/v1` (see [How the URL is built](/providers/overview/#how-the-url-is-built)).

| Vendor | `url` | Routes the vendor documents |
|---|---|---|
| Groq | `https://api.groq.com/openai/v1` | chat, Responses |
| Mistral | `https://api.mistral.ai` | chat, embeddings |
| Together AI | `https://api.together.ai/v1` | chat, Responses, embeddings |
| Fireworks AI | `https://api.fireworks.ai/inference/v1` | chat |
| DeepSeek | `https://api.deepseek.com` | chat (see the DeepSeek tab) |
| OpenRouter | `https://openrouter.ai/api/v1` | chat, Responses |
| xAI | `https://api.x.ai` | Responses, chat |
| Gemini (compatible endpoint) | `https://generativelanguage.googleapis.com/v1beta/openai/` | chat |

Gantry forwards each route to any `openai` provider. A route the vendor does not serve comes back as the vendor's 404.

## Responses and embeddings

`POST /v1/responses` (OpenAI's Responses API, used by Codex and newer OpenAI SDKs) and `POST /v1/embeddings` go to the `openai` provider that lists the request's `model`, as their original bytes. They are governed as chat requests are: identified, decided, checked by guardrails, cached, rate limited, counted against budgets, recorded before they are sent, retried and sent to the fallback.

| Route | Guardrails read | Usage read from |
|---|---|---|
| `/v1/responses` | `instructions`, every `input` text (a string, or `input_text` parts), the `output` of `function_call_output` items, string values of `prompt.variables` | `usage`: `input_tokens` less `input_tokens_details.cached_tokens` and `cache_write_tokens` (counted apart), and `output_tokens`. For a stream, from `response.completed`, `response.incomplete` or `response.failed`. |
| `/v1/embeddings` | `input` strings. Token ID arrays are not text and are not checked. | `usage.prompt_tokens` |

A Responses request's `max_output_tokens` sizes its budget reservation.

- A request with `previous_response_id` or `store: true` leaves the conversation stored at OpenAI under Gantry's provider key. The record shows the request; Gantry does not track what the provider stored.
- Under a budget, a request that names stored context (`previous_response_id`, `conversation` or `prompt`) is refused with `stored_context`, unless the model's price sets `max_context`. See [Pricing](/routing/pricing/).
- A response made through Gantry is its creator's: `GET /v1/responses/{id}` (with `include`, `stream` and `starting_after`), `GET /v1/responses/{id}/input_items`, `DELETE /v1/responses/{id}` and `POST /v1/responses/{id}/cancel` reach the provider that made it (OpenAI, or Azure at its own path) for them alone; anyone else is answered 404, as for files and batches, and an admin key reaches all. Each read is decided and recorded. A response translated for a provider that does not speak Responses is kept by Gantry instead, for an hour, when the request said `"store": true`; reading one that was not kept is refused with `not_kept`, and cancelling one with `not_background`. Where it is kept: see [Held answers](#held-answers).
- A background response (`"background": true`, not streamed) is answered `queued` and has used nothing yet, so its usage record says `usage: background` and charges nothing; the budget reservation its request made stays held. Gantry charges what it used, from the response's `usage`, the first time it sees the response ended (`completed`, `incomplete`, `failed` or `cancelled`): when its creator reads it (`GET`) or cancels it, or when Gantry asks for it itself, once a minute, so a response nobody reads is still charged. The usage record names it (`response`, `background: true`) and the reservation is given back. With a store, the first replica to see it end charges it and the others do not. One deleted before Gantry saw it end is read once more and charged what it used, or its reservation if the provider says nothing more.

## Async jobs

`POST /v1/async/<route>` runs a request in the background on one of `chat/completions`, `completions`, `responses`, `embeddings`, `messages`, `moderations`, `rerank`, `images/generations`, `audio/speech`, `audio/transcriptions`. The body is the route's own. Gantry answers `202` with `{"id": "job_...", "status": "pending"}` at once, then runs the request on the governed route: decided, guarded, budgeted and recorded under its own decision, as if sent there. `GET /v1/async/<route>/<id>` answers `202` while it runs and `200` when it ends, with `status` (`completed` or `failed`), `status_code`, `result` or `error`, `decision` (the inner request's record) and `expires_at`. Only the submitter (or an admin key) reads it; anyone else gets 404.

- The answer is held for an hour after the job ends, or `x-gantry-async-ttl` seconds (60 to 86400).
- A job cannot stream: `"stream": true` is refused with `stream_not_async`.
- Where the answer is held: see below.

## Held answers

Async job answers and translated responses kept with `"store": true` are text Gantry holds for their owner. They are never written to the audit log.

- With a store (`store:` in the policy), they are kept in its database, table `gantry_batches_held` (namespace `batches`, migration 2), so any replica answers for any job or response. When the gateway has a master key (`GANTRY_MASTER_KEY`, as for provider credentials), each answer is sealed with it (AES-256-GCM); without one it is kept as JSON, so set a master key wherever the database is not trusted with prompts and answers. Expired answers are deleted as new ones are held; reads never return one past its time.
- Without a store, they are kept in the memory of the replica that took them, and lost when it restarts.

## Images, audio, moderations and rerank

These routes go to the `openai` provider that serves the request's `model`, or an alias's deployment, as their original bytes, to the same path under its `url`. Each is governed as chat is.

| Route | Body | Guardrails read | Usage and cost |
|---|---|---|---|
| `POST /v1/images/generations` | JSON | `prompt` (a string; any other shape is refused under a rule with guardrails) | `usage` when reported (gpt-image models), else `per_image` times the images in `data` |
| `POST /v1/images/edits`, `POST /v1/images/variations` | `multipart/form-data`, parsed strictly, forwarded byte for byte; the policy reads its `model` field | Every text field but `model`, such as an edit's `prompt`. Not the images. | `usage` when reported, else `per_image` times the images in `data`; a budget reserves `per_image` times the form's `n` |
| `POST /v1/audio/transcriptions` | `multipart/form-data`, parsed strictly, forwarded byte for byte | Every text field but `model`, such as `prompt`. Not the audio. | `usage` when reported, else the reservation |
| `POST /v1/audio/speech` | JSON; the audio answer streams through | `input` and `instructions` (strings; any other shape is refused under a rule with guardrails) | None reported: charged its reservation under a budget |
| `POST /v1/moderations` | JSON | `input`: a string, a list of strings, or `text` items | None reported |
| `POST /v1/completions` | JSON, legacy text completions | `prompt` and `suffix` (a string or a list of strings; token IDs are refused under a rule with guardrails) | `usage` |
| `POST /v1/rerank` | JSON, Cohere style, for a provider that serves it (vLLM, Cohere's compatible endpoint) | Every string in `query` and each document, structured fields included | None reported |

- A request with no `model` is refused with `unreadable_request`. This includes a moderation request, which OpenAI would otherwise send to its default model. A form with no `model` field, or with two, is refused the same way.
- A transcription form is parsed strictly, so the field Gantry decides on is the one every parser reads. A form with an extended `name*=` parameter, spaces around `=`, a backslash or single quotes in a parameter, a folded header line, or bytes after the closing boundary is refused with `unreadable_request`.
- A guardrail mask on a transcription's text fields is written back into the form. A form with no text field is forwarded, and its record says `"guardrails": "not_run: the body is audio"`.
- Image edits and variations and audio translations are refused with `unknown_route`. Files, batches, fine-tuning jobs and Realtime sessions are served natively, each owned by its creator: see [Files, batches and realtime](/providers/batches-and-realtime/).

<Aside type="caution">
Guardrails never read the audio of a transcription. Do not give transcription models to a rule whose guardrails must see what is spoken.
</Aside>

Image and speech models priced by the token need `max_output` in their price under a budget or a tokens-per-minute limit; image models priced by the image need `per_image`. See [Pricing](/routing/pricing/).

## Presets

Each of these has a `preset:` in the [provider catalog](/reference/providers/), with the URL from its own documentation:

| Provider | `preset` | Notes |
|---|---|---|
| DeepSeek | `deepseek` | Chat. `deepseek-reasoner` returns `reasoning_content`, which Gantry passes on. |
| xAI | `xai` | Chat, Responses. |
| Together AI | `together` | Chat, embeddings, rerank. |
| Fireworks AI | `fireworks` | Chat, embeddings. |
| Perplexity | `perplexity` | Chat; citations come back in the answer as Perplexity sends them. |
| Cerebras | `cerebras` | Chat. |
| OpenRouter | `openrouter` | Chat, Responses. |
| Hugging Face Inference Providers | `huggingface` | Chat. |
| Databricks Model Serving | `databricks` | Write your workspace URL, `https://<workspace>.cloud.databricks.com/serving-endpoints`, next to the preset; the key is a Databricks token. Model names are serving endpoint names. |
| Snowflake Cortex | `snowflake` | Write your account URL, `https://<account>.snowflakecomputing.com/api/v2/cortex/v1`, next to the preset; the key is a programmatic access token. |
| Ollama, vLLM, LM Studio | `ollama`, `vllm`, `lmstudio` | Local: `allow_private: true`. See [Local models](/providers/local-models/). |

A preset whose URL holds a placeholder in capitals fails `gantry check` until the provider writes its own `url`:

```yaml
  - name: databricks
    preset: databricks
    url: https://acme.cloud.databricks.com/serving-endpoints
    key_env: DATABRICKS_TOKEN
    models: [databricks-claude-sonnet-5-5, databricks-gpt-5]
```

Databricks model names in the price table carry the `databricks-` prefix Databricks gives its foundation model endpoints, so budgets price them without a `prices:` entry.

Cohere and IBM watsonx.ai have native kinds: see [Cohere and watsonx.ai](/providers/cohere-and-watsonx/).
