The live matrix runs every route Enterplace serves through a real `enterplace serve` against each provider kind, and records pass, fail or skipped per route and provider. A provider runs only when its credentials are set, so a skipped cell means no key, never a pass.

## Routes

| Route | Request | Passes when |
|---|---|---|
| `chat`, `chat_stream` | `POST /v1/chat/completions`, whole and streamed | A `chat.completion`, or chunks ending in `data: [DONE]` |
| `messages`, `messages_stream` | `POST /v1/messages`, whole and streamed | A `message`, or events ending in `message_stop` |
| `tool_calls` | One tool and a forced tool choice, in the provider's own API | The answer calls the tool |
| `responses` | `POST /v1/responses` | A `response` object |
| `embeddings` | `POST /v1/embeddings` | An embedding |
| `images` | `POST /v1/images/generations`, one low quality image | An image |
| `audio_speech`, `audio_transcription` | `POST /v1/audio/speech`, and `POST /v1/audio/transcriptions` of a half second tone | Audio bytes, or a `text` field |
| `moderations` | `POST /v1/moderations` | A `results` list |
| `count_tokens` | `POST /v1/messages/count_tokens` | `input_tokens` |
| `passthrough` | `GET` of the provider's model list through `/passthrough/<provider>/...` | A JSON answer |

Every passing answer also carries `X-Enterplace-Decision`. Each provider runs on its own gateway with its own key and audit log, and the run ends with `enterplace audit verify` on that log.

## How a run is made

`.github/workflows/live.yml` runs `scripts/live_matrix.py` every night and on demand. It writes the matrix as the run's job summary and as the `live-matrix` artifact (`live-matrix.json`).

Spend is capped: the cheapest model of each provider, prompts of a few words, `max_tokens` 16 (64 for a tool call), and a cap on the tokens of the whole run (`ENTERPLACE_LIVE_MAX_TOKENS`, 20,000 by default), counted from each answer's usage. Past the cap every remaining cell is skipped.

| Provider | Repository secrets |
|---|---|
| OpenAI | `ENTERPLACE_LIVE_OPENAI_KEY` |
| Anthropic | `ENTERPLACE_LIVE_ANTHROPIC_KEY` |
| Azure OpenAI | `ENTERPLACE_LIVE_AZURE_KEY`, `ENTERPLACE_LIVE_AZURE_URL` (`https://<resource>.openai.azure.com`), `ENTERPLACE_LIVE_AZURE_DEPLOYMENT` (a `gpt-4.1-nano` deployment) |
| Amazon Bedrock | `ENTERPLACE_LIVE_AWS_ACCESS_KEY_ID`, `ENTERPLACE_LIVE_AWS_SECRET_ACCESS_KEY` (Claude Haiku 4.5 enabled in `us-east-1`) |
| Gemini | `ENTERPLACE_LIVE_GEMINI_KEY` |
| Vertex AI, Gemini and Claude | `ENTERPLACE_LIVE_VERTEX_SA_JSON`, a service account key with the Vertex AI User role. The run signs in with it for a one-hour token. |
| Groq | `ENTERPLACE_LIVE_GROQ_KEY` |
| Mistral | `ENTERPLACE_LIVE_MISTRAL_KEY` |

Run it on your own machine with the same variables:

```bash
cargo build --release -p enterplace-cli
ENTERPLACE_LIVE_OPENAI_KEY=sk-... python3 scripts/live_matrix.py --out live-matrix.json
```

`--mock` runs every provider against a local mock of its API instead, and `--selftest` checks both the mocks (every cell passes) and a run without keys (every cell is skipped). CI runs `--selftest` on every change.

## Updating this page

This page shows `docs/src/data/live-matrix.json`. To publish a new run, download its `live-matrix` artifact, replace that file with it and commit. The workflow never writes to the repository itself.

<Aside type="note">
Until the provider secrets are set, the latest run has every cell skipped. Models, regions and the API version are set per provider with `ENTERPLACE_LIVE_<PROVIDER>_CHAT_MODEL` and the other variables named at the top of `scripts/live_matrix.py`.
</Aside>
