A provider of `kind: azure` serves Azure OpenAI chat completions, the Responses API and embeddings. Callers send the model name; Gantry maps it to your deployment and calls Azure with the `api-key` header, or with a Microsoft Entra ID token when the provider has no key.

## Example

```yaml title="gantry.policy.yaml"
version: 1
providers:
  - name: azure
    kind: azure
    url: https://acme.openai.azure.com        # https://<resource>.openai.azure.com
    key_env: AZURE_OPENAI_API_KEY
    api_version: 2024-10-21
    models: [gpt-4o, gpt-4o-mini]
    deployments:                               # model name: deployment name
      gpt-4o: prod-gpt-4o
      gpt-4o-mini: prod-gpt-4o-mini
rules:
  - name: everyone
    principals: { any: true }
    models: [gpt-4o-mini]
```

A chat request for `gpt-4o` goes to:

```text
POST https://acme.openai.azure.com/openai/deployments/prod-gpt-4o/chat/completions?api-version=2024-10-21
api-key: <the value of AZURE_OPENAI_API_KEY>
```

The other routes:

```text
POST https://acme.openai.azure.com/openai/responses?api-version=2025-04-01-preview          (model: the deployment name)
POST https://acme.openai.azure.com/openai/deployments/prod-embed/embeddings?api-version=2024-10-21
```

The Responses API needs an `api_version` of `2025-03-01-preview` or later. Its body goes as it came, with `model` set to the deployment.

## Microsoft Entra ID

Leave out `key_env`, `key_file` and `credential`, and Gantry signs in with Microsoft Entra ID instead, sending `Authorization: Bearer <token>` for the scope `https://cognitiveservices.azure.com/.default`. It looks for credentials in the order of the Azure Identity libraries' default chain, and the first source that answers is used:

| Order | Source | Set up by |
|---|---|---|
| 1 | `AZURE_TENANT_ID`, `AZURE_CLIENT_ID` and `AZURE_CLIENT_SECRET`: client credentials | You (an app registration) |
| 2 | `AZURE_TENANT_ID`, `AZURE_CLIENT_ID` and `AZURE_FEDERATED_TOKEN_FILE`: the federated token as a client assertion | Workload identity on AKS |
| 3 | `IDENTITY_ENDPOINT` and `IDENTITY_HEADER` | The managed identity of App Service and Container Apps |
| 4 | The instance metadata service at 169.254.169.254 | The managed identity of a VM or AKS node pool |

`AZURE_CLIENT_ID` picks a user-assigned managed identity for sources 3 and 4. `AZURE_AUTHORITY_HOST` names another cloud's sign-in host (for example `https://login.microsoftonline.us`). Tokens are renewed in the background five minutes before they expire; the start line names the source, never the token. The identity needs the Cognitive Services OpenAI User role on the resource.

```yaml
  - name: azure
    kind: azure
    url: https://acme.openai.azure.com
    api_version: 2025-04-01-preview
    models: [gpt-4o]
    deployments: { gpt-4o: prod-gpt-4o }
```

## Fields

| Field | Type | Default | Description |
|---|---|---|---|
| `url` | string | required | `https://<resource>.openai.azure.com`. A `url` with a path is put in front of `/openai/deployments/...`. |
| `key_env` | string | none | The variable that holds the Azure OpenAI key, sent as `api-key`. Without it, Gantry signs in with Microsoft Entra ID. |
| `chat_as_responses` | bool | `false` | Send chat completions requests to the Responses API, for models served only there. |
| `api_version` | string | required | A date, such as `2024-10-21`, or a date with `-preview`, such as `2025-04-01-preview`. Needs a restart to change. |
| `deployments` | map | required | Model name to deployment name. Every model in `models` needs an entry. |

## Behavior

- Callers use `POST /v1/chat/completions`, `POST /v1/responses` and `POST /v1/embeddings`. Messages requests are refused with `wrong_route` unless the provider sets `accept_messages: true`. See [Translation](/routing/translation/).
- The body goes as it came, `model` included. The deployment in the path decides what runs.
- `deployments` changes without a restart; `api_version` needs one.
- An `azure` provider can be the fallback of an `openai` provider, and the reverse. The fallback serves each model through its own `deployments`. See [Retries and fallbacks](/routing/retries-and-fallbacks/).
- A content filter error from Azure (`content_filter`) can send an alias request to its `content_policy_fallback`. See [Aliases](/routing/aliases/).

<Aside type="note">
Azure's newer `/openai/v1` API, and images and audio on Azure, are not served yet: Gantry uses the deployment URLs with `api-version`.
</Aside>

## Errors from gantry check

```text
gantry.policy.yaml:12: api_version is a date, as Azure writes it: 2024-10-21, or 2025-04-01-preview for a preview version.
gantry.policy.yaml:14: model "gpt-4o" has no entry in deployments, so Gantry would not know what to call it at provider "azure". Add `gpt-4o: <name>` under deployments.
```
