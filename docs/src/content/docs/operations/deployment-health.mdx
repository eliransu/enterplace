A deployment is a provider and model an [alias](/routing/aliases/) names. Enterplace keeps a circuit for each: it cools down after a failure, a [health probe](/routing/health-probes/) can check it, and its limits and latency steer the alias's routing. The console's **Deployments** page and `GET /admin/deployments` show that state, and each provider with its [key pool](/routing/key-pools/).

## What every replica shows

With a [store](/operations/store/), every gateway writes what it knows of each deployment to the store every 2 seconds and reads the others' reports, so the page is the same whichever replica answers it. Without a store it shows this gateway alone. The answer says which in `counted_by` (`store` or `this gateway`) and how many gateways reported in `gateways`.

The page's Gateways panel lists every gateway on the store with its version, its health and the policy version it runs. One silent for 10 seconds is `silent`; one with no heartbeat for over an hour is `stopped` and folded away behind **Show stopped gateways (N)**, so the running ones read at a glance. The store forgets a gateway a day after its last heartbeat.

| Field | Meaning | Across gateways |
|---|---|---|
| `state` | `up`, `cooling` (passed over after a failure) or `down` (its last probe got no answer, a 429 or a 5xx) | Cooling on any gateway is cooling: the store shares cooldowns |
| `cooling_seconds` | How long until it is tried again | The longest |
| `cooldowns` | Times it was put to cool down since start | Summed |
| `probe` | The last probe's `outcome` (a status or a refusal code), `up` and `time`. `null` without a probe | The newest: one gateway at a time probes a deployment |
| `limits` | Its `rpm`, `tpm` and `max_parallel` from the policy | The policy's |
| `in_flight`, `requests_this_minute`, `tokens_this_minute` | Its load now, against those limits | Summed |
| `latency_p50_ms`, `latency_p90_ms` | Time to its answer's headers, over its last 32 answers on each gateway | Over every gateway's samples |
| `error_rate` | The share of recent attempts that failed, as a moving average (each attempt moves it a fifth of the way) | The highest any gateway sees |
| `rate_headroom` | The smallest share left of the rate limits its provider named in its last answer's headers | The lowest |

Each provider lists the keys of its pool by fingerprint, never the key: `ready` or `resting` (set aside after a 401, 403 or 429) with the seconds left, and how often each was used. A key resting on any gateway is resting.

```bash
curl http://127.0.0.1:8080/admin/deployments -H "Authorization: Bearer $ENTERPLACE_ADMIN_KEY"
```

```json title="200"
{"counted_by":"store","gateways":3,
 "deployments":[{"deployment":"azure-eu/gpt-4o","provider":"azure-eu","model":"gpt-4o","aliases":["smart"],
   "limits":{"rpm":600,"tpm":null,"max_parallel":null},"probed":true,"state":"cooling","cooling_seconds":42,"cooldowns":3,
   "probe":{"up":false,"outcome":"503","time":"2026-11-15T10:04:11.220Z"},"latency_p50_ms":410,"latency_p90_ms":980,
   "error_rate":0.36,"in_flight":0,"requests_this_minute":12,"tokens_this_minute":48200,"rate_headroom":0.4}],
 "providers":[{"name":"azure-eu","kind":"azure","models":["gpt-4o"],
   "keys":[{"key":"9f2c11aa","state":"ready","resting_seconds":0,"uses":812},{"key":"03be7c5d","state":"resting","resting_seconds":38,"uses":790}]}]}
```

Any admin role reads it. State is kept in memory and in the store's routing tables, so it starts over when every gateway restarts. For state over time, graph `enterplace_deployment_up`, `enterplace_deployment_cooldowns_total`, `enterplace_upstream_responses_total` and `enterplace_deployment_rate_headroom_ratio` from [`/metrics`](/operations/observability/).

## Test a provider's connection

**Test connection** beside a provider, or `POST /admin/providers/<name>/test`, sends the cheapest call a provider documents: `GET /v1/models`, its model list, which bills nothing. Any 2xx means the address, the key and the network between hold.

```bash
curl -X POST http://127.0.0.1:8080/admin/providers/openai/test -H "Authorization: Bearer $ENTERPLACE_ADMIN_KEY"
```

```json title="200"
{"provider":"openai","call":"GET /v1/models","latency_ms":212,"key":null,"ok":true,"status":200,"outcome":"200","models_listed":64,
 "detail":"The provider answered: its address and key work."}
```

| Outcome | `ok` | What it means |
|---|---|---|
| 2xx | `true` | The provider answered. `models_listed` counts its list |
| 401, 403 | `false` | The provider refused the key. Check its `key_env` or its entry on the [Credentials](/governance/provider-credentials/) page |
| 404 | `false` | No model list at this address. Check the provider's `url`; a provider that serves no model list can only be tested with a request |
| 429 | `false` | The address and key work; the key is out of quota or rate limited now |
| `upstream_unreachable`, `upstream_timeout` | `false` | Enterplace could not reach it. Check the `url` and the network |

The test needs the `edit_policy` permission and a role not kept to part of the install. Each test is recorded in the audit log as `test_provider` with its outcome and latency; the record never holds the key or the provider's answer. A provider with a key pool is tested with the pool's next key, named by its fingerprint in `key`.

<Aside>
The Deployments page is built from the console's existing components and has no design of its own yet.
</Aside>
