## What you get

A list of the AI tools and models in use and what each one costs, per key, from the first day. Nothing is blocked.

## The one change

<Steps>

1. On the machine that will run Gantry, install it and start it (no provider key needed):

    ```bash
    curl -fsSL https://gantry.enterplace.dev/install.sh | sh
    gantry start
    ```

    It writes `gantry.policy.yaml` in observe mode with one rule that allows everyone, makes an admin key, starts the gateway, and opens the dashboard with a link that signs you in once. In the dashboard, **Connect a model** takes a provider key (kept sealed) or the free demo model, and **Send your first request** shows the first request arrive. Provider keys already in the environment (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`) are picked up.

2. Point the first tools at it. In the dashboard, **Start here** makes a key and shows the exact lines for each tool; the [coding tool guides](/integrations/coding-tools/) cover Claude Code, Codex, Cursor and the rest. Claude Code on a Claude subscription needs one line and no key: `export ANTHROPIC_BASE_URL=http://127.0.0.1:8080`.

</Steps>

## Check it worked

In observe mode Gantry forwards every request from a key it knows. A request with a missing, wrong, expired or revoked key, or for a model your providers do not list, is still refused.

The dashboard link `gantry start` printed opens the console (or sign in at `http://127.0.0.1:8080/console` with the admin key). The banner says nothing is blocked yet. On an empty install the console asks what you want to start with; pick **Coding agents** (or **Our own apps and agents**) and **Start here** gives you the checklist for this step: connect a model, send a first request, make a key for a person, paste the lines it shows, send one prompt. The step turns done by itself when the request arrives, and the first rows show on Start here.

- **Analytics** (`/console/analytics`): rank by coding agent, model or key to see requests, tokens and cost for each.
- **Requests** (`/console/requests`): one row per request, with its model and cost. Filter by coding agent to see one tool.

<Aside type="note">
Claude Code on Claude Pro, Max, Team or Enterprise seats goes through Gantry on its own login, with no API key: `gantry start` already wrote the `claude-subscriptions` provider for it. See [Claude Code](/integrations/claude-code/#claude-subscriptions). Where nothing may be routed, Gantry Enterprise's [watch mode](/integrations/claude-team/) receives Claude Code's own telemetry instead, and those requests appear on the same pages with **Source** `watch`.
</Aside>

## When you're ready

You can see tools, models and cost, with one line per key. To see people and teams, go to [Step 2: Know](/start/step-2-know/).

## More

### The policy `gantry start` writes

With both provider keys set, `gantry start --no-serve` writes exactly this:

```yaml title="gantry.policy.yaml"
# Written by gantry start. Every key may use every model. Observe mode: nothing is blocked, and what a
# rule would refuse is recorded as would_refuse. Reference: https://gantry-docs.enterplace.dev/governance/policy/
version: 1
mode: observe
providers:
  # Answered inside Gantry with a sample text, free: a first request works before any provider key is set.
  - name: demo
    preset: demo
    models: [gantry-demo]
  - name: openai
    preset: openai
    key_env: OPENAI_PROVIDER_KEY
    models: [gpt-5, gpt-5-mini, gpt-5-codex, gpt-4o-mini]
  - name: anthropic
    preset: anthropic
    key_env: ANTHROPIC_PROVIDER_KEY
    models: [claude-sonnet-5-5, claude-haiku-5-5]
  # Claude Code on your developers' own Claude subscriptions (Pro, Max, Team, Enterprise): each request carries
  # the person's own Claude login, sent on unchanged and never kept. Gantry holds no Anthropic key for it.
  - name: claude-subscriptions
    kind: anthropic
    auth: passthrough
    identity: optional
    models: ["claude-*"]
    url: https://api.anthropic.com
rules:
  - name: everyone
    principals: { any: true }
    models: ["*"]
```

Add a model to a provider's `models` list to serve it. The provider keys stay in the environment and never appear in the file. The policy reads them from `OPENAI_PROVIDER_KEY` and `ANTHROPIC_PROVIDER_KEY`, so the tool settings can set `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` to your Gantry key in the same shell; `gantry start` passes a key it found under `OPENAI_API_KEY` to the gateway it runs. A provider connected in the dashboard reads its key from a sealed credential instead (`credential: openai`), and the `demo` provider is answered inside Gantry.

### What observe mode does

| Situation | In observe mode |
|---|---|
| A rule, budget, rate limit or guardrail would refuse the request | Forwarded, and recorded as `would_refuse` with the refusal code |
| The same on batches, files, fine-tuning, realtime, passthrough and MCP tools, or for an address, tag or customer the rule does not list | Forwarded, and recorded as `would_refuse` |
| A budget applies and the cost cannot be estimated (`no_price`, `max_tokens_needed`, `stored_context`) | Forwarded, and recorded as `would_refuse` with that code |
| No key, an unknown, expired or revoked key | Refused |
| A model no provider lists | Refused |
| A [kill switch](/governance/kill-switches/) matches | Refused with `killed` |

`gantry check` warns while `mode: observe` is in the policy. Delete the line to enforce the policy from the next request.

### Flags

| Flag | Does |
|---|---|
| `--providers openai,anthropic` | Sets up only these of the provider keys found in the environment |
| `--dir <path>` | Writes the files in that folder |
| `--listen <host:port>` | Where the gateway listens, `127.0.0.1:8080` by default |
| `--no-open` | Prints the dashboard link without opening the browser |
| `--force` | Writes a new policy and admin key over the ones there. Without it, `gantry start` serves the policy it finds |
| `--no-serve` | Writes the files and does not start the gateway |
