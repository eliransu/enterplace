## What you get

A list of the AI tools and models in use and what each one costs, per key, from the first day. Nothing is blocked.

## The one change

<Steps>

1. On the machine that will run Gantry, set the provider keys you already have and start it:

    ```bash
    export OPENAI_API_KEY=sk-...
    export ANTHROPIC_API_KEY=sk-ant-...
    gantry start
    ```

    It writes `gantry.policy.yaml` in observe mode with one rule that allows everyone, prints an admin key once and the settings for the coding tools it finds on the machine, and starts the gateway.

2. Give the people who try it first one key: `gantry key new pilot --team pilot` prints it once, with the lines their tool reads. The [coding tool guides](/integrations/coding-tools/) cover Claude Code, Codex, Cursor and the rest.

</Steps>

## Check it worked

In observe mode Gantry forwards every request from a key it knows. A request with a missing, wrong, expired or revoked key, or for a model your providers do not list, is still refused.

Open `http://127.0.0.1:8080/console` and sign in with the admin key. The banner says **Observe mode: nothing is blocked**.

- **Analytics** (`/console/analytics`): rank by coding agent, model or key to see requests, tokens and cost for each.
- **Requests** (`/console/requests`): one row per request, with its model and cost. Filter by coding agent to see one tool.

<Aside type="note">
Developers on Claude Team or Enterprise seats cannot send their requests through a gateway. Use the [Claude Team watch setup](/integrations/claude-team/) for them instead.
</Aside>

## When you're ready

You can see tools, models and cost, with one line per key. To see people and teams, go to [Step 2: Know](/start/step-2-know/).

## More

### The policy `gantry start` writes

With both provider keys set, `gantry start --yes --no-serve` writes exactly this:

```yaml title="gantry.policy.yaml"
# Written by gantry start. Step 1, See: every key may use every model, and in observe mode
# nothing is blocked; what a rule would refuse is recorded. Reference: https://gantry-docs.eliran.me/governance/policy/
version: 1
mode: observe
providers:
  - name: openai
    preset: openai
    key_env: OPENAI_PROVIDER_KEY
    models: [gpt-5, gpt-5-mini, gpt-5-codex, gpt-4o-mini]
  - name: anthropic
    preset: anthropic
    key_env: ANTHROPIC_PROVIDER_KEY
    models: [claude-sonnet-5-5, claude-haiku-5-5]
rules:
  - name: everyone
    principals: { any: true }
    models: ["*"]
```

Add a model to a provider's `models` list to serve it. The provider keys stay in the environment and never appear in the file. The policy reads them from `OPENAI_PROVIDER_KEY` and `ANTHROPIC_PROVIDER_KEY`, so the tool settings can set `OPENAI_API_KEY` and `ANTHROPIC_API_KEY` to your Gantry key in the same shell. `gantry start` passes a key it found under `OPENAI_API_KEY` to the gateway it runs, and prints the `export OPENAI_PROVIDER_KEY=$OPENAI_API_KEY` line for the next `gantry serve`.

### What observe mode does

| Situation | In observe mode |
|---|---|
| A rule, budget, rate limit or guardrail would refuse the request | Forwarded, and recorded as `would_refuse` with the refusal code |
| The same on batches, files, fine-tuning, realtime, passthrough and MCP tools, or for an address, tag or customer the rule does not list | Forwarded, and recorded as `would_refuse` |
| A budget applies and the cost cannot be estimated (`no_price`, `max_tokens_needed`, `stored_context`) | Forwarded, and recorded as `would_refuse` with that code |
| No key, an unknown, expired or revoked key | Refused |
| A model no provider lists | Refused |
| A [kill switch](/governance/kill-switches/) matches | Refused with `killed` |

`gantry check` warns while `mode: observe` is in the policy. Delete the line to enforce the policy from the next request.

### Run it without questions

| Flag | Does |
|---|---|
| `--providers openai,anthropic` | Names the providers instead of asking |
| `--yes` | Accepts every default, for scripts and CI |
| `--dir <path>` | Writes the files in that folder |
| `--listen <host:port>` | Where the gateway listens, `127.0.0.1:8080` by default. The printed settings use it |
| `--all-tools` | Prints the settings for every tool, not only the ones found on the machine |
| `--force` | Overwrites an existing `gantry.policy.yaml`. Without it, `gantry start` refuses to |
| `--no-serve` | Writes the files and does not start the gateway |
