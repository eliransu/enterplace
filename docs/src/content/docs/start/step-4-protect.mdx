## What you get

A prompt that holds an API key, a private key or a database password is stopped before it leaves. You see what would be stopped before anything is.

## The one change

Add a guardrail to `gantry.policy.yaml` and name it in your rule:

```yaml title="gantry.policy.yaml (changed)"
guardrails:
  - name: no-secrets
    type: secrets
    action: block
    shadow_until: 2026-12-15
rules:
  - name: everyone
    principals: { any: true }
    models: ["*"]
    guardrails: [no-secrets]
```

Until 15 December (UTC) it records what it finds and blocks nothing. From that date it refuses a request that holds a secret with `guardrail_blocked`, with no reload.

## Check it worked

- **Start here** (`/console/start`): **MCP tools** puts a server behind Gantry, prints the `claude mcp add` command for this gateway, and turns done on the first tool call and the first call that waits for approval.
- **Requests** (`/console/requests`): filter by guardrail finding, such as `aws_access_key` or `database_url`, to see which requests held one.
- **Audit log** (`/console/audit`): open a record to see its findings. During the trial each one says `shadow`.

If the findings are real secrets, let the date arrive. If the guardrail catches text it should leave alone, move the date and read [Guardrails](/governance/guardrails/) for what each detector matches.

<Aside type="note">
Guardrails read requests that go through Gantry. Claude Code on Claude Team or Enterprise seats talks to Anthropic directly, so [watch mode](/integrations/claude-team/) records it and cannot check it: this step needs API traffic through Gantry.
</Aside>

## When you're ready

Secrets stay in. To keep evidence of all of it, go to [Step 5: Prove](/start/step-5-prove/).

## More

### Where the check runs

The detector runs inside Gantry. No prompt text goes to another service, and the text it matched is never written to a record. Pick a trial date that gives you a week or two of normal work to look at.

### Personal data

The `pii` detector finds email addresses, phone numbers, card numbers and similar. `mask` replaces each finding and forwards the rest of the request:

```yaml title="gantry.policy.yaml (changed)"
guardrails:
  - name: no-secrets
    type: secrets
    action: block
  - name: mask-pii
    type: pii
    action: mask
    shadow_until: 2026-12-15
rules:
  - name: everyone
    principals: { any: true }
    models: ["*"]
    guardrails: [no-secrets, mask-pii]
```

### Test on examples first

Run a guardrail over a file of example prompts before any request meets it:

```bash
gantry guardrail test no-secrets --corpus examples.jsonl --policy gantry.policy.yaml
```

The report counts what it would hit, by kind. See [Backtest before enforcing](/governance/guardrails/#backtest-before-enforcing).

### Tools behind the gateway

Agents call tools through MCP servers. Put those servers behind Gantry and name the tools that need an admin's approval before they run:

```yaml title="gantry.policy.yaml (changed)"
mcp:
  - name: github
    url: https://api.githubcopilot.com/mcp/
rules:
  - name: platform
    principals: { team: platform }
    models: ["*"]
    tools: [github.*]
    approve_tools: [github.delete_repo, github.merge_pull_request]
    approval_timeout_seconds: 120
```

A call to one of those two tools waits until an admin approves or denies it on the console's **MCP approvals** page. See [MCP gateway](/governance/mcp-gateway/).
