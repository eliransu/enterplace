A kill switch stops matching traffic within a second, with a reason the people stopped see in their tool. Use it for a runaway agent, a leaked key or a provider incident, then turn it off with `enterplace unkill`.

## Set a switch

<Tabs syncKey="admin">
<TabItem label="CLI">

```bash
export ENTERPLACE_URL=https://enterplace.example.com
export ENTERPLACE_ADMIN_KEY=enterplace_...

enterplace kill --person maya.cohen@example.com --reason "retrying the same ticket in a loop"
enterplace kill --team support --reason "support budget review"
enterplace kill --key-prefix 3f9a1c2e --reason "key pasted in a public issue"
enterplace kill --model gpt-4o --reason "provider incident"
enterplace kill --all --reason "suspected key leak, investigating"
```

The CLI takes the admin key from `ENTERPLACE_ADMIN_KEY`, or the key saved by `enterplace login` if it is an admin's. The gateway is `--url`, `ENTERPLACE_URL` or the saved login's address.

</TabItem>
<TabItem label="Admin API">

```bash
curl -X POST https://enterplace.example.com/admin/kills \
  -H "Authorization: Bearer $ENTERPLACE_ADMIN_KEY" \
  -H "Content-Type: application/json" \
  -d '{"scope":"person","value":"maya.cohen@example.com","reason":"retrying the same ticket in a loop"}'
```

Answers `201` with the switch and `"in_effect": true`. `GET /admin/kills` lists the switches that are on. See [Admin API](/reference/admin-api/).

</TabItem>
<TabItem label="Console">

On the console's **Kill switches and audit** page (under **Security**) or the **Users** page, press **Stop traffic**. Pick a person, a team, a model, a key (the first 8 hex characters of its hash) or everyone, and give the reason. People and teams are picked from a searchable list, and a name no key and no request ever had is refused. Every gateway refuses the requests within 2 seconds, and the stop is recorded with your name.

</TabItem>
</Tabs>

## Clear a switch

<Tabs syncKey="admin">
<TabItem label="CLI">

```bash
enterplace unkill --person maya.cohen@example.com
enterplace unkill --all
```

</TabItem>
<TabItem label="Admin API">

```bash
curl -X DELETE https://enterplace.example.com/admin/kills \
  -H "Authorization: Bearer $ENTERPLACE_ADMIN_KEY" \
  -H "Content-Type: application/json" \
  -d '{"scope":"person","value":"maya.cohen@example.com"}'
```

`404 no_such_switch` when no switch is on for that scope and value.

</TabItem>
<TabItem label="Console">

Each switch that is on shows at the top of **Kill switches and audit**, with who set it, when and why. Press **Restore traffic** on it. **Copy for your agent** gives a coding agent the same change with `enterplace unkill`.

</TabItem>
</Tabs>

## Scopes

| CLI flag | API `scope` | Matches |
|---|---|---|
| `--person <name>` | `person` | The name on the key. Keys from `enterplace login` are named by email. |
| `--team <team>` | `team` | The team on the key. |
| `--key-prefix <hash>` | `key_prefix` | Keys whose SHA-256 starts with these 8 to 64 hex characters, as `enterplace key list` shows them. |
| `--model <model>` | `model` | The model the caller sent. Also stops every alias with a deployment of that model. |
| `--all` | `all` | Everyone. Takes no value. |

| Flag | API field | Description |
|---|---|---|
| `--reason <text>` | `reason` | Required to set a switch. 1 to 500 characters. Shown to the people stopped and kept in the audit log. |
| `--force` | `force` | Set the switch even if it matches nothing, for example for a key about to be issued. |
| `--url <url>` | none | The gateway address. |

A switch that would match no key, team or served model is refused with `kill_matches_nothing`, naming what you may have meant: `Keys named like it: maya.cohen@example.com`.

A switch on a model stops the whole alias, not only that deployment. An alias's named fallback (`context_window_fallback`, `content_policy_fallback`) is not taken when a switch stops it by its name or the model of any of its deployments.

## What the stopped person sees

A stopped request is refused with `killed` (403), in the error shape their client understands:

```text
Refused: a kill switch stops traffic for person maya.cohen@example.com: "retrying the same ticket in a loop" (set by noa.bar at 2026-11-13T09:12:44.120Z). It stays stopped until an admin runs enterplace unkill. Ask noa.bar.
```

While a switch is on, the console's **Kill switches and audit** page shows it at the top, and the record of each request it stopped names it.

Admin API calls are never stopped, so an admin can always turn a switch off, including `--all`. That holds for an admin a switch names too: stop a leaked admin key by [revoking it](/governance/keys/#revoke-a-key), not with a switch.

## Persistence

Switches are kept in memory and in `enterplace.kills.json` beside the keys file, so a restart keeps them.

```json title="enterplace.kills.json"
{
  "kills": [
    {
      "scope": "team",
      "value": "support",
      "reason": "support budget review",
      "by": "noa.bar",
      "at": "2026-11-13T09:12:44.120Z"
    }
  ]
}
```

- The node that takes the change applies it before it answers. Every other node serving the same files reads it within 1 second.
- Every set and clear is an `admin` audit record: `set_kill` with the reason, `clear_kill`.
- A `enterplace.kills.json` that cannot be read, at start or when it changes, refuses every request with `kills_unreadable` (503) until it is fixed or deleted. Enterplace cannot tell who is not stopped, so it fails closed.

<Aside type="note">
Two nodes changing switches at the same instant can lose one change. Check `GET /admin/kills` after a change made during an incident.
</Aside>

## Refusal codes

| Code | Status | Cause |
|---|---|---|
| `killed` | 403 | A switch stops this person, team, key or model. |
| `kills_unreadable` | 503 | `enterplace.kills.json` cannot be read. |
| `kill_matches_nothing` | 400 | Setting a switch that matches no key, team or served model, without `--force`. |
| `no_such_switch` | 404 | Clearing a switch that is not on. |
