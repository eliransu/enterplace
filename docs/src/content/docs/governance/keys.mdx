A Enterplace key identifies one person or one workload. Callers send it in place of a provider key, and the provider keys stay with Enterplace.

Each key carries a name and a team, which the [policy](/governance/policy/) rules match on. It can also carry an expiry, a budget, a model list and a tokens-per-minute limit of its own.

## Issue a key

<Tabs syncKey="admin">
<TabItem label="CLI">

```bash
enterplace key new maya.cohen --team payments --url https://enterplace.example.com
```

```text
Key for maya.cohen, team payments. It is shown once and is not stored anywhere:

  enterplace_3f9c...(64 hex characters)

To hand it over, send these lines through your secret manager, never in chat. Claude Code and the OpenAI SDKs read them:

export ANTHROPIC_BASE_URL=https://enterplace.example.com
export ANTHROPIC_API_KEY=enterplace_3f9c...
export OPENAI_BASE_URL=https://enterplace.example.com/v1
export OPENAI_API_KEY=enterplace_3f9c...

Its hash was added to /srv/enterplace/enterplace.keys.yaml. A running `enterplace serve` accepts it within 2 seconds. `enterplace serve` reads the keys file beside its policy file unless `--keys` names another.
```

The block is ready for a shell profile, a `.env` file or a secret manager entry. `--quiet` prints the key alone, for a pipe:

```bash
enterplace key new ci.bot --team platform --quiet | vault kv put secret/enterplace key=-
```

</TabItem>
<TabItem label="Console">

Sign in to `/console` as an admin and open **People and workloads**. Fill in the name and team, and optionally an expiry, a budget and the admin flag. The console shows the key once and saves its hash to the keys file. Enterplace uses it within 2 seconds.

See [Admin console](/operations/console/).

</TabItem>
<TabItem label="Admin API">

```bash
curl -X POST https://enterplace.example.com/admin/keys \
  -H "Authorization: Bearer $ENTERPLACE_ADMIN_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"maya.cohen","team":"payments","expires":"2026-12-31","budget":{"usd":20,"per":"month"}}'
```

The answer (`201`) holds the key once, with `name`, `team` and `sha256_prefix`. The key works as soon as the answer arrives, because the admin API reloads the keys file before it answers. See [Admin API](/reference/admin-api/).

</TabItem>
</Tabs>

<Aside type="caution">
A key is shown once. Hand it over through your secret manager or device management, never in chat or email. Lose it and issue a new one.
</Aside>

### Options

| Flag | Admin API field | Console | Description |
|---|---|---|---|
| `--team <team>` | `team` | yes | Required. The team rules match on. |
| `--admin` | none | yes | May sign in to the console and call the admin API. |
| `--expires <date>` | `expires` | yes | UTC date (`2026-12-31`: refused from the start of that day) or time (`2026-12-31T18:00:00Z`). |
| `--budget <usd>/<period>` | `budget` | yes | What this key alone may spend, for example `20/month`, `5/6h` or `100/month@America/New_York` (a time zone after `@`; the API takes `{"usd": 100, "per": "month", "tz": "America/New_York"}`). |
| `--models <a,b>` | `models` | no | Narrows the rule's models for this key. |
| `--tpm <n>` | `tpm` | no | Tokens per minute for this key, 1 to 1000000000. |
| `--parallel <n>` | `parallel` | no | Most requests this key may have in flight at once, 1 to 100000. |
| `--org <org>` | `org` | no | The [organization](/governance/policy/#organizations) the key belongs to. An admin kept to one organization issues keys in it only. |
| `--customer <name>` | `customer` | no | The [end customer](/governance/budgets-and-rate-limits/#end-customers-and-tags) every request with the key is for. |
| `--tags <a,b>` | `tags` | no | Tags every request with the key carries, at most 16. |
| `--role <role>` | `role` | no | A [console role](/governance/policy/#console-roles) the key signs in with and calls the admin API with. An issuer may give only a role whose permissions it holds. |
| `--url <url>` | none | no | The address printed in the env lines. Default `http://127.0.0.1:8080`. |
| `--quiet` | none | no | Print the key alone. |
| `--keys <file>` | none | no | The keys file. Default `enterplace.keys.yaml` in the current directory. |

`enterplace serve` looks for the keys file beside the policy file. Run `key new` in that folder, or pass the same `--keys` to both.

Names and teams use letters, digits, `.`, `-`, `_` and `@`, up to 100 characters.

### The first admin

The admin API cannot make admin keys, so the first admin is made on the machine that holds the keys file:

```bash
enterplace key new noa.bar --team platform --admin
```

This writes `admin: true` on the entry. After that, admins issue keys, including more admin keys, from the console. People can also sign in to the console through [single sign-on](/governance/single-sign-on/).

## Limits per key

```bash
enterplace key new ci.release --team platform --expires 2026-12-31 --budget 20/month
enterplace key new ci.agent --team platform --models gpt-4o-mini,o3 --tpm 200000
```

| Limit | Behavior | Refusal |
|---|---|---|
| `expires` | The key stops working at that date or time. The record names whose key it was. | `key_expired` (401) |
| `budget` | Counted like a rule's budget, and on top of it: a request must fit both. | `key_budget_exceeded` (429) |
| `models` | Narrows the rule, never widens it. `/v1/models` shows only what both allow. | `model_not_allowed`, naming the key and its list |
| `tpm` | Counted for this key alone, on top of the rule's `tpm`. | `rate_limited` (429) |

Use `budget` and `expires` for a CI job or an agent that shares a team with people. The admin API refuses a `models` entry the policy does not serve, and refuses an expiry in the past. All four are written to the key's entry, and editing the entry changes them within 2 seconds, without a restart.

See [Budgets and rate limits](/governance/budgets-and-rate-limits/) for how spend and tokens are counted.

## Key fields

Besides name, team, `admin`, `expires`, `budget`, `models` and `tpm`, a key may carry:

| Field | Type | Description | Refusal |
|---|---|---|---|
| `rpm` | integer, 1 to 1000000 | Requests per minute for this key, on top of the rule's `rpm`. Shared across gateways on a store | `rate_limited` (429), `limit.of: key` |
| `parallel` | integer, 1 to 100000 | Requests in flight at once with this key, shared across gateways on a store. A place is held until the answer has been read to its end | `parallel_limited` (429) |
| `tags` | list | Tags every request with the key carries: recorded, and used by [tag routing](/routing/strategies/#tags-and-teams-pick-deployments) | |
| `metadata` | map | Your own notes, such as owner or ticket: at most 32 entries, each value at most 256 characters on one line. Shown and recorded, never decided on. An `email` entry is the address [watch mode](/integrations/claude-team/#one-name-per-person) knows the key's holder by | |
| `routes` | list | Path prefixes the key may call, such as `/v1/messages`. A prefix matches whole path segments. Empty allows every route | `route_not_allowed` (403) |
| `from` | list | [Address ranges](/governance/access-control/#source-address-ranges) the key may be used from | `ip_not_allowed` (403) |
| `mcp_tools` | list | MCP tools this key may use, within its rule's `tools:`: `<server>.<tool>`, `<server>.*`, `*`, or `!<server>.<tool>` to leave one out. It only narrows the rule. Empty leaves the rule's list. See [Tool permissions](/governance/tool-permissions/#mcp-tools-per-key-and-per-request) | `tool_not_allowed` |
| `guardrails` | list | Guardrails the key adds to its rule's, by name. They only add. See [Guardrails](/governance/guardrails/#default-guardrails-and-guardrails-per-key) | `guardrail_blocked` (403) |
| `replaced_by` | string | Set by a [rotation](#rotate-a-key): the key that replaces this one | |

```yaml title="enterplace.keys.yaml"
keys:
  - name: ci.release
    team: platform
    sha256: 0d6c...(64 hex characters)
    rpm: 60
    parallel: 4
    tags: ["release"]
    metadata: {"owner": "maya", "ticket": "OPS-12"}
    routes: ["/v1/chat/completions"]
    from: ["10.20.0.0/16"]
```

## Bounds on issued keys

`key_bounds:` caps what a key may be issued with: how long it works, how much it may spend and which models it may be given. At the top level it holds for every role and for keys from `enterplace login`; on a role it replaces the top-level one for that role's holders.

```yaml
key_bounds:
  max_days: 365
roles:
  - name: team-lead
    permissions: [see_keys, issue_keys]
    teams: [payments]
    key_bounds:
      max_days: 30
      max_budget: { usd: 100, per: month }
      models: ["group:small", gpt-4o]
model_groups:
  small: [gpt-4o-mini, claude-haiku-*]
```

| Field | Type | Description |
|---|---|---|
| `max_days` | integer, 1 to 3660 | The longest a key may work. A key issued without `expires` gets this many days. |
| `max_budget` | budget | The fastest a key may spend. A key's budget is compared by its rate, so `$5 a day` is over `$100 a month`. A key issued without a budget gets this one. |
| `models` | list | The models a key may be given: names, patterns or `group:<name>`. A key issued without `models` gets this list. |

A key over a bound is refused with `key_bounds_exceeded` (403), naming the bound and the fix. The bounds hold on `POST /admin/keys`, the console's issue form and `enterplace login`, whose keys never outlive `max_days`. `enterplace key new` writes the keys file or the store directly, as the operator of the machine, and is not bounded.

## Change a key

Change any field but name, team and `admin` on a running gateway. `none` (CLI) or `null` (API) removes a field. Each change is recorded in the audit log with what each field was and what it became, and is in force within 2 seconds on every gateway serving the same keys.

```bash
enterplace key update 5d1e4a07 --rpm 60 --tags eval,batch --metadata owner=maya --url https://enterplace.example.com
enterplace key update 5d1e4a07 --budget none
```

```bash
curl -X PATCH https://enterplace.example.com/admin/keys/5d1e4a07 \
  -H "Authorization: Bearer $ENTERPLACE_ADMIN_KEY" \
  -d '{"rpm": 60, "budget": {"usd": 20, "per": "month"}, "routes": null}'
```

A change that is wrong in any field is refused whole, and nothing is written.

## Key info and spend

```bash
enterplace key info 5d1e4a07 --url https://enterplace.example.com
```

```text
maya.cohen (team payments), key 5d1e4a07
  admin: false
  budget: {"per":"month","usd":20.0}
  rpm: 60
Spend (counted by store):
  day 2026-11-14: $0.4120 spent, $0.0300 held by requests in flight
  month 2026-11: $7.9050 spent, $0.0300 held by requests in flight
```

With a [store](/operations/store/), spend is counted across every gateway on it. Without one, it is what this gateway counted, including the audit log's records of the month at start. `GET /admin/keys/<prefix>` gives the same as JSON.

## The keys file

```yaml title="enterplace.keys.yaml"
# Keys Enterplace accepts. Only the SHA-256 of each key is kept here. Add keys with `enterplace key new`.
keys:
  - name: maya.cohen
    team: payments
    sha256: 5d1e...
  - name: ci.release
    team: platform
    sha256: 41e0...
    expires: 2026-12-31
    budget: { usd: 20, per: month }
  - name: ci.agent
    team: platform
    sha256: 7c2e...
    models: [gpt-4o-mini, o3]
    tpm: 200000
  - name: noa.bar
    team: platform
    sha256: 9b74...
    admin: true
```

| Field | Type | Default | Description |
|---|---|---|---|
| `name` | string | required | Person or workload. |
| `team` | string | required | Team. |
| `sha256` | string | required | SHA-256 of the key, 64 hex characters. |
| `admin` | boolean | `false` | Console and admin API access. |
| `expires` | string | none | UTC date or time. |
| `budget` | map | none | `{ usd: <above 0>, per: <period>, tz: <zone> }`. |
| `models` | list | none | Models this key may use, within its rule's. |
| `tpm` | integer | none | Tokens per minute for this key. |
| `parallel` | integer | none | Requests in flight at once for this key. |
| `org` | string | none | Organization, one the policy's `orgs:` lists. |
| `customer` | string | none | End customer of every request with this key. |
| `tags` | list | `[]` | Tags of every request with this key. |
| `role` | string | none | Console role, built in or from the policy's `roles:`. |

How keys are stored:

- A key is `enterplace_` followed by 256 random bits in hex, from the operating system's random source. With no randomness available, no key is made.
- The `enterplace_` prefix lets secret scanners recognize a leaked key.
- Only the SHA-256 is written. The key itself is kept nowhere.
- The file is created with mode `0600`.
- `key new` appends its entry to the end and never rewrites what is there, so a key removed by hand stays removed. It shows the key only after finding its entry in the file. If an editor saved an older copy at the same moment, `key new` says so and makes no key: run it again.
- A list written on one line (`keys: [...]`) is refused with that cause.

## Send a key

A client sends the key in either header:

```text
Authorization: Bearer enterplace_...
x-api-key: enterplace_...
```

Both may be present only if they hold the same value. Two different credentials are refused with `ambiguous_key`. A value starting with `sk-` that identifies nobody is refused with `unknown_key` and a hint that it looks like a provider key.

Enterplace removes the key from every header before forwarding, under any header name, compared without regard to case, with or without the `enterplace_` prefix.

## Revoke a key

<Tabs syncKey="admin">
<TabItem label="Keys file">

Delete the entry from `enterplace.keys.yaml` and save. Enterplace stops accepting the key within 2 seconds.

</TabItem>
<TabItem label="Console">

Revoke the key on the **People and workloads** page. The console saves the file and Enterplace uses the change within 2 seconds.

</TabItem>
<TabItem label="Admin API">

```bash
curl -X DELETE https://enterplace.example.com/admin/keys/41e0a7f3 \
  -H "Authorization: Bearer $ENTERPLACE_ADMIN_KEY"
```

Stops the key at once, because the API reloads the keys file before it answers. `404 no_such_key` if no entry has that prefix, `400 ambiguous_key` if more than one does (send more of the hash).

</TabItem>
</Tabs>

A request with a revoked key is refused with `unknown_key`. Its record holds the first 8 hex characters of the key's hash: enough to tell two unknown keys apart, far too little to recover the key. A request already in flight finishes, stream included.

## Rotate a key

```bash
enterplace key rotate 5d1e4a07 --grace 48h --url https://enterplace.example.com
```

```text
New key for maya.cohen (team payments). It is shown once and is not stored anywhere:

  enterplace_8a41...(64 hex characters)

The old key 5d1e4a07 keeps working until 2026-11-16T09:14:02Z (UTC). Every request made with it until then is recorded with key_rotated, so you can find who still uses it.
```

A rotation makes a new key with the same name, team and settings, and gives the old key `expires` at the end of the grace and `replaced_by` naming the new key. An expiry already earlier stays: a rotation never lengthens a key's life.

- `--grace` takes `90s`, `30m`, `48h` or `7d`, at most `90d`, and `0` to end the old key now. Default `24h`.
- Every request with the old key during the grace carries `"key_rotated": {"replaced_by": "8a41...", "expires": "..."}` on its record. Search for it to find the callers who still have to switch.
- A key already rotated is refused with `already_rotated`: rotate the new one.
- The new key's budget counts from zero, as any new key's does.

The API form is `POST /admin/keys/<prefix>/rotate` with `{"grace": "48h"}`. Without the API, issuing a second key under the same name with `enterplace key new` and revoking the old one later still works.

## Prune expired keys

Expired keys, such as old [`enterplace login`](/governance/single-sign-on/#developer-keys-with-enterplace-login) keys, stay in the file. Serving refuses them with `key_expired`, and `enterplace check` lists each as a warning, so a check in CI keeps passing.

```bash
enterplace key prune --keys enterplace.keys.yaml
```

`key prune` removes every expired entry, each the same safe way `DELETE /admin/keys` removes one, and keeps every other line. It is safe while Enterplace runs.

## Roll out to a team

<Steps>

1. Make the first admin key with `--admin`, on the machine that holds the keys file.

2. Issue each person's key with the admin API in a loop, or `enterplace key new <name> --team <team> --quiet` per person, straight into your secret manager. Or turn on [self-service keys](/governance/single-sign-on/#developer-keys-with-enterplace-login).

3. Give each workload (CI job, agent) its own key with `--expires` and `--budget`.

4. Rotate by issuing a new key under the same name, then revoking the old one once the audit log shows it unused.

</Steps>

## Errors

| Code | Status | Cause |
|---|---|---|
| `no_key` | 401 | The request carries no key. |
| `unknown_key` | 401 | The key was never issued or has been revoked. |
| `ambiguous_key` | 400 | Two different credentials on one request. |
| `key_expired` | 401 | The key's `expires` has passed. |
| `not_admin` | 403 | An admin API call with a key that is not `admin: true`. |
| `no_such_key` | 404 | `<prefix>` matched no entry. |
| `already_rotated` | 409 | A rotation of a key that was already rotated. |
| `route_not_allowed` | 403 | The key's `routes` do not include the request's path. |
| `parallel_limited` | 429 | The key has `parallel` requests in flight already. `Retry-After: 1`. |
| `ip_not_allowed` | 403 | The request came from outside the key's `from`. |
