# Refusal codes

Every refusal has a stable code, a status, a message that names the cause and the fix, and the decision ID. It never contains an address, an internal error or another caller's data.

## Shapes

On `/v1/messages` and `/v1/messages/count_tokens` a refusal uses Anthropic's error shape, so Claude Code and Anthropic's SDKs show the message:

```json
{"type":"error","error":{"type":"permission_error","message":"Refused (model_not_allowed): ... Decision 01M79....."},"enterplace_code":"model_not_allowed","decision":"01M79..."}
```

Everywhere else it uses OpenAI's shape:

```json
{"error":{"message":"Refused (no_key): ... Decision 01M79....","type":"enterplace_error","code":"no_key","decision":"01M79..."}}
```

Headers on every refusal: `X-Enterplace-Decision: <id>` and `x-should-retry: true` or `false`. `busy` also sends `Retry-After: 1`, and `rate_limited` sends `Retry-After` with the seconds to wait.

## Codes

The Anthropic type is the `error.type` used on the messages routes. Retry is the value of `x-should-retry`.

| Code | Status | Anthropic type | Retry | Cause | Fix |
|---|---|---|---|---|---|
| `no_key` | 401 | `authentication_error` | false | No credential, an empty one, `Authorization` that is not `Bearer`, or a header that is not text. | Send the Enterplace key as `Authorization: Bearer enterplace_...` or `x-api-key: enterplace_...`. |
| `ambiguous_key` | 400 | `invalid_request_error` | false | `Authorization` and `x-api-key` hold different values, one of them is empty beside the other (the message names the empty one), or one of them appears twice. | Send exactly one credential: the Enterplace key. |
| `unknown_key` | 401 | `authentication_error` | false | The key's hash is not in the keys file: never issued, or removed. A key added to the file works within 2 seconds. A key starting with `sk-` gets the hint that it looks like a provider key. | Ask an admin for a key. A key just issued works within 2 seconds. Never send a provider key. |
| `key_expired` | 401 | `authentication_error` | false | The key's entry has `expires:` and that UTC date or time has come. The record names whose key it was. | Ask an admin for a new key. |
| `killed` | 403 | `permission_error` | false | A kill switch stops this person, team, key, model or everyone. The message names the switch, the reason, the admin who set it and when. | Ask that admin; it stays until `enterplace unkill`. See [Keys](keys.html#kill-switches). |
| `kills_unreadable` | 503 | `api_error` | false | `enterplace.kills.json` beside the keys file cannot be read, so Enterplace cannot tell whether a switch stops the request. Every request is refused. | Tell the admin: fix the file or delete it (which turns every switch off). |
| `unknown_route` | 404 | `not_found_error` | false | The method and path are not one Enterplace serves. Served: `POST /v1/chat/completions`, `POST /v1/responses`, `POST /v1/embeddings`, `POST /v1/images/generations`, `POST /v1/audio/transcriptions`, `POST /v1/audio/speech`, `POST /v1/moderations`, `POST /v1/rerank`, `POST /v1/messages`, `POST /v1/messages/count_tokens`, `GET /v1/models`, `GET /healthz`. | Check the method and the path. The key is checked first, so an unknown route without a key gets `no_key`. |
| `body_too_large` | 413 | `request_too_large` | false | The body is over 32 MiB, or over the memory one caller may hold at once (64 MiB by default). | Send a smaller request. |
| `body_timeout` | 408 | `invalid_request_error` | false | The body did not arrive within 30 seconds. | Send it again, from a faster link. |
| `busy` | 429 | `rate_limit_error` | true | This caller's requests in flight already hold 64 MiB of request bodies. | Wait for some to finish. `Retry-After: 1`. |
| `busy` | 503 | `overloaded_error` | true | Enterplace holds as many request bodies as its 256 MiB budget allows, across all callers. | Send again in a moment. `Retry-After: 1`. |
| `unreadable_request` | 400 | `invalid_request_error` | false | The body is not a JSON object with exactly one `model` string (a second spelling such as `Model` counts as a second one), or it stopped before it was complete. On `/v1/audio/transcriptions`: the body is not `multipart/form-data` with one boundary and exactly one `model` field, or a part is not plain (an extended `name*=`, spaces around `=`, an escape, a folded header). Under a rule with guardrails, also a text-bearing field of a shape the guardrails do not read (a moderation input item other than a string or `text` item, a non-string image prompt or speech input). | Send a JSON object with one `model` field, or a form with one `model` field. |
| `unreadable_request` | 400 | `invalid_request_error` | false | The body is sent with a `Content-Encoding` other than `identity` (Enterplace checks bodies as plain JSON), or, on a rule with guardrails, an object in it names the same key twice. | Send the body uncompressed, and each key once. |
| `bad_limits` | 400 | `invalid_request_error` | false | A budget or a cache applies, and the body names `model`, `messages`, `system`, `input`, `stream`, `max_tokens`, `max_completion_tokens`, `max_output_tokens` or `n` twice, or gives a token limit that is not a whole number, or `n` that is not a whole number from 1 to 16, or `stream` that is not true, false or null. On a rule that also has guardrails, a key named twice is found first by the guardrails and refused as `unreadable_request` (the row above): both codes mean the same fix. | Send each once, token limits as whole numbers. |
| `stored_context` | 400 | `invalid_request_error` | false | A budget applies to a `/v1/responses` request that names `previous_response_id`, `conversation` or `prompt`: the provider adds stored context Enterplace cannot see, so the most it could cost is unknown. The message names the fields. | Send the whole conversation in `input` (with `store: false`, as Codex does), or ask an admin to set `max_context` for the model under `prices:`. |
| `max_tokens_needed` | 400 | `invalid_request_error` | false | A budget or a tokens-per-minute limit applies, the request states no `max_tokens` (or `max_completion_tokens`, `max_output_tokens`), and the model's price has no `max_output`, so the most it could cost or use is unknown. The message names only the budget that applies (the rule's, the key's, or both) and the field of the route the request came on. An image or speech request to a token-priced model has no such field: its model needs `max_output` (or, for images, `per_image`). | Send `max_tokens` (`max_output_tokens` on `/v1/responses`), or ask an admin to set `max_output` for the model under `prices:`. |
| `no_rule` | 403 | `permission_error` | false | No rule names the caller's name or team. | An admin adds a rule. |
| `model_not_allowed` | 403 | `permission_error` | false | The first rule that names the caller does not list the model. The message names the rule and lists what it allows. Also when the rule allows it and the caller's key has its own `models:` list without it: the message then names the key and its list. | Use an allowed model, or ask an admin to change the policy. |
| `unknown_model` | 403 | `permission_error` | false | The rule allows the model but no provider lists it. 403, not 404: see [Claude Code](claude-code.html). Also, after the record, when an `azure` or `bedrock` provider has no deployment or model ID for it (only possible in a configuration built in code: `enterplace check` refuses it). | Check the model name, or an admin adds it to a provider. |
| `wrong_route` | 400 | `invalid_request_error` | false | The model is served by a provider that speaks the other API. The message names the route to use, and, for a chat request to an `anthropic` or `bedrock` provider, says an admin can set `accept_chat: true` (it translates chat requests only, so it is never offered for Responses or embeddings). Also `count_tokens` for a `bedrock` or `vertex_anthropic` model or a model on a provider with `accept_messages`, a messages request for a chat provider without `accept_messages` (the message says an admin can set it), and a Responses, embeddings, images, audio, moderations or rerank request for a model on a provider not of kind `openai`. | Send chat requests for `openai`, `azure`, `gemini` and `vertex` models to `/v1/chat/completions`, Responses and embeddings requests to `openai` models only, and messages requests for `anthropic` and `bedrock` models to `/v1/messages`. |
| `untranslatable` | 400 | `invalid_request_error` | false | A chat request for a provider with `accept_chat: true` holds a field the messages API has no equivalent for, or a messages request (Claude Code) for a provider with `accept_messages: true` holds one the chat completions API has none for (thinking of type `enabled`, a server tool, a `context_management` edit other than clearing thinking). The message names the field. | Remove the field, or use a model whose provider speaks chat completions. |
| `unknown_query` | 400 | `invalid_request_error` | false | A query parameter the route does not forward, a value it does not take, or a parameter given twice. Allowed: `beta` (`true` or `false`) on the messages routes, `limit` (1 to 1000) on `/v1/models`, none on chat. | Remove the parameter. |
| `guardrail_blocked` | 403 | `permission_error` | false | A guardrail the rule names refused the request, or, for a guardrail with `on: [answer]`, withheld the model's whole answer (the message says "withheld the model's answer"; this one comes after the request was recorded as allowed, and has an `answer_guardrails` record with the same ID). The message names the guardrail and the kinds it found (for example `aws_access_key (1)`) and where (`/messages/0/content`), never the text. A `fail_closed` webhook guardrail that could not check the request refuses it with this code too, and says so. | Remove what was found and send again. For a guardrail service that is down, try later or tell the admin. |
| `rate_limited` | 429 | `rate_limit_error` | true | The caller sent as many requests in the last minute as their rule's `rate: { rpm: N }` allows, or the tokens used in the last minute plus those held by requests in flight plus the most this request could use would pass a `tpm` limit (the rule's, counted per team or person, or the key's). A request that could use more tokens than a whole minute allows is refused without `Retry-After`. | Wait the seconds in `Retry-After`, which the message also says, or send a smaller `max_tokens`. |
| `budget_exceeded` | 429 | `rate_limit_error` | false | Spent plus what requests in flight reserved plus the most this request could cost would pass the rule's `budget`. The message says how much is spent of how much, what requests in flight hold, and when the budget starts again (UTC). | Wait for the period to end, send a request with a smaller `max_tokens`, or ask an admin to raise the budget. |
| `key_budget_exceeded` | 429 | `rate_limit_error` | false | The key has a `budget:` of its own, and its spend plus what its requests in flight reserved plus the most this request could cost would pass it. The message names the key by the first 8 hex characters of its hash. | Wait for the period to end, or ask an admin to raise the key's budget. |
| `no_price` | 403 | `permission_error` | false | Only for a policy built in code: a budgeted rule reached a model with no price. `enterplace check` refuses this in a policy file. | Add the model's price. |
| `audit_unavailable` | 503 | `api_error` | false | The record could not be written: the disk failed, or the log was deleted, moved, replaced or cut short. Every request is refused until restart. | Tell the admin. The admin checks the log file and the server's stderr, then restarts. |
| `upstream_unreachable` | 502 | `api_error` | true | Enterplace could not connect to the provider (5 second connect timeout). | Try again. If it persists, the admin checks the provider URL and network. |
| `upstream_failed` | 502 | `api_error` | true | The provider broke the connection before answering. | Try again. |
| `upstream_timeout` | 504 | `timeout_error` | true | The provider sent nothing for 120 seconds. | Try again, or with a smaller request. |
| `bad_path` | 400 | `invalid_request_error` | false | The path could not be joined to the provider URL. | Check the path. |
| `untranslatable` | 502 | `api_error` | false | After the record: the provider's whole answer to a translated request could not be translated back. | Tell the admin. |
| `no_upstream` | 503 | `api_error` | false | Only with `enterplace serve --unchecked`: `ENTERPLACE_UPSTREAM` is not set. | Set `ENTERPLACE_UPSTREAM` and restart. |

Every refusal before `audit_unavailable` in the table is recorded with its code. A `guardrail_blocked` record also lists what each guardrail found. `audit_unavailable` has no record: that is the problem it reports. The `upstream_*` codes, `bad_path` and the 502 `untranslatable` come after the request was allowed and recorded, so the record says `allow`. With `retries` or a `fallback` on the provider, an `upstream_*` failure, a 429 or a 5xx is tried again before the caller sees it, and an `attempts` record lists every try (see [Providers](providers.html#retries-and-fallbacks)); the caller sees only the last one.

A provider's own error response is not an Enterplace refusal: it passes through unchanged, with `X-Enterplace-Decision` added. Two exceptions keep the caller's error shape: a Bedrock error is put in Anthropic's shape, and an error answer to a translated chat request is put in OpenAI's shape, each with the provider's message.

## Not a refusal

A request the HTTP library itself rejects as malformed gets a bare 400 with no body, no code and no decision ID. A client that takes more than 10 seconds to send its headers is disconnected.
