Use casesCoding agents

Coding agents for every developer, each one under a name and a budget.

Your developers already run Claude Code, Codex, Copilot or Cursor. Most of them share one provider key, or each team bought its own. This page moves them behind Gantry without taking a tool away from anyone.

What goes wrong without control

One key, sixty laptops
The provider key sits in shell profiles. When one laptop is lost, the key is rotated for everyone, and until then it works from anywhere.
An invoice with no names
The provider bills one total per account. An agent that retried all night shows up at the end of the month, and nobody can say whose it was.
Secrets in prompts
A coding agent reads the files around it. A config file with a database password goes into a prompt, and there is no record that it did.
No list of who uses what
Three teams adopted three tools this year. Security is asked which ones, and the answer is a guess.

The steps

Each step is one change. Nothing is blocked until step four, and you can stop after any step and keep what you have.

  1. Run Gantry in observe mode

    Install it and run gantry start. No provider key is needed: it writes a policy with one rule that allows everyone, a free demo model and Claude subscription passthrough, and opens the dashboard, whose Start here checklist shows the exact settings for each coding tool.

    Step 1 in the docs

  2. Point each tool at the gateway

    A coding tool goes through Gantry when it lets you set a base URL. Claude Code on a Claude subscription needs one line and keeps its own login. On API billing it takes a Gantry key in place of the provider's, which never reaches the laptop.

    A guide for each tool

  3. Give each developer their own key

    Issue a key per person, or let developers sign in with the company account. gantry login opens the browser, and the key it stores is named by their email and expires on the schedule you set.

    Single sign-on in the docs

  4. Set a budget per team and per person

    In observe mode a request over the budget is forwarded and recorded as would_refuse, so you see what the numbers would do. Delete mode: observe to enforce them.

    Budgets in the docs

  5. Stop secrets on trial, then for real

    Until the date, the guardrail records what it finds and blocks nothing. From that date a prompt that holds an API key, a private key or a database password is refused with guardrail_blocked.

    Guardrails in the docs

What you see afterwards

  • The console's Analytics page ranks requests, tokens and cost by coding agent, person, team or model.
  • gantry audit coverage lists each person and the tool they used, and names the people who hold a key and have sent nothing.
  • A refused developer reads the reason in the terminal they already use, with a decision ID an admin can look up.
  • A coding session stays on one deployment while it answers, so the provider's prompt cache keeps working.

Limits to know before you start

  • Gantry sees what is sent through it. A tool that still calls a provider directly stays invisible until you point it at the gateway. The coverage report shows who holds a key and has sent nothing.
  • On Claude subscriptions, limits are in tokens and requests. Claude Code on Pro, Max, Team or Enterprise seats goes through Gantry on its own login, with no API key. The seat is billed by Anthropic, so dollar figures there are estimates. Where nothing may be routed, a watch setup reads Claude Code's own usage data and does not block. Claude Team and Enterprise
  • Some tools have no setting for a gateway of your own. Windsurf, Amazon Q Developer and Kiro document no custom model endpoint, so they cannot be sent through Gantry.
  • Parts of some tools stay outside. Cursor's tab completion and Copilot's inline suggestions do not use the endpoint you configure. The table above lists what each tool sends elsewhere.

Questions people ask

Does a developer have to change how they work?

They change two settings once, or run gantry login. After that the tool behaves as before. A refusal arrives in the error shape the tool already shows, with the cause and what to do.

Can different teams get different models?

Yes. A rule names the people or team it applies to and the models they may use. The first rule that names the person decides. The policy file

What happens when a key leaks?

Revoke that one key in the console or with the admin API, and it stops at once. Nobody else is touched, because the provider's key never left the gateway. A kill switch stops a person, a team or a model with one command.

Does Gantry store our code?

No. The audit log holds who asked, the model, the decision and the cost. It holds no prompt or answer text.
