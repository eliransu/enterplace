Use casesRegulated data and residency

Keep requests in the region you chose, and keep the record that shows it.

Some teams handle patient, customer or financial data. Their requests may only go to endpoints you have an agreement with, personal data must not leave in a prompt, and someone will ask you to show both.

What goes wrong without control

The region is a habit
People are told to use the EU endpoint. A fallback, a new SDK default or a copied config sends a request somewhere else, and nothing refuses it.
Personal data in prompts
A note pasted into a prompt holds an email address, a phone number and a record number. It reaches the provider as written.
No evidence
An auditor asks who used which model last quarter and how you know the list is complete. The provider's dashboard does not answer either part.
A gateway that is itself a new processor
A hosted gateway sees every prompt. For regulated data that adds a vendor to the review before the first request.

The steps

Gantry runs in your own cloud account, so prompts go from your callers to the providers your policy names and nowhere else.

  1. Run it in your own account and region

    The Terraform modules put the gateway, Postgres and the audit volume in an account and region you pick. Gantry never stores prompts or answers: not in the audit log and not in Postgres.

    Deploy

  2. Label deployments and name the allowed regions

    An alias serves one model name from several deployments. Label each one with its region. A rule with regions: [eu] reaches only those. A request with nowhere allowed to go is refused with region_not_allowed. It is never sent elsewhere, even when every allowed deployment is failing.

    Residency in the docs

  3. Mask personal data and your own identifiers

    The pii detector finds email addresses, phone numbers, card numbers and similar. mask replaces each finding and forwards the rest. A regex guardrail does the same for identifiers only you know, such as a record number.

    Guardrails in the docs

  4. Keep the record, and check it

    Put the audit log on storage that outlives the container and verify its chain. Copy the last hash somewhere the Gantry host cannot write. Each record carries the regions the rule allows and the region the request went to.

    Step 5 in the docs

  5. Add export, retention and legal hold Enterprise

    Gantry Enterprise sends every record to Splunk, Datadog, Elasticsearch, Microsoft Sentinel or object storage as it is written. Retention deletes records older than a set number of days while the chain stays verifiable, and a legal hold stops all deletion until an owner lifts it. In the open source edition you ship the audit file with Vector, Fluent Bit or the OpenTelemetry Collector.

    Retention and legal hold

Limits to know before you start

  • The region label is yours to set. Gantry enforces it exactly. It does not check where a provider runs. Label a deployment with the region of the endpoint and the data processing terms you have with that provider.
  • Built-in guardrails match plain text. Text that is encoded, split across messages or translated is not found, and the detectors do not find names or street addresses. Add a vendor guardrail or your own service by webhook for those.
  • Gantry holds no compliance certification and has not yet had an independent security audit. It gives you controls and a record. Your compliance program decides whether they are enough.
  • Anyone who can write the audit file can rewrite the chain. The last hash kept somewhere else is what catches that.

Questions people ask

Does the audit log itself hold personal data?

It holds the person or workload that asked, the team, the model, the decision and the cost. It holds no prompt text, no answer text and never the text a guardrail matched.

Can we see what a guardrail would do before it changes anything?

Yes. Give it a shadow_until date and it records findings and changes nothing until then. You can also run it over a file of example prompts with gantry guardrail test.

What about models that are not behind an alias?

A model that is not an alias has no region label, so where it runs cannot be shown. Under a rule with regions, a request for it is refused.
