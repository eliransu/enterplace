Use casesClaude Team and Enterprise

Every Claude Code user in your organization, with one paste in claude.ai.

On Claude Team or Enterprise, an Owner can push settings to every Claude Code install from claude.ai. Paste the block Enterplace prints, and Claude Code reports who used it, on which model, with how many tokens, to a gateway you run. Nothing is installed on laptops and nobody changes their login.

Where it goes

claude.ai, Organization settings, Claude Code, Managed settings. Paste and save. Claude Code fetches it at its next start and checks again every hour. Each developer approves the telemetry endpoint once.

On Team the block applies to the whole organization. On Enterprise each group of members can get its own block, counted under its own Enterplace team.

The steps

Three steps, done once by an admin. Developers do nothing.

  1. Run Enterplace where laptops can reach it

    Claude Code sends its telemetry to the address in the block, so the gateway needs an HTTPS address your developers reach, not 127.0.0.1. Watch mode keeps its data in a store and is part of Enterplace Enterprise.

    Docker, Kubernetes and the clouds

  2. Make a watch token

    The command prints the managed settings block with the token in it. The token is shown once. --team names the Enterplace team people are counted under. The console's Start here page does the same with a button.

    Watch mode in the docs

  3. Paste it into claude.ai

    As an Owner or Primary Owner, paste the block into Managed settings and save. Within a few minutes of each developer's next session, they show on the console's Watch page, told apart by the email they signed in to Claude with.

What you see afterwards

  • Who used Claude Code, when and on which model, per person and team.
  • Tokens by type and Claude Code's own cost estimate at list price. Seats are not billed per dollar, so read it as relative usage.
  • Tool calls accepted, rejected and failed, lines changed, commits, pull requests and sessions.
  • The same data in the console's Requests and Usage pages, coverage, alerts, SIEM export and the audit chain, as source watch.

When you want to enforce, not only watch

Watch mode observes: Claude Code still talks to Anthropic directly, so nothing can be blocked. To add rules, kill switches and token limits, route Claude Code through Enterplace on the same seats. Enterplace passes each person's Claude login to Anthropic unchanged, so nobody needs an API key, and the same managed settings block can hold both.

Claude subscriptions through Enterplace

Limits to know before you start

  • Watch mode blocks nothing. Budgets, guardrails and kill switches need requests through Enterplace.
  • Server-managed settings reach Claude logins only. Developers on an API key, Amazon Bedrock or Vertex AI need the same block as a managed settings file on the machine, delivered by your device management. Device deployment
  • Routing skips the Claude desktop app's Code tab. It sets its own base URL, so those sessions go to Anthropic directly. Claude Code in a terminal and in VS Code is routed.
  • A routed request needs a person token to carry a name. One block for the whole organization cannot hold one per person, so routed requests show as unknown until each developer adds their token. Watch data names people by their Claude email either way.

Questions people ask

Does Enterplace see our prompts or code?

Not in watch mode. Claude Code's telemetry holds usage counts and events, and Enterplace keeps no prompt or answer text.

Does any of this go to Enterplace the company?

No. Claude Code sends the telemetry only to the address in the block, which is your own gateway.

Can we start with one team?

On Enterprise, give one group of members its own block and token as a pilot. On Team the block applies to everyone, so pilot with one developer's ~/.claude/settings.json first.
