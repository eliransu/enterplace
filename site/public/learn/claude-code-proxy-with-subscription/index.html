Claude Code through a gateway, on a subscription login

Most proxy guides for Claude Code start with "create an API key". Teams on Claude seats do not want one. This page shows the setup where each developer keeps the Claude login they already have.

How it works The setup Say who is calling Roll it out When it does not work What it does not do

How it works

Claude Code sends every request to the address in ANTHROPIC_BASE_URL. On a subscription, each request carries the developer's own Claude login in the Authorization header.

A gateway can handle that login in two ways. It can swap it for an API key the gateway holds, which moves the team from seats to per-request billing. Or it can pass the login through unchanged, so Anthropic sees the same request it would have seen without a gateway. This page is about the second way.

Enterplace calls it subscription passthrough. The login is taken off the request before any check reads it, sent to Anthropic and to nothing else, and never stored, logged or hashed into a record.

Say who is calling

The Claude login goes to Anthropic, so the gateway needs its own way to know the person. That is a second header, which Claude Code sends from ANTHROPIC_CUSTOM_HEADERS.

The value is a person token. It names the person and their team and reaches no model on its own, so a leaked token gives nobody model access. An admin makes one in the console or with enterplace key new maya.cohen --team payments --identity-only. With single sign-on, enterplace login writes both lines for the developer.

Roll it out to every laptop

Claude Code reads the same env block from its managed settings file, which an MDM such as Jamf or Intune can place on each machine.

  • macOS: /Library/Application Support/ClaudeCode/managed-settings.json
  • Linux and WSL: /etc/claude-code/managed-settings.json
  • Windows: C:\Program Files\ClaudeCode\managed-settings.json

When it does not work

What you seeCauseFix
Requests never reach the gatewayThe session runs in the Code tab of the Claude desktop app, which sets ANTHROPIC_BASE_URL itselfUse the terminal or the VS Code extension. Check with echo $ANTHROPIC_BASE_URL inside a session
Claude Code asks for, or bills, an API keyANTHROPIC_API_KEY or ANTHROPIC_AUTH_TOKEN is set somewhereUnset both, in the shell profile and in settings files, then sign in with /login
403 person_neededThe provider has identity: required and the request has no person headerAdd the person token, or set identity: optional while you roll out
403 person_token_onlyThe person token was sent as the only credentialKeep the Claude login; the token goes in ANTHROPIC_CUSTOM_HEADERS, not in ANTHROPIC_API_KEY
403 login_not_acceptedThe model is served only by a provider that takes an API keyList the model on the passthrough provider

Claude Code labels any 403 "Failed to authenticate". The text after that label is the gateway's own message, and it names the cause.

What it does not do

  • It does not change your plan's allowance. The seat's own limits at Anthropic stay as they are. A gateway can add stricter limits of its own, in tokens and requests per person.
  • It does not give real dollar figures. A seat is paid by the month. Cost is shown as an estimate at API list prices.
  • It does not settle the terms question for you. Check that routing your plan's traffic through your own gateway fits Anthropic's terms for that plan.
