What is an AI gateway?

An AI gateway is one program that sits between your company's AI tools and the model providers. Every request passes through it, so it is the one place where you can see what is happening and apply your rules.

The picture

Today each AI tool in your company talks to a provider on its own. A developer's coding agent calls Anthropic. A support bot calls OpenAI. A script someone wrote last spring calls a model on AWS. Each one holds a key, and nobody has one place to look.

A gateway changes one thing: the tools send their requests to the gateway, and the gateway sends them on.

What it can do, because it sits there

A gateway is useful only because of where it sits. Five jobs follow from that position.

  • See. It can count every request: which tool, which model, how many tokens, what it cost.
  • Name. It gives each person and each service their own key, so a request has a name on it. The provider's key never reaches a laptop.
  • Limit. It can refuse a request: the wrong model for this team, a budget that is spent, too many requests in a minute.
  • Check. It can look at the prompt before it leaves and stop one that holds a password or mask a card number.
  • Record. It can write down each decision, so that later you can show what happened.

Most gateways also do the plumbing: one API in front of several providers, retries when a provider fails, a fallback to a second provider, a cache for repeated questions.

An example

Dana is an intern. She runs a coding agent on a long task, and by the afternoon she has used her daily budget of 20 dollars.

Without a gateway, the agent keeps going. The cost appears on next month's invoice, inside a total.

With a gateway, her next request is refused. Her terminal shows a message that says the daily budget is spent and when it starts again. The gateway writes a record: who, which model, refused, why. Her team lead can raise the number if the work needs it.

What an AI gateway is not

  • It is not a model. It answers nothing itself. It passes requests to the providers you already use.
  • It does not see everything. It sees the requests that are sent through it. A tool that still calls a provider directly is invisible to it.
  • It is not a replacement for security review. A check for secrets in prompts catches a pasted password. It does not decide whether a tool should have been allowed to read that file.
  • It is not the same as an API gateway. An API gateway manages traffic to your own services. An AI gateway understands model requests: tokens, prices, prompts, tool calls.

Do you need one?

You probably do not need one if three people use one AI tool and the bill is small. You probably do if any of these is true:

  • More than one team uses AI tools, and no one keeps the list.
  • A provider key is shared by more people than you can name.
  • Finance has asked who spent the AI budget and got an estimate.
  • Security or a customer has asked what data goes into prompts.
  • Agents call tools that change systems: merge code, run a deploy, write to the warehouse.
