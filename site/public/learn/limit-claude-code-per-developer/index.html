How to set a daily limit per developer on Claude Code

An agent left running overnight can use a week of budget before anyone looks. Claude Code has no setting for "this person, this much per day". A gateway in front of it does. This page shows the lines.

Where a limit can live On subscription seats On API keys Try it before it blocks What the developer sees The stop button

Where a limit can live

A limit per person needs something that counts each person's requests as they happen. Claude Code talks to Anthropic directly, so by default nothing of yours sits there. Point Claude Code at a gateway with ANTHROPIC_BASE_URL, give each developer a name on their requests, and the gateway can count and refuse. The setup is on Claude Code through a gateway.

The examples below are Enterplace policy. The limits are checked when a request is admitted.

On subscription seats: limit tokens and requests

A seat is paid by the month, so a dollar budget has nothing real to count. Tokens are what a subscription is metered in. Limit those.

tpd counts prompt and answer tokens per calendar day, UTC. A request is admitted while the day's count is under the limit and counted with what its answer used, so one request may end above the number. The next one is refused until midnight UTC.

To limit seats in dollars anyway, at the API list price estimate, add budget_basis: api_equivalent to the rule next to a budget.

This does not change the seat's own allowance at Anthropic. It adds a stricter limit of yours in front of it.

On API keys: limit dollars

A budget reserves the most a request could cost before it is sent, and gives back the difference when the answer ends. Claude Code asks for a large max_tokens on every request, so each one reserves far more than it usually spends, and a small budget can refuse requests that would have fitted. Two fixes:

  • Run export CLAUDE_CODE_MAX_OUTPUT_TOKENS=8000 before claude, so each request reserves less.
  • Size the budget for the reserve of several requests in flight, not for the average spend.

Try it before it blocks anyone

A limit you guessed will be wrong for someone. Two ways to see what a number would do first:

  • Observe mode. With mode: observe at the top of the policy, nothing is refused. A request over a limit is forwarded and recorded as would_refuse.
  • A trial date on one limit. shadow_until: 2026-12-15 on a budget or a limits: entry does the same for that limit alone, and it starts enforcing on the date.

After a week, the records show who would have been stopped and how often. Raise the number for the people whose work needs it, then enforce.

What the developer sees

A refusal uses Anthropic's error shape, so Claude Code prints the gateway's own message in the terminal: the limit, the scope it belongs to and when it starts again. A token or request limit also sets Retry-After.

The stop button

A limit handles the slow case. For the fast one, a runaway agent at two in the morning, a kill switch stops a person, a team, a key or a model at once, with no policy change, and lifts the same way.
