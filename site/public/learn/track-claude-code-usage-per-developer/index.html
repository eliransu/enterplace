How to track Claude Code usage per developer

A team on Claude Code gets one bill, or one seat count. This page lists the three ways to break it down by person, what each one shows, and the settings for each.

The short answer 1. Your plan's admin pages 2. Claude Code telemetry 3. A gateway Side by side Two catches

The short answer

There are three places the numbers can come from. Pick by what you need to do with them.

  • You only want totals per seat. Start with the admin pages of your Claude plan. Nothing to install.
  • You want tokens, models and tools per person, and nothing may sit in the request path. Turn on Claude Code's own telemetry and send it to a collector.
  • You also want to set limits, stop secrets in prompts or keep an audit record. Route Claude Code through a gateway. Developers keep their Claude subscription login.

1. Your plan's admin pages

Claude Team and Enterprise plans have admin pages, and an API account has a usage page per key. Look there first, because it costs nothing. What you get depends on the plan, and it is a view inside the vendor's product: you cannot join it with your other AI tools, set your own limits per person from it, or export a record you control.

2. Claude Code's own telemetry

Claude Code can send usage telemetry over OpenTelemetry to an address you choose. It reports who used it, the model, tokens by type, an estimated cost, which tools ran or were rejected, and counts such as lines changed and commits. Requests still go straight to Anthropic, so nothing can be refused or changed.

Any OpenTelemetry collector takes this. You then need somewhere to store it and a dashboard that groups by person. On Claude Team, an owner can paste the block once under Organization settings, Claude Code, Managed settings, and every seat picks it up at its next start.

Enterplace can be that collector: its watch mode takes the same telemetry and shows it per person, team and model next to the rest of your AI traffic. Watch mode is part of Enterplace Enterprise. Watch mode in the docs

3. A gateway in the request path

Claude Code sends its requests to whatever ANTHROPIC_BASE_URL names. Point it at a gateway you run, and the gateway sees every request before it goes to Anthropic: the person, the model, the tokens Anthropic reports back.

With Enterplace this works on Claude subscriptions. Claude Code keeps its own login, Enterplace passes that login to Anthropic unchanged and never stores it, and a person token in a header says who sent the request. Nobody needs an API key. This part is open source.

Leave ANTHROPIC_API_KEY and ANTHROPIC_AUTH_TOKEN unset: with either set, Claude Code stops using the subscription. You can also start with the first line only. Requests then arrive under the person unknown, told apart by session, and you hand out person tokens later.

The console's Requests and Usage pages then rank requests, tokens and cost by person, team, model and coding agent. Claude Code setup in the docs

Two catches worth knowing

  • Cost on a subscription is an estimate. A seat is paid by the month, not by the request. Telemetry and gateways price the tokens at the API list price. Read the figure as relative usage between people, not as an invoice.
  • The desktop app's Code tab does not follow the setting. The Code tab of the Claude desktop app sets ANTHROPIC_BASE_URL itself, so its sessions never reach a gateway. The terminal and the VS Code extension do follow it. Run echo $ANTHROPIC_BASE_URL inside a session to check.

Before you route a plan's traffic through your own gateway, check that it fits Anthropic's terms for that plan.
