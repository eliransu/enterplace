Get started

Every request is identified, decided and recorded before it leaves.

Enterplace is a reverse proxy with a fixed order of checks. Your tools send requests to it, and it sends them on to the provider. A request that cannot be recorded is refused.

The request path

Twelve stages, always in this order. Pick an outcome and watch where the request stops and what the caller reads.

  1. 1 identifyLook up the key's SHA-256
  2. 2 routeIs this a method and path Enterplace serves?
  3. 3 read bodyWithin the size, time and memory limits
  4. 4 decideThe first rule that names the person or team, and any kill switch
  5. 5 providerThe one provider that lists the model
  6. 6 queryOnly parameters the route allows
  7. 7 guardrailsBuilt-in detectors first, then vendors and webhooks
  8. 8 cacheAn identical request answered from the rule's cache
  9. 9 rateRequests and tokens per minute
  10. 10 budgetReserve the most the request could cost
  11. 11 recordOne audit line, chained to the one before
  12. 12 forwardProvider key in, caller key out, retries and fallback

Allowed: forwarded to the provider

The record is written first. The provider's key replaces the caller's, and the answer comes back as the provider sent it. A second record follows with tokens and cost.

A refusal uses the error shape the client already understands (Anthropic's, OpenAI's or Google's), so coding agents and SDKs show the cause to the person. Every refusal code

Messages are shortened here. Stage 11 runs for every request, including the ones refused earlier. The request path in the docs

The controls

Each one is a few lines in the policy file or one page in the console, and each can run on trial before it refuses anything.

Identity
A Enterplace key per person and per workload, shown once and stored as a SHA-256 hash. enterplace login gives a developer an expiring key through your identity provider. Services can send JWTs from a trusted issuer. Keys
Budgets and rate limits
Dollars, requests per minute, tokens per minute and requests in flight, per organization, team, person, key, customer, tag or model. Shared by every replica on one Postgres store. Budgets and rate limits
Guardrails
Built-in detectors for secrets and personal data that block, mask or warn. Your own patterns and word lists. Vendor guardrails and your own service by webhook. On requests, answers and MCP tool calls. Guardrails
Kill switches
Stop a person, a team, a key, a model or everyone, with a reason the caller sees. Kill switches
MCP gateway
Your MCP servers behind one endpoint. Each rule lists the tools its people may see. Named tools wait for an admin's approval. MCP gateway
Routing
One model name over several deployments, with retries, fallbacks, a circuit breaker per deployment, and rules that keep requests in the regions you allow. Routing and residency
Observe mode and shadow dates
In observe mode nothing is blocked and every would-be refusal is recorded. A single limit or guardrail can also run on trial until a date you set. Observe mode

One policy file

Providers, rules, budgets and guardrails live in one YAML file you keep in git and review like code. Enterplace picks up a saved file within 2 seconds, without a restart.

enterplace check validates the file in CI. An unknown field is an error with its line, and the message names the cause and the fix:

A change that fails the check is not applied. Enterplace keeps the version it has and records the rejection in the audit log.

The policy file in the docs

The audit log

One JSON record per request, allowed or refused, written before the request is forwarded. Every record carries the hash of the one before it, so a changed, removed or reordered record breaks the chain at that record.

  • A record holds who asked, the model, the decision, the rule behind it and the cost. It holds no prompt text, no answer text and no keys.
  • If the log cannot be written, every request is refused with audit_unavailable.
  • enterplace audit verify checks the chain. The console has a Verify button that runs the same check.

The limit. Anyone who can write the audit file can rewrite the whole chain consistently. Keep the last hash where the Enterplace host cannot write, and check it later with --expect-last.
