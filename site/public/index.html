Self-hosted AI gateway, open source core

Every AI request, on the record.

Gantry runs in your cloud, between your people and the model providers and MCP servers they call. It knows who sent each request, decides by your policy, and writes a tamper-evident record before anything leaves. One Docker image and Postgres.

How it works

Four steps. Every request. No exceptions.

The same fixed order for every call, from a developer's laptop, a production agent or an MCP tool call. A request that cannot be recorded never leaves.

01

Identify

Each person and workload holds its own Gantry key. The provider's key stays inside the gateway and never reaches a laptop.

Authorization: Bearer gantry_8f2c...
→ maya.cohen, team payments
02

Decide

The first rule that names the caller decides: which models and MCP tools, what budget, how many requests at once, which guardrails, and which tool calls wait for an admin.

- name: payments-team
  principals: { team: payments }
  models: [claude-sonnet-5-5, claude-haiku-5-5]
  budget: { usd: 2000, per: month, tz: Asia/Jerusalem }
  parallel: 20
  guardrails: [no-secrets, mask-pii]
  tools: [github.*]
  approve_tools: [github.merge_pull_request]
03

Record

One line in a hash-chained log, written before anything is forwarded. Refusals are recorded too. If the line cannot be written, the request is refused.

{"seq": 119, "person": "maya.cohen", "verdict": "allow",
 "prev": "6b86b273ff34", "hash": "d4735e3a265e"}
04

Forward

The caller's key comes out, the provider's key goes in. The deployment is picked by latency, cost or region, with retries and a fallback if the first one fails. The answer comes back as the provider sent it.

AnthropicOpenAIAzure OpenAIAmazon BedrockVertex AIGeminiLocal models

Proof you can check yourself.

Each record carries the hash of the one before it. Change, insert or reorder a line and the chain breaks at that exact record. The console checks every row of its request log against the chain the same way.

Controls

What the gateway decides, and what it keeps.

Each control below is a line of policy or a page in the console, and each decision it makes is a record in the same hash-chained log.

Guardrails

  • Built-in detectors for secrets and personal data, plus your own regex patterns and keyword lists. Block, mask or record, on requests and answers.
  • Shadow mode runs a new guardrail until a date you set and records what it would have stopped. Backtest one against a corpus of your examples for precision and recall before it enforces anything.
  • Eight vendors built in, among them Lakera Guard, Presidio, Bedrock guardrails, Azure Content Safety and Google Model Armor, or any service of your own by webhook.
  • Guardrails in the docs

MCP gateway

  • Your MCP servers behind one endpoint. Each person sees only the tools, prompts and resources their rule allows, and signs in with their key or by OAuth from the client.
  • Guardrails run on tool calls. Tools you name wait for an admin to approve each call.
  • Every tool is pinned by a hash of its description and schema. A changed tool can be held until an admin approves it, and any tool can be stopped with a kill switch.
  • A server can run each call with the person's own credential, sealed under your master key.
  • MCP gateway in the docs

Spend and limits

  • Budgets on any scope: organization, team, person, key, end customer, tag, model or the whole install. Periods from a minute to a year, in your time zone.
  • Requests and tokens per minute and requests in flight, exact across every replica on one Postgres store.
  • gantry explain shows which rule decided, every limit that applied, and the entries it overrode.
  • Answer cache scoped to a person or a team, with semantic matching, and Anthropic prompt caching marked for you. Savings are counted per team.
  • Budgets in the docs

Policy changes

  • Edit providers, models, prices, rules and keys in the console. Each save is a new policy version, checked like gantry check checks a file.
  • A second admin approves a version after reading its diff and a dry run against this gateway's recent requests. Any earlier version is one click away.
  • Or keep git as the source: the console stays read only for policy and CI runs gantry check.

Request log

  • Search every request by person, team, key, model, provider, outcome, cost and latency. Each row is checked against the audit chain.
  • Analytics with p50, p95 and p99 latency, and a forecast for each budget: whether it lasts the period, or when it runs out.
  • A rule can keep redacted request and answer bodies, sealed apart from the log, readable only by the people it names. Every read is recorded first.

Access

  • Keys per person and workload, updated or rotated with a grace period for the old key. Allowed networks per key and per rule.
  • JWTs from your identity provider in place of Gantry keys, single sign-on for the console, SCIM, and console roles you define.
  • Provider keys sealed in the store under your master key. A caller may send their own provider key only on rules that allow it.

APIs and routing

  • Chat completions, Responses, messages, embeddings and completions, plus OpenAI files, batches and fine-tuning, Anthropic message batches, OpenAI Realtime and Gemini Live. Each file, batch and job belongs to the person who made it, and every batch line is checked.
  • Lowest latency or lowest cost across deployments, requests kept in the regions a rule allows, and a coding agent's session kept on one deployment.

Alerts and export

  • Alerts to Slack, Teams, PagerDuty, email or a signed webhook, on spend, unusual spend, rate limits, refusals, provider errors, latency, guardrail blocks, kill switches, a key on a new address, and use after hours.
  • Audit export to Splunk, Datadog, Elastic, Sentinel, S3, Google Cloud Storage and Azure Blob. Every batch carries the hash range it holds, so the SIEM can check its copy.
  • Traces over OTLP, Langfuse, or an HTTP callback, with prompt text only when you turn it on, redacted.

Runs in your cloud

  • One Docker image and Postgres. Docker Compose, a Helm chart, and Terraform for AWS ECS, Google Cloud Run and Azure Container Apps.
  • Cloudflare Containers, with each gateway's audit chain kept in R2.
  • Readiness on /readyz and a drain on shutdown that finishes requests in flight and writes every record.
  • Deployment guides

Claude Code

Roll out Claude Code without losing track of it.

Two environment variables per developer. Every session goes through Gantry, under their own name, inside their team's budget. When something is refused, they see why in the terminal they already use. gantry audit coverage lists who sent requests from which tool, and which key holders sent nothing.

export ANTHROPIC_BASE_URL=https://gantry.internal
export ANTHROPIC_API_KEY=gantry_...

Open source

Apache 2.0, for any number of people. One binary on files, or several replicas on Postgres.

  • Keys per person and workload, policy as code, kill switches
  • Hash-chained audit log with a command that verifies it
  • Guardrails, MCP gateway, budgets, rate limits and caching
  • Every major provider, with routing, retries and fallbacks
  • Admin console with single sign-on

Gantry Enterprise

The same gateway in one image, with features a signed license key turns on. The key is checked offline and nothing calls home. A lapsed license never stops model traffic.

  • Console members and SCIM from Okta or Microsoft Entra ID
  • Alerts, SIEM export and LLM observability destinations
  • Audit retention with a legal hold
  • Compose, Helm, Terraform and Cloudflare deployment templates
