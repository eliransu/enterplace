How it works

Four steps. Every request. No exceptions.

The same fixed order for every call, from a developer's laptop or a production agent. A request that cannot be recorded never leaves.

01

Identify

Each person and workload holds its own Gantry key. The provider's key stays inside the gateway and never reaches a laptop.

Authorization: Bearer gantry_8f2c...
→ maya.cohen, team payments
02

Decide

The first rule that names the caller decides: which models, what budget, how many requests a minute, which guardrails.

- name: payments-team
  principals: { team: payments }
  models: [claude-sonnet-5-5, claude-haiku-5-5]
  budget: { usd: 2000, per: month }
  guardrails: [no-secrets, mask-pii]
03

Record

One line in a hash-chained log, written before anything is forwarded. Refusals are recorded too. If the line cannot be written, the request is refused.

{"seq": 119, "person": "maya.cohen", "verdict": "allow",
 "prev": "6b86b273ff34", "hash": "d4735e3a265e"}
04

Forward

The caller's key comes out, the provider's key goes in. Retries and a fallback provider if the first one fails. The answer comes back as the provider sent it.

Proof you can check yourself.

Each record carries the hash of the one before it. Change, insert or reorder a line and the chain breaks at that exact record.

Claude Code

Roll out Claude Code without losing track of it.

Two environment variables per developer. Every session goes through Gantry, under their own name, inside their team's budget. When something is refused, they see why in the terminal they already use.

export ANTHROPIC_BASE_URL=https://gantry.internal
export ANTHROPIC_API_KEY=gantry_...
claude
> refactor the invoice parser and add tests

Open source

Apache 2.0, for any number of people. One binary, no database.

  • Keys per person and workload, with expiry and budgets
  • Policy as code, checked before it loads
  • Hash-chained audit log and a verify command
  • Guardrails on requests and answers
  • Every major provider, with retries and fallbacks
  • Admin console with single sign-on
