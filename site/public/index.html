One file. Every rule.

Which providers, which models, and who may use them. One file your team reviews like code, and gantry check names every mistake with its line.

gantry.policy.yamlRefusedline 13
1# Who may use which model.
2version: 1
3providers:
4 - name: anthropic
5 kind: anthropic
6 url: https://api.anthropic.com
7 key_env: ANTHROPIC_PROVIDER_KEY
8 models: [claude-sonnet-5-5, claude-haiku-5-5]
9rules:
10 - name: payments-team
11 principals: { team: payments }
12 models: [claude-sonnet-5-5, claude-haiku-5-5]
13 - name: everyone-else
14 principals: { any: true }
15 models: []

Rules are read in order and the first that names the caller decides. A rule can also name guardrails, and set a budget in dollars, a rate limit and a cache.

Line 4, where
A provider, the API it speaks and the exact models it serves. Its key stays in an environment variable.
Line 11, who
A team, a person or a workload, or anyone. No anonymous requests.
Line 12, what
The models this team may reach. Anything else is refused with a reason.
Line 13, everyone else
This rule refused the request above. The record names the rule and its line.

Check the file, make a key, serve

One binary and no database. Build it from source, or build the container image: one static binary, 9.1 MB, not root.

It is shown once and is not stored anywhere.$ export ANTHROPIC_PROVIDER_KEY=...$ gantry serve gantry.policy.yamlgantry 0.0.1 listening on http://127.0.0.1:8080

What each one does

gantry check
Names the file, the line and the word for every mistake, before anything runs.
gantry key new
Prints a key once. Gantry keeps only its hash.
gantry serve
Identifies, checks and records every request, then forwards it with the provider's key.
gantry audit verify
Proves the log is one unbroken chain, and prints the last hash to keep elsewhere.
