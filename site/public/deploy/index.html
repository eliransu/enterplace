Get started

One image plus Postgres, in your own cloud.

Gantry runs in your network or cloud account. Prompts go from your callers, through the gateway, to the providers your policy names. Gantry never stores them, and the license is checked without a network call.

Open the deploy guides Try it on one machine first

Pick where it runs

Each guide goes from nothing to a gateway that answers governed requests, with the console signed in and the audit log verified.

Docker ComposeThe gateway and Postgres on one machine. The shortest path to a real deployment. KubernetesA Helm chart with autoscaling and a disruption budget, for one or more replicas on a shared Postgres store. AWSTerraform for ECS, RDS and EFS. Bedrock is reached as the task role, with no provider key. Google CloudTerraform for Cloud Run, Cloud SQL and Filestore. Vertex AI is reached as the service account. AzureTerraform for Container Apps, Azure Database for PostgreSQL and Azure Files. CloudflareContainers, with the audit chain sealed into R2.

The guides use the Gantry Enterprise image with its Compose stack, Helm chart and Terraform modules. Enterprise Without a license the same image runs the open source edition.

What you deploy

Seven parts. The last two are optional.

PartWhat it isWhere it lives
The imageghcr.io/eliransu/gantry: one static binary, built from scratch, running as user 65532. It serves the gateway, the console and the admin API.Your registry, or ghcr.io
PostgresThe store: keys, kill switches and spend, shared by every replica.A managed database, or the Compose container
A volume per replicaThat replica's hash-chained audit log. Two replicas never share one, because each writes its own chain.A Docker volume, a PersistentVolumeClaim, EFS, Filestore or Azure Files
The policyOne YAML file: providers, rules, guardrails. It holds no secrets.Version control, then a ConfigMap, a parameter or a mount
Provider keysOne environment variable per provider, named by the policy.Your secret store
The license key, optionalOne line of text. It unlocks the Enterprise features and is checked offline.Your secret store
The master key, optionalSeals provider credentials kept in the store with AES-256-GCM. A lost one cannot be recovered.Your secret store

What stays in your network

Prompts and answers
Go to the provider your policy names and back to the caller. Never stored: not in the audit log, not in Postgres.
Provider keys
Read from environment variables and sent only to their provider.
Gantry keys
Shown once when issued. Only the SHA-256 is stored.
The audit log
On your volume. You ship it where you choose.
The license
Checked against a public key in the binary. No network call.

Limits to know before you start

  • Gantry serves plain HTTP unless you give it a certificate. Start it with --tls-cert and --tls-key, or put TLS in front of it, before traffic leaves one machine.
  • On Cloud Run and Container Apps, one replica. More than one replica on those two is planned. Kubernetes and ECS run several.
  • Pin the version. latest is for a first try. A moving tag makes a rollback guesswork.
  • Releases are signed. Images ship with an SBOM and provenance. Verify a release
