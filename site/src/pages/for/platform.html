Use casesFor platform

"How do 300 people get model access without provider keys on laptops?"

You are the team that gets asked for keys, quota and a new provider every week. Gantry gives you one endpoint to hand out, one file to review, and one service to run.

What you get

One endpoint
OpenAI, Anthropic, Azure OpenAI, Amazon Bedrock, Vertex AI, Gemini and local servers behind the APIs your tools already speak.
Keys you can hand out
Per person and per workload, with expiry, budget and model list. Developers issue their own through single sign-on with gantry login.
Policy as code
One YAML file in git. gantry check runs in CI and names the line and the fix for every mistake.
Routing
Aliases over several deployments, retries, fallbacks, a circuit breaker per deployment and session affinity for coding agents.
Little to operate
One static binary in one image, plus Postgres. No Redis. Policy and keys reload within 2 seconds, without a restart.

Where it stops

  • Gantry is pre-1.0. The docs list what is built and what is planned.
  • The answer cache is per replica. Budgets, rate limits and kill switches are shared through the store.
  • Most provider integrations were built from public docs and tested against local mocks. The docs publish a live matrix per route and provider.
  • Moving from LiteLLM: gantry import litellm turns a LiteLLM proxy config into a Gantry policy. Read the result before you use it.
