Five questions most companies cannot answer about their AI use.

Your people already use AI tools. Developers run coding agents. Other teams call model APIs from scripts and internal apps. Each tool talks to a provider on its own, so the company has no single place to look.

1. Who uses which AI tools?

Three teams adopted three coding tools this year, and nobody kept a list. One team wired an agent to an internal system. The tools were installed by the people who use them, which is how good tools spread, and the list lives in nobody's system.

A gateway answers this as a side effect. Once tools send their requests through it, it knows which tool sent each one, and once each person has their own key, it knows who.

2. What does it cost, and who spent it?

The provider invoice gives one total per account. It does not say which team or tool spent it. When the total doubles, the only way to find out why is to ask around.

A gateway counts tokens and cost per request, so the same total breaks down by team, person, tool and model.

3. Can you cap it and stop it?

An agent retries the same task all night. A key is pasted into a public issue. In both cases you need two controls you may not have: a limit that refuses the next request, and a switch that stops one person, one team or one key right now without stopping everyone else.

4. What leaves the company?

Someone pastes a config file into a prompt, and the file holds a database password. A support agent sends a customer's card number to a model. Nobody meant harm. There was no check on the way out, and there is no record that it happened.

A gateway can look at each prompt before it leaves, block the ones that hold a secret, and mask personal data in the rest.

5. Can you prove it?

A customer or an auditor asks who used which model last quarter, and how you know the record is complete. Screenshots of a provider dashboard do not answer the second half.

A record that is written for every request, and that shows when a line has been changed or removed, does.

What starting takes

Less than most people expect. The first step is one container, the provider keys you already have, and a settings change in each tool so it points at the gateway. In Gantry that first step runs in observe mode: every request from a key you issued is forwarded, and nothing your people do today is blocked.

You decide when to go further. Each step is one change on top of the last, and each one works without the next. Your provider accounts and contracts stay as they are, and people keep the tools they chose.

What a gateway does not do

  • It sees the requests that are sent through it. A tool that still calls a provider directly stays invisible until you point it at the gateway.
  • A check for secrets finds an API key in a prompt. It does not know that a paragraph is your unreleased roadmap unless you give it a pattern or a word list.
  • Some subscriptions cannot be routed. Developers on Claude Team or Enterprise seats, for example, cannot send requests through a gateway. Gantry has a watch setup for them that shows usage and does not block.
  • Gantry's audit log holds who asked, which model, the decision and the cost. It holds no prompt or answer text, so it will not tell you what was said.
