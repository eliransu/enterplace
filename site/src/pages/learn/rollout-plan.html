At step 4
The date the secrets check starts blocking.

Whether you need Enterplace Enterprise for SIEM export, retention and legal hold.

And your contracts with them. Enterplace holds the provider keys, and your people stop holding them.

Three example rollouts

These are scenarios written to show the steps, with real policy lines. They are not customers. Enterplace is pre-1.0 and has no customer stories to publish yet.

Example: a 200-person fintech rolling out Claude Code

Sixty engineers already use Claude Code with one shared Anthropic key. Finance sees a single invoice. Security has been asked whether card data has gone into a prompt.

  • See. The shared key moves into Enterplace and laptops point at the gateway. Nothing is blocked for two weeks.
  • Know. Engineers run enterplace login and get a personal key through the identity provider. The shared key is revoked.
  • Limit. A daily budget per person and a monthly budget per team.
  • Protect. The secrets guardrail runs in shadow, then blocks. Personal data is masked.
  • What they have: spend by engineer and team, a refusal message developers can act on, and a log that answers the card data question with records.
Example: a platform team with 40 MCP servers

Agents across the company call internal MCP servers for GitHub, the data warehouse and deploys. Each server has its own token, and nobody can list which agent may call which tool.

  • See. The servers go behind Enterplace's one MCP endpoint. Every tool call is recorded with the person who made it.
  • Know. People sign in with their key or by OAuth from the client. Each rule lists the tools its team may see.
  • Limit. Merges and deploys wait for an admin's approval. Any tool has a kill switch.
  • Protect. Each tool is pinned by a hash of its description and schema. A changed tool is held until an admin approves it.
  • What they have: one list of every tool, who called it, and a way to stop one tool without taking a server down.
Example: a healthcare company that must keep patient data in region

Clinical teams want model help with notes. Compliance requires that patient data stays with an EU endpoint under a signed agreement, and that records can be produced on request.

  • See. Enterplace runs in the company's own EU cloud account, from the Terraform module.
  • Limit. The clinical rule reaches only deployments labelled eu. A request with no EU deployment is refused before anything is sent.
  • Protect. Personal data is masked, and a regex guardrail masks patient record numbers.
  • Prove. With Enterplace Enterprise: export to the SIEM, a retention period, and a legal hold when a case opens.
  • What they have: a record per request naming the region rule that decided it. Enterplace enforces the label set on each deployment. It does not check where a provider runs.
