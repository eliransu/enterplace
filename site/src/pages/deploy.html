One image plus Postgres, in your own cloud.

Enterplace runs in your network or cloud account. Prompts go from your callers, through the gateway, to the providers your policy names. Enterplace never stores them, and the license is checked without a network call.

Show the Cloudflare agent prompt 
Deploy Enterplace, the self-hosted AI gateway, to my Cloudflare account with its wrangler template, so everything runs on Cloudflare: the gateways in Cloudflare Containers behind a Worker, the store (keys, kill switches, budgets, sessions, credentials, policy versions) in a Durable Object, the audit chain in R2. No database or service outside Cloudflare.

Never put a secret in chat, in a file or in a command line I can see: I type each one myself at the wrangler prompt, or you pipe a generated one straight into wrangler.

First ask me, one at a time:
- The hostname for the gateway (for example ai.example.com), in a zone on my Cloudflare account.
- A name for the Worker (default enterplace) and for the R2 bucket (default enterplace-audit).
- Which model providers I use (OpenAI, Anthropic, Gemini, others), and the models each rule should allow.
- Whether I have an Enterplace license key (optional: without one it runs the open source edition).

Then:
1. Check the prerequisites and tell me what is missing: Docker running, Node.js 20 or later, and a Cloudflare account on the Workers Paid plan (Containers need it) with R2 enabled.
2. Copy the template out of the image, pinned to the digest of the newest build:
   docker pull ghcr.io/eliransu/enterplace:latest
   IMAGE=$(docker inspect --format '{{index .RepoDigests 0}}' ghcr.io/eliransu/enterplace:latest)
   docker create --name enterplace-files "$IMAGE" && docker cp enterplace-files:/deploy/cloudflare ./enterplace-cloudflare && docker rm enterplace-files
   cd enterplace-cloudflare && npm ci && npx wrangler login   (I sign in in the browser)
3. Edit the lines marked EDIT in wrangler.jsonc: the Worker name, ENTERPLACE_IMAGE in image_vars (set it to $IMAGE), the bucket name, and my hostname. Set "GATEWAYS" to "1" for now.
4. Edit enterplace.policy.yaml: one provider per provider I named (kind, url, key_env: <NAME>_PROVIDER_KEY, models), and the rules. Keep its last two lines as they are:
   audit: { path: /var/lib/enterplace/enterplace-audit.jsonl }
   store: { cloudflare: true }
5. Create the bucket and deploy: npx wrangler r2 bucket create <bucket>, then npx wrangler deploy (the first build takes a few minutes).
6. Secrets. Generate these yourself, piped so the values never show:
   openssl rand -hex 32 | npx wrangler secret put ENTERPLACE_MASTER_KEY
   openssl rand -hex 32 | npx wrangler secret put ENTERPLACE_EXPORT_KEY
   openssl rand -hex 32 | tee audit-read-token.txt | npx wrangler secret put ENTERPLACE_AUDIT_READ_TOKEN
   Then have me run, one by one, npx wrangler secret put <NAME>_PROVIDER_KEY for each provider, and ENTERPLACE_LICENSE if I have one. Tell me to keep a copy of the master key outside Cloudflare: a lost one cannot be recovered. Run npx wrangler deploy again so the gateways start with the secrets.
7. Verify, and show me each result:
   - curl -s https://<hostname>/healthz answers (the first request starts a container, which takes a few seconds).
   - npx wrangler tail --format pretty | grep "First run" gives the one-time setup link. Show it to me with http://127.0.0.1:8080 replaced by https://<hostname>, for me to open, make the first admin and keep the admin key it shows once. Never ask me to paste that key into chat: I export ENTERPLACE_ADMIN_KEY in my own shell.
   - With that key, issue a test key with POST https://<hostname>/admin/keys and send one chat request through https://<hostname>/v1/chat/completions.
   - The audit chain: curl -s -H "Authorization: Bearer $(cat audit-read-token.txt)" https://<hostname>/_enterplace/audit/gateway-0 > chain.jsonl, then docker run --rm -v "$PWD":/w:ro "$IMAGE" audit verify /w/chain.jsonl
8. Set "GATEWAYS" back to "2" and deploy again: keys, kill switches and budgets are shared through the store's Durable Object, so either instance answers any request.

What you deploy

Seven parts. The last two are optional.

PartWhat it isWhere it lives
The imageghcr.io/eliransu/enterplace: one static binary, built from scratch, running as user 65532. It serves the gateway, the console and the admin API.Your registry, or ghcr.io
PostgresThe store: keys, kill switches and spend, shared by every replica.A managed database, or the Compose container
A volume per replicaThat replica's hash-chained audit log. Two replicas never share one, because each writes its own chain.A Docker volume, a PersistentVolumeClaim, EFS, Filestore or Azure Files
The policyOne YAML file: providers, rules, guardrails. It holds no secrets.Version control, then a ConfigMap, a parameter or a mount
Provider keysOne environment variable per provider, named by the policy.Your secret store
The license key, optionalOne line of text. It unlocks the Enterprise features and is checked offline.Your secret store
The master key, optionalSeals provider credentials kept in the store with AES-256-GCM. A lost one cannot be recovered.Your secret store

What stays in your network

Prompts and answers
Go to the provider your policy names and back to the caller. Never stored: not in the audit log, not in Postgres.
Provider keys
Read from environment variables and sent only to their provider.
Enterplace keys
Shown once when issued. Only the SHA-256 is stored.
The audit log
On your volume. You ship it where you choose.
The license
Checked against a public key in the binary. No network call.

Limits to know before you start

  • Enterplace serves plain HTTP unless you give it a certificate. Start it with --tls-cert and --tls-key, or put TLS in front of it, before traffic leaves one machine.
  • On Cloud Run and Container Apps, one replica. More than one replica on those two is planned. Kubernetes and ECS run several.
  • Pin the version. latest is for a first try. A moving tag makes a rollback guesswork.
  • Releases are signed. Images ship with an SBOM and provenance. Verify a release
