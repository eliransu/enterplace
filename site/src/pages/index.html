Put a name on every AI call.

Gantry is a self-hosted AI gateway. Coding tools, agents, apps and MCP clients call models through it, and each request gets a person's name, a budget, guardrails and a line in an audit log you can verify.

Set up Gantry, the self-hosted AI gateway, on this machine, and route my Claude Code through it while I keep my own Claude subscription login (no API key).

1. Install it: curl -fsSL https://gantry.enterplace.dev/install.sh | sh
   Then open a new shell, or run the PATH line it prints.
2. Make a folder for it (~/gantry) and run "gantry start --no-open" there in the background.
   It serves http://127.0.0.1:8080 and already has the claude-subscriptions provider, which passes my Claude login on unchanged.
   It prints a dashboard sign-in link and an admin key once: show me the link, and never put the admin key in chat, files or commits.
3. Optional, so my requests carry my name (without it they are recorded as unknown). In that folder, make a person token for me (ask me for my name and team):
   gantry key new <name> --team <team> --identity-only --url http://127.0.0.1:8080
4. Add these lines to my shell profile (the second only with a token from step 3):
   export ANTHROPIC_BASE_URL=http://127.0.0.1:8080
   export ANTHROPIC_CUSTOM_HEADERS="x-gantry-user: <token>"
   ANTHROPIC_API_KEY and ANTHROPIC_AUTH_TOKEN must stay unset, so Claude Code keeps using my subscription.
5. Verify: in a new shell run: claude -p "say hello". It answers, and the request shows at http://127.0.0.1:8080/console/requests once I open the sign-in link.

What every call gets on its way through.

Gantry sits between your tools and the model providers. It identifies the caller, decides by your policy and writes the record before anything is forwarded.

A name
A key per person and per workload, or sign-in through your identity provider. The provider's key stays inside the gateway.
A budget
Dollars, requests and tokens per team, person, key or model. A refusal says why and when the budget starts again.
Guardrails
Secrets and personal data blocked or masked before they leave. Each one can run on trial first.
A kill switch
Stop a person, a team, a key or a model with one command and a reason.
A record
One line per request, chained by hash to the one before it. It holds no prompt or answer text.

Five steps, one change at a time.

Start by watching. Nothing your people do today is blocked in step one, and each step works without the next.

  1. See

    Which tools and models are in use, and what they cost.

  2. Know

    Who uses what, by person and team.

  3. Limit

    A budget per team, and a stop button.

  4. Protect

    Secrets and personal data stay out of prompts.

  5. Prove

    A record of every request that anyone can verify.

It runs where your data already is.

Prompts and answers go from your callers, through Gantry, to the providers your policy names. Gantry never stores them, and nothing calls home.

ghcr.io/eliransu/gantry

One image

A single static binary in an image built from scratch, running as a non-root user. It serves the gateway, the console and the admin API.

DATABASE_URL

Postgres, for teams

Optional. Keys, kill switches, budgets and rate limits, shared by every replica. No Redis.

gantry.policy.yaml

One policy file

Providers, rules, budgets and guardrails, kept in git. An unknown field is an error with its line number.
